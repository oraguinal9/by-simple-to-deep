第三章 奖励模型：让模型学会「什么是好回答」

有了偏好数据，下一步是训练一个奖励模型（Reward Model，RM）。它的任务很单纯：看到一个回答，就给出一个标量分数，表示「人类会觉得这回答有多好」。

你可以把奖励模型理解为 RLHF 里的「代理裁判」——我们不可能每次都请真人来打分，所以用 RM 来代替人，给海量生成结果快速评分。

一、奖励模型长什么样

奖励模型通常在 SFT 好的模型基础上改造：

  • 去掉原来的语言模型 head（预测下一个词的那一层）；
  • 换上一个标量输出头（scalar head），把整个回答压缩成一个实数分数 r。

输入一个问题 x 和一个回答 y，RM 输出：

r_θ(x, y) ∈ ℝ

分数越高，表示 RM 认为「人类越喜欢这个回答」。

为什么复用 SFT 模型？因为 RM 需要强大的语言理解能力才能判断回答好坏，从头训太贵也太难，站在 SFT 的肩膀上最省力。

二、训练目标：Bradley–Terry 模型

偏好数据是一对 (x, y_w, y_l)：人对 x 给出的两个回答里，更偏好 y_w。我们希望 RM 给 y_w 的分数高于 y_l。一个经典、优雅的损失来自 Bradley–Terry 模型（它原本是用来给棋手排名的）：

P(y_w ≻ y_l) = σ( r(x, y_w) − r(x, y_l) )

其中 σ 是 sigmoid 函数。直观理解：两者分差越大，y_w 胜出的概率越接近 1。

损失函数（负对数似然）写成：

L = − log σ( r(x, y_w) − r(x, y_l) )

梯度会推动 RM：抬高胜方分数、压低败方分数。当 y_w 分数已经明显高于 y_l 时，损失趋近 0，学习放缓——这很合理，说明 RM 已经「学会了」这对偏好。

如果数据是 K 个回答的排序，损失可以扩展为「所有胜–负对」损失的加和（两两比较的排名损失）。

三、训练中的几个关键细节

1. 只训练奖励头，还是全量微调？

常见做法：冻结（或部分冻结）主干，只训练顶部的标量头，训练更稳、不易遗忘语言知识。也有全量微调的变体，视数据量和算力而定。

2. 长度偏置（Length Bias）

经验发现：RM 容易偏爱更长的回答——因为长回答往往看起来「更认真」。这是个陷阱。缓解方法包括：在损失里对长度做惩罚、或在数据构造时刻意让长短回答均匀分布、或在最终 RLHF 时引入长度归一化。

3. 过拟合与分布偏移

RM 是在「SFT 模型生成 + 人类比较」的数据上训的。一旦策略模型在 RLHF 中进化得「太远」，它生成的回答可能超出 RM 见过的分布，RM 的打分就不可信了。这正是后面要引入 KL 约束（第七章）的原因。

四、奖励模型的「价值观」从哪来

RM 的分数，本质上是对标注者偏好的压缩。所以：

  • 标注指南写「安全性优先」，RM 就给安全回答高分；
  • 标注者群体偏爱某种文风，RM 就会奖励那种文风。

这意味着 RM 不是客观真理，而是偏好的镜像。如果你发现模型变得「太爱附和」「不敢说不确定」，很可能 RM 在训练时把「谄媚」当成了「好」。

五、奖励模型不是万能的

一个常被忽视的事实：RM 只能评估它见过的那种「好」。对于需要真实世界验证的任务（代码能不能跑、数学对不对），RM 的分数并不可靠，它可能给一个「看起来很对但其实是错的」回答打高分。这也是为什么 RLHF 之外还需要过程奖励、工具验证、人类审核等补充手段。

本章小结

  • 奖励模型 = SFT 模型 + 标量头，输入 (问题, 回答)，输出一个实数分数。
  • 训练用 Bradley–Terry 损失：拉大「胜方 − 败方」的分差。
  • 实操要点：警惕长度偏置、防止 RM 过拟合、注意 SFT→RLHF 的分布偏移。
  • RM 是人类偏好的镜像，会忠实学到标注者的价值观（包括偏见）。
  • RM 对「看起来对但实际错」的回答无能为力，需配合其他验证手段。

思考与延伸

  • 如果 RM 给「错误但自信」的回答打高分，会对最终模型造成什么后果？（提示：想想「幻觉」会不会被奖励）
  • 长度偏置除了在 RM 损失里惩罚，还能从数据层面怎么缓解？
