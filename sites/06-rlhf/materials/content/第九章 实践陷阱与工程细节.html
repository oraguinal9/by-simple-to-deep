第九章 实践陷阱与工程细节

理论讲完，这一章聊聊真刀真枪做 RLHF/DPO 时会踩的坑。很多项目不是算法不行，而是死在工程细节上。无论你用 PPO 还是 DPO，下面这些点都值得打印贴在显示器上。

一、数据与偏好的坑

  1. 噪声偏好直接毒化模型 标注者乱点、指南含糊，会让 RM/DPO 学到错误信号（第七章）。务必先小批量试标、测一致性、再放大。

  2. 分布不匹配（Distribution Shift） 训练偏好用的 prompt，要和线上真实 prompt 同分布。否则模型在训练集上很乖，一上线就原形毕露。

  3. 只比「好 vs 坏」，忘了「好 vs 更好」 如果偏好对里胜方只是「没那么烂」，模型学到的上限也低。要有意识地收集「两个都不错、但微妙更好」的难样本。

二、奖励模型的坑

  1. 长度偏置 RM 偏爱长回答（第三章）。缓解：数据层让长短均衡、训练时做长度惩罚或归一化、最终评估看「单位长度质量」。

  2. RM 过拟合 RM 在固定数据上训久会过拟合，对分布外样本打分失真。监控 RM 在 Validation 集上的准确率，别训太多 epoch。

  3. 奖励尺度漂移 RM 分数范围不稳定，会让 PPO 的优势信号忽大忽小。实践中对奖励做 running mean/std 归一化很常见。

三、PPO 训练的坑

  1. 学习率与更新步数 PPO 学习率通常比 SFT 小一个数量级；每个 batch 的更新步数（epochs per batch）也要限制，否则容易过冲。

  2. KL 系数 β 难调 β 太大模型学不动（被参考模型绑死），太小疯狂钻空子（第七章）。常用「自适应 β」或监控 KL 值是否落在预期区间。

  3. 采样是瓶颈 on-policy 的 rollout 逐词生成极慢。加速靠大 batch、多卡推理、KV cache 优化；别让 GPU 在采样时空转。

  4. 四个模型显存爆炸 用 LoRA 只训适配层、用 ZeRO/张量并行切分、把冻结的 Reference/RM 用参数共享或 CPU 卸载——这些是标配，不是锦上添花。

四、DPO 特有的坑

  1. β 不是越大越好 DPO 的 β 控制「对齐强度」。太大 → 模型死守偏好、丧失流畅度；太小 → 偏好信号被淹没。常见从 0.1 起调。

  2. 参考模型必须和策略同源 DPO 的损失依赖 π_ref 和 π 出自同一基座。如果你在 SFT 模型和 DPO 模型之间换了底座，损失会失真。

  3. 负样本质量决定下限 DPO 同时看胜方和败方。如果败方本来就很烂、胜方优势巨大，模型学不到细腻区分；要有「势均力敌」的难负例。

五、评估的坑

  1. 只看奖励分数会自欺欺人 RM 分越高 ≠ 人类越满意（奖励黑客）。必须做人工评估 / 胜率对战（如让人类或强模型当裁判比较 A/B），且评估集要独立、未参与训练。

  2. 忘了对齐税（Alignment Tax） RLHF/DPO 可能让模型在某些基准（如代码、数学）上退步——因为它把精力花在了「讨好偏好」上。要用综合 benchmark 监控，必要时用 SFT 数据「回补」能力。

六、一套稳妥的实操清单

  • [ ] 偏好数据：小批量试标 → 测一致性 → 修指南 → 放大
  • [ ] RM/DPO：监控验证集指标，防止过拟合与长度偏置
  • [ ] PPO：学习率小、β 自适应、奖励归一化、LoRA 省显存
  • [ ] 评估：独立人工/裁判评估 + 综合 benchmark，不只看 RM 分
  • [ ] 监控：定期红队抽检，发现新空子就补数据

本章小结

  • 数据层：防噪声偏好、防分布偏移、收集「微妙更好」的难样本。
  • RM 层：警惕长度偏置、过拟合、尺度漂移。
  • PPO 层：小学习率、β 自适应、采样加速、4 模型显存靠 LoRA+并行。
  • DPO 层：β 别太大、参考模型须同源、负例要难。
  • 评估层：别只看 RM 分（奖励黑客），要人工/裁判评估 + 综合 benchmark 监控「对齐税」。
