中文小模型实战：MiniMind 从零训练

前面的章节用的是别人的库（Unsloth）。这一章我们用 MiniMind 这个极简的中文小模型，把「从零训练/微调一个能聊天的模型」这件事彻底搞清楚。MiniMind 由国内开发者开源，代码极其精简，非常适合教学——你几乎能看懂每一行在干嘛。

MiniMind 是什么

MiniMind 是一个为中文教学和研究设计的小型开源 LLM，特点：

  • 模型极小：有 26M、52M、104M 等超小规模，普通 CPU/小显存就能跑；
  • 代码极简：核心训练代码几百行，去掉了一切工业化的复杂封装；
  • 全程中文：数据、示例、文档都是中文，对中文学习者极其友好；
  • 流程完整：预训练、指令微调、对话推理全都有。

用它做教学，你能看到「一个 LLM 到底是怎么从数据训练出来的」，而不只是「调一个库」。

训练一个模型的两大步

第一步：预训练（Pre-training）

让模型学会「中文长什么样」——词与词的搭配、语法、常识。这步用海量无标注文本，训练目标是「预测下一个 token」。

MiniMind 预训练输出的是一堆「原始文本生成器」：它知道中文怎么读着顺，但还不会「有问有答」。

第二步：指令微调（SFT，Supervised Fine-Tuning）

用「指令—回答」对，让模型学会「问什么答什么」。这才是我们前面一直在说的「微调」。它让模型从「会写中文」变成「会对话、会执行指令」。

打开 MiniMind 的代码看结构

MiniMind 的仓库结构大致如下（不同版本略有差异）：

MiniMind/
├── model.py          # 模型结构定义（Transformer）
├── train.py          # 预训练脚本
├── sft.py            # 指令微调脚本
├── generate.py       # 推理/生成脚本
├── config.py         # 配置（模型大小、路径等）
└── data/             # 数据

关键收获：一个完整的 LLM 训练项目，本质上就这几块——模型定义、训练循环、数据、配置、推理。

从「原理」看懂一条训练样本

在 MiniMind 里，一条指令微调样本最终也是一段 token 序列，用特殊的模板标记角色。它的思路和 ChatML 类似，只是标记符号不同。

训练时模型做的依然是「下一个 token 预测」：给定前面的 token，预测下一个 token。通过海量样本，它逐渐学会「看到 user 的问题，就接着生成 assistant 的回答」。

你可能会问：那怎么让它「回答」而不是「把问题复述一遍」？靠的就是只对 assistant 段算 loss（mask 机制），第 5 章讲过了。MiniMind 的 sft 脚本里也有对应的 mask 逻辑。

实操：跑通 MiniMind 微调

以最小的 26M 模型为例，大致流程：

git clone https://github.com/jingyaogong/minimind.git
cd minimind

# 1. 配置里把模型大小设到最小
# 2. 准备你的指令数据（JSON）
# 3. 跑指令微调
python sft.py

跑完后，generate.py 就能加载微调后的权重做对话：

python generate.py

你会得到：一个真的在本地、用你自己数据、能跟你对话的中文小模型。虽然它很笨（26M 参数能力有限），但它是「你自己训练出来的」，这个理解价值远超一个大模型的 demo。

为什么先从小模型学

有人会问：我直接学 7B 不就行了吗？为什么要先玩 26M 的玩具？

三个理由：

  1. 看得见全过程：26M 模型在 CPU 上几分钟就能训完，你能反复试「改数据 → 重训 → 看效果」，这个反馈循环是学习的关键；
  2. 概念通用：小模型和大模型的训练机制完全一样，只是规模不同。你在这里搞懂的 mask、模板、loss，放大到 7B 一字不差；
  3. 省钱省心：不烧显存，犯错成本极低。

等你在 MiniMind 上把「训练」这件事真正搞明白，回到 Unsloth 跑大模型只是「换了个更大的模型」而已。

预训练 vs 指令微调：别搞混

预训练 指令微调（SFT）
数据 海量无标注文本 指令-回答对
目标 学会语言本身 学会听从指令/对话
模型产出 文本生成器 对话助手
成本 高（算力大） 相对低
你实际要做的 通常是「用现成的」 这才是你日常说的「微调」

大多数个人微调场景，你不需要从头预训练——直接用现成的开源模型（Qwen 等）做指令微调即可。MiniMind 让你看到预训练的样子，是为了让你理解全貌，不是让你真去预训练一个生产模型。

训练日志：小模型也能看到「学习」的瞬间

用 MiniMind 训练时，多留意训练日志里的 loss。你会观察到一些有意思的现象：

  • 前几十步 loss 掉得飞快：模型在「见世面」，快速学会数据的整体规律；
  • 之后下降变缓：进入精调阶段，学细节；
  • loss 平台期：暂时不降了，可能过一会儿继续降，也可能到头了。

对小模型的额外收获：因为训练快，你能用「改数据 → 重训 → 看效果」循环快速验证假设。比如：把「你是谁」这类身份问答加进去，重训后再问，看它是不是学会了——这种「亲手制造行为变化」的体验，比任何讲解都深刻。

用 MiniMind 理解「模型大小」意味着什么

同一份数据，分别训 26M 和 104M 的 MiniMind，你会直观感受到：

  • 26M：训练快、显存几乎为零，但回答经常前言不搭后语，记不住复杂规则；
  • 104M：训练稍慢，但明显「更聪明」——能更稳定地学会格式和简单逻辑。

这直观地验证了第 1 章的观点：模型大小决定能力天花板，数据决定在这个天花板内能学到什么。参数是「容器」，数据是「水」，容器不够大，水再多也装不下。

常见的 MiniMind 上手问题

新手跑 MiniMind 常遇到这几个问题，提前给你答案：

Q1：克隆下来直接跑 sft.py 报错？ 答：多半是路径或依赖问题。按 README 要求装依赖（requirements.txt），确认数据文件路径和 config 里的一致。

Q2：训完 generate.py 问它，回答是乱的？ 答：先看训练有没有真的收敛（loss 有没有降到很低）；再看推理时的 prompt 格式是否和训练模板一致。小模型对格式更敏感。

Q3：26M 模型太笨，是不是我数据问题？ 答：不一定是。26M 就是很弱，把模型换成 104M 再试，你会在对比中理解「参数量的意义」。

Q4：能不能直接拿 MiniMind 做生产？ 答：不能。MiniMind 是教学玩具，生产至少用 1B+ 的模型。它的价值是「看懂」，不是「投产」。

从 MiniMind 到真实项目：你的理解迁移清单

学完 MiniMind，把下面这些「小模型上验证过的理解」带到真实项目里：

  • [ ] 我理解「下一个 token 预测」是训练的底层逻辑；
  • [ ] 我知道 mask 只让 assistant 段参与 loss；
  • [ ] 我见过 loss 曲线的正常与异常形态；
  • [ ] 我知道模板/特殊 token 必须匹配模型；
  • [ ] 我亲手造过「数据改变行为」的实验；
  • [ ] 我理解预训练和 SFT 的区别，知道日常说的「微调」是 SFT。

全部打勾，你就具备了「看懂任何训练框架」的底子——Unsloth、LLaMA-Factory 在你眼里都只是「同一件事的工程化封装」。

小练习

  1. 把 MiniMind 克隆到本地，跑通 26M 模型的指令微调，记录训练时长和 loss 变化。
  2. 给你的数据加 5 条「你是谁？你叫什么名字？」这种身份类问答，微调后再问模型，看它是否学会自我介绍。
  3. 对比 MiniMind 的 sft 和 Unsloth 的 SFTTrainer，找出它们在「数据组织、loss mask」上做法的共同点。
  4. 进阶：分别训 26M 和 104M 两个版本，用同一批问题对比回答质量，写 3 句话总结「参数量带来的差异」。
