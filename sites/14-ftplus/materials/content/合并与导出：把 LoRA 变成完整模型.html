合并与导出：把 LoRA 变成完整模型

训练结束只完成了一半。你手里的 lora_model/ 只是一堆 LoRA 适配器权重，不能直接拿去部署。这一章讲清最后一步：怎么把 LoRA 合并回基座，导出成能真正对外服务的完整模型，甚至压缩成更省资源的格式。

为什么 LoRA 权重不能直接部署

回顾 LoRA 原理：微调后的等效权重 = W + A×B，其中 W 是基座权重（冻结的），A、B 是训练出来的 LoRA 小矩阵。

你训练保存的 lora_model/ 只包含了 A、B（可能还有 adapter 配置文件）。要得到最终模型，必须把 A×B 加回 W。没有基座 W，只有 A、B 的模型是「残缺」的，无法独立生成。

合并：W + A×B

合并就是把两个东西相加，得到完整的微调后权重。绝大多数框架（PEFT、Unsloth、LLaMA-Factory）都提供一行命令：

用 Unsloth / HF PEFT 合并：

from unsloth import FastLanguageModel

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen2.5-7B-Instruct",
    load_in_4bit=True,
)
model = FastLanguageModel.get_peft_model(model, r=16, ...)  # 要和训练时一致
model.load_adapter("lora_model")          # 加载训练好的 LoRA

model = model.merge_and_unload()          # 合并 LoRA 回基座
model.save_pretrained("merged_model")     # 保存完整模型
tokenizer.save_pretrained("merged_model")

关键点：

  • 加载时的模型名、r、target_modules 必须和训练时一致，否则 adapter 形状对不上会报错；
  • merge_and_unload() 会把 LoRA 权重并回基座，得到一个不再需要额外 adapter 的完整模型；
  • 合并后的模型大小 ≈ 基座模型 + 一点点，是完整可推理的。

导出成什么格式

合并后，你有几种导出选择：

1. 标准 Safetensors（HF 原生格式）

save_pretrained 默认导出的格式，一堆 .safetensors 权重文件 + config.json + tokenizer。可直接用 transformers 加载推理，也可用 vLLM / llama.cpp 等推理框架直接跑。

2. GGUF（给 llama.cpp / Ollama 用）

如果你要部署到 CPU、Mac、或轻量环境（如 Ollama 本地跑），GGUF 是首选。它自带量化，资源占用极低。

常用转换工具：llama.cpp 的 convert、或 Unsloth 自带的转换（model.save_pretrained_gguf(...)），转 GGUF 时可同时指定量化级别（如 Q4_K_M、Q5_K_M）。

3. 更进一步：导出为 Ollama 能直接用的模型

如果你本地装了 Ollama，可以把 GGUF 再封装成 Ollama 模型，一条 ollama create 命令就能让微调后的模型「像原生模型一样被 ollama run」调用。

导出前先做一轮小验证

别急着部署，先验证合并正确：

# 加载合并后的模型
from transformers import AutoModelForCausalLM, AutoTokenizer
model = AutoModelForCausalLM.from_pretrained("merged_model")
tok = AutoTokenizer.from_pretrained("merged_model")

prompt = "请用一句话解释什么是微调。"
inputs = tok(prompt, return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=100)
print(tok.decode(out[0], skip_special_tokens=True))

如果回答符合你微调数据里的风格/内容，说明合并成功。

什么时候不需要合并

如果你只是在自己本地用训练框架加载 LoRA 做实验，不需要合并——直接 load_adapter 就能用。合并的意义在于：

  • 脱离训练框架部署（生产环境）；
  • 多份 LoRA 对比时并出完整模型来统一评测；
  • 转格式（GGUF 等）需要完整模型。

部署到哪

合并导出后，部署方式取决于你的环境：

  • 本地单机：直接用 transformers / llama.cpp / Ollama 跑；
  • 服务化高并发：用 vLLM、TGI 等推理框架起 HTTP 服务；
  • 云端：推到 HuggingFace 或你的模型平台，走 API。

具体部署细节在 L10（本地部署大模型）里讲过，这里不再重复——你只需要记住「微调产物要先合并，才能交给部署链路」。

合并的常见坑：手把手排雷

合并这步看着简单，坑其实不少：

坑 1：加载参数和训练时不一致。 训练时 r=16、挂了 7 个 target_modules，合并时用 r=8 或漏挂层——adapter 形状对不上，直接报错。铁律：合并时的模型名、r、alpha、target_modules 必须和训练时一字不差。

坑 2：用错基座版本。 训练用的基座是 Qwen2.5-7B-Instruct，合并时加载成 Qwen2.5-7B（少了个 Instruct）——虽然形状可能一样能合并，但行为会错乱。基座必须精确到同一个 checkpoint。

坑 3：合并后忘记验证就上线。 合并成功 ≠ 合并正确。永远先跑一轮推理验证，再部署（前面已给出验证代码）。

坑 4：多个 LoRA 叠加的顺序。 如果你想把多个 LoRA 一起合并（比如「领域 + 风格」两个 adapter），顺序会影响结果。通常逐个 load_adapter 再一次性 merge，顺序按「先基座影响大的，后微调的」。

模型格式全景：什么时候用哪种

合并后选择导出格式，其实是在「兼容性、体积、速度」之间取舍：

格式 体积 部署场景 说明
Safetensors 最大 HF 生态 / vLLM / TGI 标准格式，兼容性最好
GGUF 最小（可量化） llama.cpp / Ollama / CPU / Mac 自带量化，资源占用低
ONNX 中等 跨平台、边缘设备 适合特定硬件优化
MLX 中等 Apple Silicon Mac 专属优化

决策建议： - 服务器 GPU 部署 → Safetensors（或 GGUF 量化省显存）； - 本地 CPU / Mac / Ollama → GGUF； - 移动端 / 边缘设备 → ONNX 或量化 GGUF。

GGUF 量化级别怎么选

转 GGUF 时你会看到 Q4_K_M、Q5_K_M、Q8_0 等选项，什么意思？

量化级别 体积（约） 质量 场景
Q4_K_M 最小 尚可 极省资源，能跑就行
Q5_K_M 中 较好 体积质量均衡（推荐起步）
Q6_K 中上 很好 追求质量，显存充足
Q8_0 接近无损 最好 几乎无损，体积接近原模型

经验：本地体验选 Q5_K_M，质量体积都友好；真要上线高质量服务，用 Q8_0 或直接上 Safetensors。

一个「合并 → 导出 → 验证」完整流程示例

把这一章的操作串成一段可复制的流程（以 Unsloth + 转 GGUF 为例）：

# 1. 合并回基座（Python）
python merge_lora.py        # merge_and_unload + save_pretrained("merged_model")

# 2. 转 GGUF（Unsloth 一行）
python - <<'EOF'
from unsloth import FastLanguageModel
model, tokenizer = FastLanguageModel.from_pretrained("merged_model")
model.save_pretrained_gguf("gguf_out", quantization_method="q5_k_m")
EOF

# 3. 用 llama.cpp 快速验证
./llama-cli -m gguf_out/xxx-q5_k_m.gguf -p "你好" -n 64

# 4. 封装成 Ollama 模型（可选）
ollama create my-model -f Modelfile
ollama run my-model

跑通这四步，你的微调模型就从「训练产物」变成了「可用的服务」。

小练习

  1. 把你第 3 章训练出的 LoRA 合并回基座，导出一个完整模型。
  2. 再把它转成 GGUF（Q4_K_M 量化），对比合并前和量化后的大小。
  3. 用合并后的模型回答你训练数据里的一个问题，验证是否学到了你要的行为。
  4. 进阶：分别转 Q4_K_M 和 Q8_0，用同一批问题对比回答质量，观察量化带来的实际差异。

合并导出后，你的微调已经「闭环」了。最后一环是——怎么科学地评测你的模型到底变好了没有。
