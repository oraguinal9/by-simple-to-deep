用 Unsloth 快速跑通 QLoRA

前两章你搞懂了「微调是改行为」和「数据怎么准备」。这一章我们进入实操：用目前社区最省事、最省显存的库 Unsloth 把一次 QLoRA 训练跑起来。目标是先让整条链路「能通」，细节后面几章再补。

为什么是 Unsloth

现在微调工具很多（HuggingFace PEFT、LLaMA-Factory、Axolotl……），为什么这一章选 Unsloth？

  • 省显存、省时间：Unsloth 在底层对注意力计算做了优化，官方宣传比传统 PEFT 快 2~5 倍、显存占用更低；
  • API 友好：几乎就是 HF Trainer 的「平替」，上手极快；
  • 生态成熟：支持绝大多数主流开源模型（Llama、Qwen、DeepSeek 蒸馏、Mistral、MiniCPM 等）。

它本质上是把「加载 4bit + 挂 LoRA + 训练」这几步封装得特别顺手。

环境准备

微调通常推荐在 Linux + 有 NVIDIA 显卡的环境跑。个人电脑显存不够的话，可以用云 GPU（按小时计费）。

pip install "unsloth[cu121]@git+https://github.com/unslothai/unsloth.git"
# 以及
pip install trl peft transformers datasets accelerate bitsandbytes

如果你的显卡驱动较新（CUDA 12+），装 unsloth[cu121] 即可。显存建议：微调 7B 用 QLoRA，8GB 能跑，16GB 更从容。

最小可用代码

下面这段就是「跑通」的全部骨架。不要被吓到，每一行后面都解释。

from unsloth import FastLanguageModel
import torch

# 1. 加载 4bit 量化 + 准备 LoRA
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen2.5-7B-Instruct",   # 基座模型
    max_seq_length=2048,                      # 最长序列长度
    dtype=None,
    load_in_4bit=True,                        # 4bit 量化，省显存
)

model = FastLanguageModel.get_peft_model(
    model,
    r=16,            # LoRA 秩
    target_modules=["q_proj","k_proj","v_proj","o_proj",
                    "gate_proj","up_proj","down_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing="unsloth",
)

# 2. 定义训练参数
from trl import SFTTrainer
from transformers import TrainingArguments
from datasets import load_dataset

dataset = load_dataset("json", data_files="mydata.json")["train"]

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    dataset_text_field="text",     # 数据里放完整模板文本的字段
    max_seq_length=2048,
    args=TrainingArguments(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        warmup_steps=5,
        max_steps=200,             # 先少跑一点看效果
        learning_rate=2e-4,
        output_dir="outputs",
    ),
)

# 3. 开始训练
trainer.train()

# 4. 保存 LoRA 权重
model.save_pretrained("lora_model")
tokenizer.save_pretrained("lora_model")

逐段拆解关键点

4bit 量化（load_in_4bit=True）

这是 QLoRA 的核心。基座权重被压缩成 4bit（原本是 16bit），显存直接缩到约四分之一，训练时 LoRA 的小矩阵还是正常精度。代价是基座被压缩后精度略降，但对绝大多数任务影响很小，换来的是「消费级显卡也能训大模型」。

LoRA 挂在哪（target_modules）

q_proj、k_proj、v_proj、o_proj 是注意力层的四个投影矩阵；gate/up/down_proj 是 FFN（前馈）层的三个矩阵。把它们都挂上 LoRA，通常效果更稳。这是微调里最值得动手调的一行——挂的层越多，可训练参数越多，效果上限越高，但也越费显存。

r 秩与 lora_alpha

  • r（秩）：控制 LoRA 小矩阵的宽度，一般 8~64；
  • lora_alpha：缩放系数，控制 LoRA 更新的强度，通常设成和 r 相等或 2 倍。

社区经验：默认 r=16, lora_alpha=16 起步，大多数场景够用。

学习率

LoRA 的学习率通常比全参数微调大一些，常见 1e-4 ~ 3e-4。太小不收敛，太大易震荡。后面第 9 章讲怎么从 loss 曲线判断。

训练多久 / 多少步

训练步数取决于数据量和模型。原则：

  • 先小跑验证：max_steps=200 先跑，看 loss 是不是在降；
  • 再根据 loss 收敛情况决定继续跑多久；
  • 一般「数据量不大」时几百到几千步就够，不是跑越多越好——跑太久容易过拟合。

用「epoch」还是「step」思考

训练量有两种计量方式，新手常混：

  • step（步）：更新一次参数 = 一步。max_steps 直接指定步数；
  • epoch（轮）：把整个数据集过一遍 = 一轮。

数据量不同，「跑 1 个 epoch」需要的步数完全不同。经验法则：

数据量 推荐训练量
几百条 3~5 个 epoch（或几百步）
几千条 1~3 个 epoch（或一千步内）
几万条 0.5~1 个 epoch 往往就够

重要：训练量不是越大越好。很多人误以为「训得越久越好」，结果把模型从「学会了」训到「背过了」（过拟合）。正确做法是拿一小块验证集盯 loss，在验证 loss 开始回升前停下。

训练日志怎么看

训练时控制台会不断刷日志，别只看热闹，关键信息在这些字段：

{'loss': 1.2345, 'learning_rate': 0.0002, 'epoch': 0.42}
  • loss（损失）：核心指标。应该随训练逐渐下降，最后趋于平稳；
  • learning_rate：学习率，按你设置的 schedule 变化（warmup 阶段先升后降）；
  • epoch：当前进行到第几轮。

loss 不降的排查顺序（这是高频问题）：

  1. 数据问题（最常见）：标签错、口径乱、模板拼错、答案里混入未 mask 的废话；
  2. 学习率问题：太低（降不动）、太高（震荡）；
  3. 模型问题：基座和模板不匹配（第 5 章）；
  4. 显存问题：OOM 会直接报错，不会「不降」。

在训练中做推理测试

训练到一半，怎么知道模型「学成什么样了」？不需要等训完——直接在训练脚本里或另开终端加载 checkpoint 测几轮对话：

from unsloth import FastLanguageModel

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="outputs/checkpoint-100",   # 加载某个中间 checkpoint
)
FastLanguageModel.for_inference(model)

messages = [{"role": "user", "content": "什么是 LoRA？"}]
inputs = tokenizer.apply_chat_template(messages, tokenize=True, return_tensors="pt").to("cuda")
out = model.generate(**inputs, max_new_tokens=128)
print(tokenizer.decode(out[0]))

经验：训练过程中每隔固定步数做一次推理测试，把回答记下来，能非常直观地看到「模型是怎么一步步变好的」——这是比看 loss 更接近真实的信号。

保存与恢复：随时能续训

长时间训练怕中断？Unsloth / HF Trainer 支持断点续训：

  • 训练中每 save_steps 会自动存 checkpoint 到 outputs/；
  • 中断后用 resume_from_checkpoint=True 恢复：
trainer.train(resume_from_checkpoint="outputs/checkpoint-500")

实践建议： - 把 save_steps 设小一点（如 100~200），避免白跑； - 每训完一版，立即记录「这版数据/参数 + 评测结果」——微调实验管理是工程化的第一步，你会感谢自己的记录。

常见报错与排查

  • 显存 OOM：把 per_device_train_batch_size 降到 1，max_seq_length 调小，或把 use_gradient_checkpointing 打开（上面代码已开）。
  • 加载模型失败：确认模型名拼写正确、模型在 HuggingFace 上确实存在且你已登录/网络可达。
  • 数据格式报错：检查你的 JSON 里有没有 text 字段、字段名和 dataset_text_field 是否一致。
  • CUDA 版本不匹配：重装对应 unsloth[cuXXX] 版本。
  • torch.cuda.OutOfMemoryError 中途炸：多半是序列长度超了，调短 max_seq_length 或减小 batch。

小练习

  1. 在真实环境里（或云 GPU）用 Qwen2.5-7B-Instruct 跑通上面这段代码，记录你显卡的显存占用和训练时长。
  2. 把 r 从 16 改成 4 再跑一次，对比训练速度和 loss 收敛情况有什么不同。
  3. 试着把 target_modules 里的 FFN 层（gate/up/down_proj）去掉，看效果是否明显变差。
  4. 进阶：训练中每隔 50 步做一次推理测试，记录模型回答的「进化过程」，观察它是先学会格式还是先学会内容。
