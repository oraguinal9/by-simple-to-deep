微调全景再认识：从 LoRA 到全参数

为什么你已经会了基础，还要「进阶」

在上一阶段（finetune）里，你已经知道「微调」就是拿一份新数据，让预训练好的大模型继续学一点东西，从而改变它的行为和知识。但那只讲到了「会用一个库跑起来」的程度。这一阶段，我们要回答更硬核的问题：

  • LoRA 到底改了模型的哪些参数？为什么它那么省？
  • 全参数微调（Full Fine-Tuning）和 LoRA 效果差别有多大？什么时候值得上全参数？
  • 训练到一半 loss 不降了，是数据问题、学习率问题，还是显存爆了？
  • 训完的 LoRA 怎么「合并」成一份真正能拿去推理的模型？

这一章先把整张地图铺开。后面每一章再钻进一个具体环节。请把这章当作「总纲」来读，很多术语后面都会反复用到。

微调的三种主要方式

微调按「到底动了多少参数」可以分成三大类。搞懂它们的差别，你才能判断自己该用哪种。

1. 全参数微调（Full Fine-Tuning）

做法：把整个模型所有层的所有权重都拿去做梯度更新。

特点： - 效果上限最高，最能贴合你的任务； - 显存和算力需求极大。一个 7B 模型的全参数微调，除了模型权重本身，还要保存每一层的梯度、优化器状态（Adam 通常要 2 份额外状态），显存通常是模型大小的好几倍； - 容易过拟合，数据太少时会「背题」而不是「学会」。

适用：数据量足够大（几万条以上）、算力充足、且确实需要把模型能力全部翻新的场景。

2. 参数高效微调（PEFT）

这一类的共同点是：大部分参数保持冻结，只训练一小撮新增的参数。最主流的就是 LoRA 和 QLoRA。

LoRA（Low-Rank Adaptation，低秩适配）：不直接改原权重 W，而是在每一层旁边挂两个小矩阵 A 和 B，训练时只更新 A、B。最终等效权重 = W + A×B。因为 A、B 很小，可训练参数通常只有全模型的 0.1%~1%，显存占用骤降。

QLoRA：在 LoRA 基础上，把冻结的基座权重先量化成 4bit 存储，进一步把显存压到最低，让「一块普通消费级显卡也能微调大模型」成为可能。

适用：绝大多数个人和中小团队场景。这一阶段的主角就是 LoRA / QLoRA。

3. 适配器 / 前缀微调（Adapter / Prefix Tuning）等

属于 PEFT 家族里的其他成员，原理各异，有的在层间插小网络，有的在输入前加可学习向量。理解 LoRA 后这些都不难上手，本章不多展开。

一句话看懂 LoRA 为什么省

要理解 LoRA 的省，先看一个关键观察：大模型的权重 W 是巨大的矩阵（比如 4096×4096），但研究者发现，模型在微调时真正需要的变化量 ΔW 其实「秩很低」——也就是说，这个变化不需要那么多独立维度来表达，用两个低秩矩阵相乘就能近似。

于是 LoRA 的玩法是：

原权重：W（冻结，不更新）
新增两个小矩阵：A（r×k 形状）和 B（d×r 形状）
微调后的权重：W' = W + A × B

其中 r 就是「秩（rank）」，一个很小的数，比如 8、16、64。A×B 相乘的结果形状和 W 一样，但 A、B 本身很小。

训练时，梯度只流向 A 和 B，原 W 纹丝不动。你不需要为整个 W 存梯度、存优化器状态，所以显存和计算量都大幅下降。

直观类比：想象一张一万字的合同需要「修改」。全参数微调是逐字重写整份合同；LoRA 是只在合同旁边贴几张便签，写着「这段改成这样、那段改成那样」，原合同一个字不动。

微调 vs 提示词 vs RAG：到底该用哪个

很多人纠结：都 2026 年了，大模型那么强，我还要不要微调？

这里给一张决策表：

你的诉求 推荐方案 原因
让模型知道一批最新/私有知识 RAG 检索增强 不改模型，答案可追溯、可更新
让模型「说话风格/格式」变成你的 提示词工程，必要时轻量微调 风格偏好用提示词就能带
让模型学会一种固定的输出协议 轻量微调或结构化输出 稳定性比提示词更可靠
让模型掌握一个需要内化推理的技能 微调 技能很难靠检索喂进去
想让模型更懂你的领域术语和习惯 微调 术语分布靠数据改变

微调不是万能的，它不能凭空塞给你模型没见过的知识（那是 RAG 的事），它的核心价值是改变模型的行为倾向、输出格式、领域语感。搞清这个边界，你才不会把微调用错地方。

微调还改变了什么：几个容易忽略的细节

除了「行为」，微调还会在几个不容易察觉的地方产生影响，值得提前知道：

1. 输出风格会「传染」。你微调数据的语气、标点习惯、回复长度，模型都会学过去。如果你的数据是「短促、口语化」的，模型会整体变短；如果数据都是「结构化、带编号」的，模型也会倾向编号输出。这是把双刃剑——想要什么样的风格，数据就得是什么风格。

2. 能力会「此消彼长」。微调是「重定向」而不是「叠加」。你在 A 任务上花的训练量，会挤占模型在 B 任务上的表现。这就是为什么社区常说「微调要克制」——训得越久越专，通用能力越可能流失。

3. 同一条数据，顺序不同效果不同。数据排列顺序（比如把难样本放前面还是后面）会影响训练过程。实践中常见做法是「简单 → 难」或随机打乱并固定随机种子，保证可复现。

4. 模型大小决定「天花板」。LoRA 再厉害，也是在一个 7B 基座上改造。基座太小，能力上限就低；这就是为什么同样微调，14B 通常比 7B 更聪明——它「天生的底子」更好。

一个完整的微调项目的成本构成

很多初学者以为微调的成本 = GPU 费用。实际上一个完整的微调项目，成本分布通常是：

环节 占比 说明
数据准备与清洗 40%~60% 最容易被低估，也最决定成败
训练与调参 20%~30% 显存/时间，QLoRA 已大幅压缩
评测与迭代 15%~25% 反复「评测→修数据→重训」
部署与维护 10%~20% 合并导出、推理服务、监控

看到没？真正的大头是数据，不是算力。 这也是为什么本课程把数据准备放在第 2 章——它不是「先凑合弄弄」的环节，而是整个项目的根基。

常见误区速查

学习微调的人常踩这几个坑，提前帮你排雷：

  • 「微调 = 让模型记住更多知识」：错。知识靠 RAG，微调改行为。硬用微调塞知识，结果是「背题」且更新困难。
  • 「数据越多越好」：错。小而精胜过大而杂，配比和清洗比数量重要。
  • 「loss 降到最低就成功了」：错。loss 低可能只是过拟合，要拿评测集验证泛化。
  • 「LoRA 是低配凑合方案」：错。对多数任务，LoRA 效果已接近全参数，是性价比之王。
  • 「训完的 LoRA 直接能部署」：错。必须合并回基座才能独立部署（第 8 章）。

小练习

  1. 用自己的话说清：LoRA 训练时，哪些参数会被更新，哪些不会？
  2. 如果公司想让你做一个「内部客服机器人」，它需要既懂公司业务（私有知识）又会按固定话术回答。你会分别用到 RAG 和微调的哪个能力？
  3. 你手头只有一张 8GB 显存的显卡，想微调 7B 模型，全参数、LoRA、QLoRA 里你选哪个？为什么？
