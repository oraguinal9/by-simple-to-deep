全参数微调与 LoRA 效果对比

到这一步，你已经能熟练地用 QLoRA 微调了。但一个老问题始终在问：全参数微调效果真的更好吗？好多少？我到底什么时候才值得花那份钱和显存去上全参数？ 这一章我们正面回答。

两种方式的本质差别

全参数微调：更新模型所有权重。模型在「怎么表达」这个层面被全面重塑，理论上表达自由度和效果上限最高。

LoRA：只更新几个低秩小矩阵，原权重冻结。模型主体没变，只是「贴了几张便签」改变输出倾向。

直觉上，全参数能做得更好。但差别有多大？在很多任务上，差距比你想的小得多。

实际经验：LoRA 通常能达到全参数的 90%+

社区大量实验（包括 HuggingFace、各开源项目的 benchmark）反复得到类似结论：

在指令跟随、对话质量、特定任务风格这类「行为调整」型微调上，LoRA 往往能达到全参数 80%~95% 的效果，而成本（显存、时间、算力）只有零头。

尤其在数据量不大（几千条）时，LoRA 和全参数的效果差距几乎可以忽略，甚至 LoRA 因为过拟合更轻而有时表现更好。

什么时候 LoRA 完全够用

  • 做领域助手 / 客服 / 问答：数据几千条以内 → LoRA 足够；
  • 改变说话风格、输出格式：LoRA 轻松胜任；
  • 在已有开源模型上做小幅适配：LoRA 是社区默认选择；
  • 频繁实验、快速迭代：LoRA 省时省钱，方便多方案对比。

结论：绝大多数个人与中小团队场景，LoRA 就是正确答案。

什么时候才值得上全参数

全参数微调的优势要真正体现，通常需要满足：

  1. 数据量很大（通常几万条以上），需要模型「深度内化」；
  2. 任务需要整体能力提升，不只是行为微调（比如让模型学会一种新的推理范式）；
  3. 你有充足算力（多卡集群或云上 A100 级 GPU）；
  4. LoRA 已经试过，效果确实到顶了，需要最后一点上限。

如果这些都不满足，全参数微调大概率是「花大钱买微弱提升」。

一个直观的权衡表

维度 LoRA 全参数微调
可训练参数 0.1%~1% 100%
显存需求（7B） 6~20GB（QLoRA 更低） 60GB+
训练时间 快 慢
效果上限 略低 最高
适合数据量 小到中 大
过拟合风险 低 高（数据不足时）
成本 低 高
适用人群 个人、中小团队 有大算力/大数据的团队

如果两者都做，怎么验证谁更好

不要拍脑袋。科学的做法是用同一份数据集分别跑 LoRA 和全参数，再用一套统一的评测指标对比（评测方法第 9 章会细讲）：

  1. 固定同一份训练集和验证集；
  2. 分别用 LoRA 和全参数训练；
  3. 在验证集上跑同样的评测（如准确率、BLEU、或人工打分）；
  4. 对比指标 + 训练成本。

只有拿数据说话，你才能确定「多花的钱是否值得」。

混合方案：先 LoRA 后全参数 / 渐进式

有些团队会先快速用 LoRA 验证数据好不好、流程对不对，确认可行后再上全参数精调。也有人用「全参数冷启动 + LoRA 收尾」的组合。这些都是工程经验，值得记住的是：

先用便宜的方案把不确定性消掉，再决定要不要上贵的方案。

为什么 LoRA 这么「能打」：原理层面再挖一层

很多人好奇：只训练 1% 的参数，凭什么能接近全参数的效果？两个层面的解释：

1. 微调是「轻量重定向」而不是「从头学起」。 基座模型已经学会了语言的绝大部分规律。微调要做的改变很小——只是把已有的能力「拨」向你的方向。这种小改变，用低秩矩阵就能表达，不需要动全部参数。

2. 低秩假设在微调场景成立。 大量研究（包括 LoRA 原始论文）观测到：微调产生的权重变化 ΔW 的「有效秩」很低，大部分信息压缩在少数几个主方向上。所以 A×B 的低秩近似足够表达这个变化，丢失的只是「噪声级」的细节。

这就是 LoRA 的底气：它赌的就是「微调的改变本质上是小维度的」——而实验证明这个赌注几乎总是赢。

全参数的隐藏优势：你可能没注意到的

虽然 LoRA 很能打，全参数仍有几个 LoRA 难以替代的优势：

  1. 改变「深层结构」的能力：LoRA 的便签只能贴在原结构上；全参数可以重组层与层之间的协作方式。对需要「新推理范式」的任务，全参数的表达空间更大。
  2. 长尾能力的提升：数据量大时，LoRA 的低秩近似可能漏掉「分布尾部」的细微调整，全参数能覆盖得更完整。
  3. 消除「LoRA 痕迹」：有些任务上，LoRA 训练过的模型仍会残存「基座的默认倾向」（比如基座爱说英文，LoRA 也压不住），全参数能更彻底地改写。

这些差异在「数据量大 + 任务重」时才会明显，日常小任务几乎感知不到。

LoRA 内部的调优空间：别只用一个默认值

如果你决定用 LoRA，还有几个参数值得调——它们对效果的提升可能比「换不换全参数」更明显：

1. r（秩）：8、16、32、64。秩太小学不透，太大失去「低秩」的意义。经验：先 16，效果不够再升 32/64。

2. lora_alpha：缩放系数。alpha/r 的比值影响 LoRA 的「学习强度」。常用 alpha = r 或 2r。想加强微调影响就调大 alpha。

3. 挂在哪些层：只挂注意力层 vs 连 FFN 层一起挂，效果差异明显。全挂（默认建议）更稳。

4. 作用范围（LoRA 的 target）：一些实现支持「只对特定层」挂 LoRA（比如只挂前几层或后几层），可以做更精细的实验。

社区经验：先调 r 和 alpha，再看层覆盖——这两步往往能榨出比「纠结全参数」更大的提升。

一个「决策流程图」

把这一章的逻辑浓缩成一张决策流：

要微调了
├─ 数据 < 1 万条？
│    ├─ 是 → 直接用 LoRA（数据太少，全参数易过拟合）
│    └─ 否 ↓
├─ 有充足多卡算力？
│    ├─ 否 → 用 LoRA（或 QLoRA），先把效果做到位
│    └─ 是 ↓
├─ 任务需要「整体能力重构」？
│    ├─ 否 → LoRA 足够，跑几版对比再说
│    └─ 是 → 全参数微调（并准备足够的评测来验证值不值）
└─ 永远记得：先用便宜方案消除不确定性

照着走，你基本不会选错。

实战案例：一个真实项目的选择过程

假设你要给公司做一个「法律文书助手」，让模型把口语描述改写成规范的法律文书风格。看看决策怎么走：

  1. 先估数据：你整理了 3000 条「口语 → 法律文书」改写对。数据 < 1 万条 → 按流程图走 LoRA 路线；
  2. 用 QLoRA + r=16 训练：8GB 显卡就能跑，一晚出结果；
  3. 评测对比基座：LoRA 版本在「格式规范性」上远超基座，但偶尔有个别术语不够专业；
  4. 尝试 r=32 + 全挂 FFN 层：术语问题明显改善，评分再涨一截；
  5. 要不要上全参数？：算了一笔账——需要租 4×A100，成本高 20 倍，而评测只差 3 分。结论：不值得，LoRA 封顶即可。

这个案例几乎是社区项目的标准剧本：LoRA 解决 90% 的问题，剩下的 10% 用调参解决，全参数只在极少数情况下才入场。

一个容易忽略的点：LoRA 与全参数可以「接力」

很多人把 LoRA 和全参数当成二选一，其实还有一种「接力」玩法：

第1棒：全参数微调（或继续预训练）把模型底子调到接近领域
第2棒：LoRA 收尾，把最后一公里的风格/格式定住

为什么有用？全参数先把「领域知识底子」打好（比如让模型真正懂法律术语），LoRA 再低成本地把「说话方式」固定下来。这样比「一步到位全参数」便宜，比「纯 LoRA」上限高。

不过这是进阶玩法，先把基础路线跑熟再尝试。

小练习

  1. 用你自己的数据，分别跑一次 LoRA 和一次全参数（可以用 MiniMind 小模型来省钱），记录各自的显存、时间和效果。
  2. 说出至少两个「LoRA 就够用」的场景，和两个「才值得上全参数」的场景。
  3. 为什么数据量很少时，LoRA 有时反而比全参数效果好？（提示：过拟合）
  4. 进阶：固定其它参数，只改 LoRA 的 r（8/16/32），对比评测分数，画一条「r-效果」曲线，找出你自己的甜蜜点。
