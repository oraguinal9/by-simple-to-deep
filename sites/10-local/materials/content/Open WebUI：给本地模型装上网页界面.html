Open WebUI：给本地模型装上网页界面

到现在为止，你都是通过「终端黑框」和模型聊天。这当然很酷，但如果你想给朋友用、想在手机/平板上访问、想要一个像 ChatGPT 一样漂亮的网页界面——该上 Open WebUI 了。

这一篇的目标：二十分钟内，让你的本地模型拥有一个功能齐全的「ChatGPT 同款」网页界面。

1. 先建立一个直觉：Open WebUI 是「咖啡馆前台」

你的模型（Ollama）是后厨，Open WebUI 是前台：

  • 顾客（你/你的朋友）进店，看到的是漂亮的菜单和座椅（网页界面）；
  • 点单后，前台把单子转给后厨（Ollama 跑模型）；
  • 做好后端上来（回答显示在网页上）。

技术上说：Open WebUI 是一个跑在你电脑上的网页服务，它只做「界面和交互」，真正干活的是背后的 Ollama。两者通过 HTTP 请求对接（Ollama 提供的本地 API，见第 8 篇 content/API 服务化：把本地模型变成接口.md）。

一次完整的请求是这样流动的：

你在浏览器里输入问题
   ↓
Open WebUI 收到并保存对话（浏览器 → 3000 端口）
   ↓
Open WebUI 把请求转发给 Ollama（http://localhost:11434）
   ↓
Ollama 加载模型，逐字生成回答
   ↓
回答原路返回，显示在网页上

这段流程解释了三个现象：网页打开很快但回答要等——因为速度由「后厨」（模型和硬件）决定；Open WebUI 和 Ollama 要分开装——它们是两个独立程序，职责不同；以及「换模型不用重启网页」——网页只是把请求转发出去，模型切换发生在 Ollama 那一层。

为什么要多此一举？

  1. 好看：ChatGPT 级别的现代化界面，聊天气泡、Markdown 渲染、代码高亮；
  2. 多用户：注册账号、多人同时用，每个人的对话互相隔离；
  3. 多端：手机、平板、同事的电脑，只要在同一网络下，浏览器一开就能用；
  4. 功能扩展：联网搜索、文件上传、知识库（RAG）、语音等，后厨（模型）不用动，前台全给你加上。

2. 部署前的准备

2.1 前提条件

项目 要求 说明
Ollama 已安装并在运行 第 3 篇已完成；用 ollama serve 确认服务在 11434 端口
模型 至少一个已下载 ollama run qwen2.5:7b 跑通过即可
Docker（推荐路线） 已安装 最简单可靠的部署方式
或者 Python 3.11+ 替代路线 没有 Docker 时的备选方案

先确认 Ollama 服务正常：

bash curl http://localhost:11434/api/tags

如果返回一段包含你已装模型名字的 JSON，说明后厨「开火了」，可以部署前台。

2.2 关于 Docker：一句话解释

Docker 是「集装箱」——把 Open WebUI 连同它需要的运行环境打包成一个盒子，在任何电脑上一键启动，不污染你的系统，删掉也干干净净。对 Open WebUI 这种组件，Docker 是最省心的方式。

对「Docker 是什么」还没概念的读者，暂时理解成「一键启动器」就足够了。你不需要懂容器、镜像这些底层概念——只要按命令执行，Open WebUI 就会被装进这个「集装箱」里跑起来。

3. 方案一（推荐）：Docker 一键启动

打开终端，执行这一条命令：

docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

初次运行会自动拉取镜像（约 2～3GB，需几分钟，视网速而定），之后每次开机它都会自动启动。

启动完成后，打开浏览器访问：

http://localhost:3000

3.1 首次使用三步走

  1. 注册账号：第一眼看到的是登录页，点「注册」，创建你的第一个账号（第一个账号自动成为管理员）；
  2. 登录：进入主界面，和 ChatGPT 几乎一模一样；
  3. 连接 Ollama：页面右上角（或设置里）找到「连接」，填写 Ollama 地址：
  4. 地址填：http://host.docker.internal:11434
  5. （Windows/macOS 用这个地址让 Docker 容器访问宿主机上的 Ollama；如果是 Linux 直接部署，可能填 http://localhost:11434）
  6. 点「保存」后，下拉模型列表就能看到你已下载的模型（如 qwen2.5:7b）。

如果模型列表是空的：检查 1) Ollama 服务是否在运行；2) 连接地址是否填对；3) 是否已下载模型（ollama list 看看）。90% 的「连不上」都是这三件事。

3.2 局域网访问：让手机/同事也能用

默认的 localhost:3000 只有本机能用。想在同一局域网内其他设备访问：

  1. 查你电脑的局域网 IP（Windows 用 ipconfig 看 IPv4 地址，比如 192.168.1.5）；
  2. 其他设备浏览器访问：http://192.168.1.5:3000。

安全性提醒：这等于把你的 AI 暴露给整个局域网，建议尽快设置好账号密码（默认要求注册登录，其实已经相对安全），不要在公共网络（如咖啡馆 Wi-Fi）上长期开放。

4. 方案二（替代）：没有 Docker 怎么办？

没装 Docker、或不想装，用 Python 直接跑：

# 需要 Python 3.11+
pip install open-webui
open-webui serve

启动后同样访问 http://localhost:3000。之后连接 Ollama 时，地址填 http://localhost:11434 即可。

两个提醒：pip install open-webui 在部分网络环境下安装较慢，耐心等待即可；Python 版本过低会直接报错，先确认 python --version 是 3.11 或更高。

如果 pip 安装失败（国内网络常有），可以加镜像源：

bash pip install open-webui -i https://pypi.tuna.tsinghua.edu.cn/simple

5. 体验进阶功能

Open WebUI 不只是「好看」——它是个功能怪兽，挑几个最实用的：

5.1 多模型切换

页面顶部下拉框直接切换模型（qwen2.5:7b、deepseek-r1:7b……），一次开多个模型随意对比。「同一个问题问两个模型」是学习本地部署最直观的乐趣。

5.2 联网搜索（Web Search）

在设置里配置搜索引擎（如 Google 或 SearXNG）后，可以给模型「开外挂」——问「今天的新闻」，它真的会去网上搜再回答，不再受限于训练截止日期。

5.3 文件上传

直接拖文件进对话框：把 PDF/Word/Excel 丢给它，让它总结、问答。Open WebUI 会做文本提取，把内容喂给模型。

5.4 知识库（RAG，检索增强生成）

在「文档」页面建一个知识库，把你的资料（制度文档、产品手册）传上去。之后提问时勾选知识库，模型会先从你的资料里检索相关内容再回答——这就是企业版的「专属 AI 助手」雏形，全在本地完成，数据不出门。

这里值得花 30 秒讲清楚 RAG 的原理，因为它太常被提到：

  • 模型本身并不知道你的私有资料——它的「知识」停留在训练截止的那一刻；
  • Open WebUI 会先把你的文档切块、建索引，像给文件编目录；
  • 你提问时，它先检索出最相关的几个片段，连同你的问题一起发给模型；
  • 模型基于这些片段作答，相当于「先查资料、再回答」。

好处很直观：既避免模型凭空编造你的业务细节，又不需要重新训练模型——只要换文档，知识库就跟着更新。

5.5 多人协同

管理员账号可以在「管理面板」里创建用户。几个人共用一个本地模型，对话、设置互不干扰，适合团队内网试用。

5.6 提示词模板（Prompt）

把常用的提示词存成模板，一键套用，比如「帮我润色」「翻译成英文」「写周报」。

5.7 语音输入

网页端支持麦克风语音输入（基于浏览器的语音识别），对着电脑说话就能提问。适合整理思路、懒得打字的时候——你说，它答，全程不用碰键盘。

5.8 对话导出

每条对话都能一键导出成 Markdown 文件，或直接生成分享链接。方便把有价值的问答沉淀成笔记、文档，配合知识库功能用效果更好。

6. 第一次配置：值得做的五件事

装上 Open WebUI 只是开始，花五分钟做这几件小事，体验会提升一大截。

第一件：设好默认模型。 在「设置 → 通用」里，把默认模型设为你最常用的 qwen2.5:7b。这样打开网页就能直接聊，不用每次从下拉框里挑。

第二件：理解「流式输出」。 默认回答是一个字一个字蹦出来的（这叫流式输出），这是正常现象，不是卡顿。如果你不习惯，可以在设置里关掉流式，回答会一次性完整显示——代价是要多等一会儿。

第三件：存几个提示词模板。 把「帮我润色这段文字」「总结这份文件」「翻译成英文」这类高频需求存成模板，下次一键调用，省去反复打字。

第四件：管好用户权限。 团队使用时，在「管理面板 → 用户」里创建成员账号并分配角色（管理员/普通用户），别让每个人都拿管理员权限乱改设置。

第五件：别追「最新版」。 Open WebUI 迭代很快。用 Docker 部署时建议固定一个版本号（如 :0.5.x），避免某次自动升级后配置不兼容。想更新时手动拉取新版本，更稳妥可控。

7. 常见问题速查

现象 原因 解法
打不开 localhost:3000 容器没起来 docker ps 看容器状态；docker logs open-webui 看日志
模型列表为空 Ollama 连接失败 确认 Ollama 在跑；核对地址 host.docker.internal:11434
上传文件报错 权限或格式 检查管理员设置里的文件上传开关；试试 PDF/文本
网页很卡 容器与浏览器争资源 模型推理本身吃资源，给电脑多点余量；关掉无用标签页
重启电脑后打不开 容器未随系统启动 Docker Desktop 设置里开启「开机自启」，或重新 docker start open-webui
中文显示为方块 浏览器/系统字体问题 换现代浏览器（Chrome/Edge），正常不会出现
登录后一直转圈 Ollama 负载过高 换更小模型或减少并发（见第 9 篇 content/性能调优：并发、批处理与显存优化.md）
忘记管理员密码 凭据丢失 通过 Docker 数据卷找回，或用 docker exec 重置用户

8. 关于安全，多说两句

Open WebUI 默认要求注册登录，已经挡掉了大部分风险。但本地部署不等于「绝对安全」，请记住几条底线：

  1. 别把端口直接暴露到公网。默认 -p 3000:8080 只监听本机，是安全的；不要手滑改成 0.0.0.0:3000:8080 或做公网端口映射；
  2. 局域网使用也要设强密码，别用默认账号名和弱口令；
  3. 确实需要外网访问时，优先用 Tailscale、frp 这类加密隧道方案，而不是裸奔的端口转发；
  4. 重要数据记得备份：执行 docker cp open-webui:/app/backend/data ./backup 可以把对话记录、知识库备份到本机目录。

安全这件事，多花五分钟设置，能避免未来很多麻烦。

9. 本章小结

  1. 架构：Open WebUI 是「前台」，Ollama 是「后厨」，两者通过本地 HTTP 接口协作；
  2. 部署：Docker 一行命令搞定（docker run -d -p 3000:8080 ...），没有 Docker 就用 pip install open-webui；
  3. 连接：Ollama 地址填 http://host.docker.internal:11434（容器）或 http://localhost:11434（本地进程）；
  4. 进阶：多模型切换、联网搜索、文件上传、知识库 RAG、多用户——本地也能享受「全家桶」。
