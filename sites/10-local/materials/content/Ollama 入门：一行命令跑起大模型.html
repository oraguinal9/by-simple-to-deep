Ollama 入门：一行命令跑起大模型

前面两篇我们讲了「为什么本地部署」和「硬件怎么选」，你可能已经跃跃欲试。这一篇，我们来一场十分钟的魔法：用一行命令，把一个大模型在你自己的电脑上跑起来。

这一篇的主角叫 Ollama。它是当前「在本地跑大模型」这件事里，最简单、最适合新手的工具，没有之一。

1. Ollama 是什么？——一个「模型管家」

先建立一个直觉。

假如大模型是一本书，那么「运行大模型」这件事，原本需要你：

  1. 下载模型文件（往往几十 GB）；
  2. 自己写代码把模型加载进内存/显存；
  3. 处理显卡兼容、参数配置、内存溢出等一堆问题；
  4. 自己想办法跟模型「对话」。

Ollama 把这些全部打包了。它像一个管家：

  • 你只需要说一句「把这本书拿来」（ollama pull 模型名）；
  • 管家负责取书、翻书、甚至帮你读出来（ollama run 模型名）；
  • 你不舒服时，管家还会帮你「换一本更薄的书」（换量化版本，见第 4 篇 content/模型格式与量化：GGUF 与 Q4/Q8.md）。

技术上说：Ollama 底层封装了 llama.cpp（一个高性能的 C++ 推理引擎），并在此基础上加了一层极其友好的命令行界面、模型仓库管理和内置的 API 服务。你不需要知道任何细节，Ollama 全替你搞定。（第 6 篇 content/推理引擎对比：llama.cpp、vLLM 与 Ollama.md 会拆开讲这层关系。）

2. 安装 Ollama：三平台一步到位

2.1 安装前的小准备

  • 确认电脑磁盘剩余空间至少 10GB（模型要下载到本地）；
  • 不用提前装 Python、显卡驱动（Ollama 一般会自动处理核心依赖）；
  • Windows 用户建议关闭会「吃内存」的大型软件，内存留给模型。

2.2 Windows 安装

  1. 打开浏览器，访问 Ollama 官网 ollama.com；
  2. 点击大大的 Download 按钮，选择 Windows；
  3. 下载得到一个 OllamaSetup.exe，双击运行，一路点「下一步」即可；
  4. 安装完成后，打开「命令提示符」或 PowerShell，输入：
ollama --version

如果能看到版本号（比如 ollama version 0.5.0），说明安装成功。

Windows 用户注意：Ollama 安装后会在右下角托盘常驻一个小图标，这代表服务已经在后台运行。如果你看到它，说明 Ollama 已经「待命」了。

2.3 macOS 安装

  1. 同样访问 ollama.com，下载 macOS 版本的安装包（Ollama-darwin.zip）；
  2. 解压后把 Ollama 拖进「应用程序」文件夹，双击打开；
  3. 打开「终端」，输入：
ollama --version

Apple Silicon（M 系列）的 Mac 是 Ollama 的最佳拍档——得益于统一内存，它能把大模型装进内存跑得飞快。16GB 内存跑 7B 模型毫无压力。

2.4 Linux 安装

Linux 用一行命令搞定（安装脚本会帮你处理依赖）：

curl -fsSL https://ollama.com/install.sh | sh

安装完成后同样验证：

ollama --version

3. 见证奇迹：一行命令跑起大模型

3.1 第一次运行

打开终端（Windows 是命令提示符/PowerShell，macOS/Linux 是终端），输入：

ollama run qwen2.5:7b

然后，等待。第一次运行会自动下载模型文件（大约 4～5GB，取决于网络速度），下载完成后你会看到这样的界面：

>>> 你好，你是谁？

就像打开了一个聊天框。你输入一句话，回车，模型就开始回答。到这一步，你已经在自己的电脑上成功运行了一个大模型。

试试这些输入，感受一下它的能力：

>>> 用三句话介绍一下你自己
>>> 帮我写一首关于夏天的五言绝句
>>> 1+1 为什么等于 2？
>>> /bye   （退出对话）

为什么推荐 qwen2.5:7b？因为 Qwen（通义千问）系列是当前中文能力最强、最平衡的开源模型之一，7B 这个规模对普通硬件最友好。第 5 篇 content/开源模型怎么挑：Llama、Qwen 与 DeepSeek.md 会教你怎么按任务挑模型。

3.2 看懂这行命令的结构

ollama run qwen2.5:7b 拆开看：

  • ollama：调用 Ollama 这个程序；
  • run：告诉它「我要运行/进入对话」；
  • qwen2.5：模型的名字（这是阿里通义千问 2.5 系列）；
  • :7b：模型的规格标签（这是 70 亿参数版本）。

在终端里，模型内部的斜杠命令还有几个：

/bye       退出对话
/help      查看帮助
/?         查看当前会话信息
/clear     清空当前对话上下文

4. 常用命令速查：把模型「管」起来

对话只是入门，Ollama 真正强大的是它简洁的命令体系。下面这些命令，建议都亲手敲一遍：

4.1 列出已安装的模型

ollama list

输出会告诉你：你下载了哪些模型、各占多大空间。这个命令你会经常用。

4.2 下载指定模型（不进入对话）

有时候只想下载，不想立刻用：

ollama pull qwen2.5:7b

pull 的意思是「拉取」，等价于下载。ollama run 会自动先 pull 再 run，所以平时直接用 run 即可。

4.3 换一个模型试试

不需要退出再重新输命令，直接：

ollama run llama3.2:3b

Ollama 会自动下载这个新模型并进入对话。想换就换，这是本地部署最大的自由——云端你只能被动等厂商更新。

4.4 查看模型信息

ollama show qwen2.5:7b

会显示这个模型的架构、参数量、上下文长度等元信息，适合进阶玩家查看。

4.5 删除不用的模型（释放硬盘）

ollama rm qwen2.5:7b

模型动辄几 GB，删掉不用的能救回不少硬盘空间。

4.6 让 Ollama 作为服务常驻（重要！）

Ollama 安装后其实默认就在后台运行一个本地服务，监听在 127.0.0.1:11434。也就是说，它不只是个命令行玩具，还是一个 API 服务器。查看状态：

ollama serve

这个 serve 命令很重要：后续章节（Open WebUI、API 服务化）都要依赖这个本地服务。正常安装后它已经自动在跑，如果你手动折腾过，用这条命令重启服务即可。它默认监听 http://localhost:11434，这就是你电脑上的「AI 服务器」地址。

5. 停止与排障：遇到问题别慌

5.1 退出对话 / 停止服务

  • 退出当前对话：在对话框输入 /bye；
  • 停止后台服务：
  • Windows：任务栏右下角 Ollama 图标，右键 → 退出；
  • macOS：菜单栏 Ollama 图标 → 退出；
  • Linux：systemctl stop ollama（或用 pkill ollama）。

5.2 常见问题快修

现象 原因 解决办法
提示 manifest not found 模型名打错了 用 ollama list 看已装模型，复制准确名字
下载很慢/中断 网络问题 重跑一次 ollama pull，支持断点续传
报显存不足（CUDA out of memory） 模型太大 / 精度太高 换更小模型或量化版（见第 4 篇）
回答乱码 终端编码问题 换 Windows Terminal，或设置 chcp 65001 切到 UTF-8
运行时很卡、风扇狂转 硬件吃不消 减少同时开的大程序；换更小模型
模型答非所问 上下文太长被截断 用 /clear 清空历史再问

5.3 两个容易被忽略的小问题

问题一：Windows 上命令找不到了？

明明装好了，但新开的终端里输入 ollama 却说「不是内部或外部命令」。多半是环境变量没刷新——Ollama 安装时会把自身加入 PATH，但已打开的终端窗口不会自动感知。解法：关掉当前终端，重新开一个；或者干脆重启一次电脑，保证万无一失。

问题二：下载到一半断了，要重新下载吗？

不用。Ollama 的模型下载支持断点续传，网络恢复后重跑一次 ollama pull qwen2.5:7b，它会从上次中断的地方继续，不会从头开始。耐心等它跑完即可，不要反复重试同一条命令造成干扰。

6. 跑通之后：五个有趣的小实验

第一次成功对话，值得好好庆祝。但别停下来，用下面五个小实验巩固手感：

实验一：连续对话，看它记不记得你说了什么

>>> 我的名字叫小明
>>> 我叫什么名字？

如果它回答「小明」，说明它记住了上下文。本地模型的好玩之处就在这里——对话内容只存在你的电脑里。

实验二：让它角色扮演

>>> 请你扮演一个幽默的历史老师，用三句话讲秦朝

系统会给它设定「人设」，回答风格完全不同。这是未来做「专属助手」的基础。

实验三：换一个不同规模的模型对比

ollama run qwen2.5:1.5b

问同样的问题，对比 1.5B 和 7B 的回答质量差异。你会亲眼看到「参数越多越聪明」这句话的意思——这也是本地部署最直观的「实验课」。

实验四：让它处理一段长文本

粘贴一段 500 字的文章，然后问「用三句话总结」。注意观察：模型要「读完」再「总结」，中间会停顿——这就是它在读取上下文。

实验五：用 ollama ps 偷看后台

ollama ps

对话的同时打开另一个终端运行这条命令，能看到模型占用了多少显存/内存。你正在用「上帝视角」观察一个大模型在你电脑里的运行状态——这在云端永远看不到。

7. Modelfile：给模型「调口味」的配方文件

当你玩熟了基础操作，Ollama 还提供一个深度定制的入口——Modelfile。它是一份「配方」，可以自定义模型的默认行为。

最简单的用法是写一个 Modelfile 文件：

# Modelfile 内容
FROM qwen2.5:7b

# 设置系统提示词，让模型每次默认带这个人设
SYSTEM 你是一位耐心的中文写作教练，回答要简洁、口语化

# 调整默认参数
PARAMETER temperature 0.7
PARAMETER num_ctx 8192

然后在终端构建并运行：

ollama create my-coach -f Modelfile
ollama run my-coach

现在每次对话，模型都默认带着你设定的「人设」和参数。这个能力在后续章节（如第 9 篇 content/性能调优：并发、批处理与显存优化.md）会反复用到，先知道有这回事即可。

8. 和 ChatGPT 的体验对比：本地 vs 云端

跑通之后，你可能想问：这和 ChatGPT 有什么区别？

维度 ChatGPT（云端） Ollama 本地
隐私 数据上云 数据不出本机
费用 会员/按量收费 免费，只花电费
联网 必须联网 完全离线可用
速度 受网络和服务器影响 取决于你硬件，本地加载更快
能力上限 极高（几百 B 参数） 取决于你能跑多大的模型
换模型 只能等厂商 一行命令随意换
多模态 官方支持图片等 需选支持多模态的模型（如 llama3.2-vision）

体验上最直观的差别是：本地模型「秒回」还是「慢慢打字」取决于你的硬件；而云端模型受网络波动影响。对一个 7B 量化模型来说，在稍好一点的显卡上，打字速度（生成速度）可以接近甚至超过人阅读的速度，体验已经相当不错。

9. 进阶预告：Ollama 不只是「聊天」

你现在学会的 ollama run，只是 Ollama 能力的冰山一角。实际上：

  • 它内置了 OpenAI 兼容 API（第 8 篇 content/API 服务化：把本地模型变成接口.md）——你可以在 http://localhost:11434/v1 上用现成的代码库调用本地模型；
  • 它可以被 Open WebUI 无缝接入，变成像 ChatGPT 一样的图形化网页（第 7 篇 content/Open WebUI：给本地模型装上网页界面.md）；
  • 它支持 Modelfile 自定义模型参数（温度、上下文长度、系统提示词），等你熟悉后可以深度定制。

10. 本章小结

这一篇你收获了三样东西：

  1. 安装方法：Windows / macOS / Linux 三步装好 Ollama；
  2. 核心命令：run 运行、pull 下载、list 查看、show 详情、rm 删除、serve 起服务；
  3. 一条铁律：ollama run qwen2.5:7b——你已经在本地跑起了大模型。
