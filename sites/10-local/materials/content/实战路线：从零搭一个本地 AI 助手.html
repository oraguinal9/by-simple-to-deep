实战路线：从零搭一个本地 AI 助手

这是本阶课程的收官篇。前 9 篇你学会了：为什么本地部署（第 1 篇）、硬件怎么选（第 2 篇）、用 Ollama 跑模型（第 3 篇）、理解量化格式（第 4 篇）、挑选开源模型（第 5 篇）、认清推理引擎（第 6 篇）、装上网页界面（第 7 篇）、把模型变成接口（第 8 篇）、做性能调优（第 9 篇）。

这一篇不教新东西，而是把所有技能串起来，给你一条完整的「从零到一」实战路线：一个能在自己电脑上运行、有网页界面、能通过接口被程序调用的本地 AI 助手。并附上最常见的坑和「新手怎么逐步加料」的路线图。

1. 整体蓝图：你要盖的「三层楼」

把最终目标拆开，是一栋三层小楼：

第三层：应用层
    Open WebUI（网页界面） / 你的程序（API 调用）
        ↕ HTTP
第二层：服务层
    Ollama 服务（http://localhost:11434，含 /v1 兼容接口）
        ↕ 内部调用
第一层：模型层
    GGUF 量化模型（如 qwen2.5:7b） + 你的硬件（GPU/CPU/内存）

建议顺序：先盖第一层，再盖第二层，最后盖第三层。 每一层跑通了再往上盖，出问题时也知道去哪里找。

这套三层结构还有一个隐藏的好处：每一层都可以独立替换。第一层不满意就换模型（一行命令的事），第三层不满意就换界面（换个前端工具），中间的 Ollama 服务层完全不用动。模块化设计，正是这套生态最有生命力的地方。

2. 第一步：选模型（5 分钟）

复习第 5 篇的决策流程：

  1. 中文为主 → Qwen 系；数学/代码 → DeepSeek 系；
  2. 按显存定规模：新手统一从 7B 起步，量化用 Q4_K_M 级别；
  3. 本教程默认选择：qwen2.5:7b——中文能力强、硬件要求亲民、社区资料多。

还没把握就再看一眼对照表：

你的显存 起步模型
无独显/4GB qwen2.5:3b
8GB qwen2.5:7b
12GB+ qwen2.5:14b

3. 第二步：安装 Ollama 并跑起来（15 分钟）

3.1 安装

按第 3 篇的方法装好 Ollama（官网下载或 curl 脚本），验证：

ollama --version

3.2 拉取并运行模型

ollama run qwen2.5:7b

第一次会下载约 4.5GB，稍等片刻，然后聊几句验证：

>>> 你好，请用三句话介绍你自己
>>> /bye

到这里，你已经完成了「模型层 + 服务层」的最小闭环。恭喜，你的本地 AI 助手已经存在了。

3.3 确认服务在跑

curl http://localhost:11434/api/tags

能看到模型列表，说明服务就绪。这个服务是后续所有东西的地基。

这里做一次「开工自检」：确认电脑磁盘剩余空间大于 10GB、内存大于等于 16GB（跑 7B 更从容）。条件不满足也别放弃——第 2 篇 content/硬件怎么选：显存、内存与 CPU 的账.md 里讲了低配方案，先从 3B 小模型起步即可。

4. 第三步：装上网页界面（20 分钟）

按第 7 篇部署 Open WebUI（二选一）：

路线 A（推荐，需要 Docker）：

docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main

浏览器打开 http://localhost:3000 → 注册账号 → 在设置里把 Ollama 地址填成 http://host.docker.internal:11434 → 下拉选择 qwen2.5:7b。

路线 B（无 Docker）：

pip install open-webui
open-webui serve

访问 http://localhost:3000，Ollama 地址填 http://localhost:11434。

验收标准：网页上能发出第一条消息并收到回答。做到这一步，你已经拥有一个「长得像 ChatGPT 但完全本地」的 AI 助手了。

Windows 用户提示：装 Docker 通常需要 WSL2 支持（Docker Desktop 安装时会自动引导开启）。如果你的电脑较旧、系统版本低，装不了 Docker，直接走路线 B 用 Python 安装 Open WebUI 即可，功能几乎没有差别。

5. 第四步：把接口也打通（10 分钟）

按第 8 篇，写一个最小调用脚本 assistant.py：

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",  # 指向本地
    api_key="ollama",                       # 本地不校验，随意
)

resp = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[{"role": "user", "content": "你好，介绍一下你自己"}],
)

print(resp.choices[0].message.content)

运行：

python assistant.py

看到输出，你的助手就同时具备了「网页入口」和「程序接口」两种使用方式。

6. 第五步：调优与加料（按需进行）

6.1 基础调优（第 9 篇）

  • 上下文嫌慢 → 把 num_ctx 调到 4096 或 8192；
  • 写代码/总结乱说 → 调低 temperature 到 0.2；
  • 显存不够 → 换 Q4、缩上下文、降并行数；
  • 太慢 → ollama ps 看 GPU/CPU 分配，确认 GPU 用足。

6.2 进阶加料（自由选择）

加料 用什么 效果
知识库问答 Open WebUI 的「文档/知识库」功能 让它基于你的资料回答（RAG）
联网搜索 Open WebUI 的 Web Search 配置 问实时信息不再受训练截止日期限制
换更强模型 32B 量化版（显存够时） 回答质量上一个台阶
接进自己的程序 /v1 接口 + OpenAI 库 写自动日报、批量总结、自定义机器人
多用户团队 Open WebUI 账号系统 + 局域网访问 全公司内网共用一个本地 AI

加料的优先级怎么定？ 一句话：按你的使用场景排序。主要查公司资料 → 先上知识库；主要问实时信息 → 先配联网搜索；团队多人用 → 先管好账号。一次只加一个功能，跑稳了再加下一个——避免「叠了五个功能，出问题不知道怪哪层」。

7. 三大常见坑与解法

7.1 坑一：显存不足（OOM）

表现：对话报 out of memory / 模型加载失败 / 回答到一半中断。

解法（按顺序试）： 1. 换更小量化：qwen2.5:7b → 确认是 Q4 级别； 2. 缩短上下文：重开会话、或调低 num_ctx； 3. 关掉其他吃显存的程序； 4. 换更小模型：7B → 3B； 5. 实在不行用 CPU 混合推理（慢但能跑）。

7.2 坑二：中文乱码 / 中英文混杂

表现：回答出现 ???、方块字，或英文模型偶尔冒出英文。

解法： - 乱码：终端编码问题，Windows 执行 chcp 65001 切到 UTF-8，或换 Windows Terminal； - 中英混杂：这是模型本身的语言偏好——换 Qwen 系模型（中文语料充足）基本解决；或在系统提示词里写「请始终用简体中文回答」。

7.3 坑三：模型「一本正经地胡说八道」（幻觉）

表现：编造不存在的书、错误的法律条文、自信地给错答案。

解法： - 降低 temperature，减少发散； - 事实敏感的任务，要求它「不知道就明确说不知道」； - 让它给出依据（引用原文）；知识库场景（RAG）天然缓解幻觉； - 记住：本地小模型的能力边界就在那里——重要决策务必人工复核。

7.4 坑四：硬盘空间不足

表现：下载模型到一半提示空间不足，或系统越来越卡。

解法： 1. 下载前先看磁盘剩余空间（一个模型通常占 4～8GB）； 2. 把模型目录放到空间充足的分区； 3. 定期 ollama list 看清单、ollama rm 删掉不再用的模型。

补充一个实用技巧：想自定义模型存放位置（比如放到 D 盘），Windows 上设置环境变量 OLLAMA_MODELS=D:/ollama/models 后再启动 Ollama，模型就会下载到新目录——对 C 盘紧张的用户非常友好。

8. 新手路线图：先跑通最小闭环，再逐步加料

给完全从零开始的你一张「分阶段验收单」，每一阶段都有明确的「跑通信号」：

阶段 做什么 跑通信号
0 装 Ollama ollama --version 有输出
1 跑 7B 模型 ollama run qwen2.5:7b 能聊天
2 装 Open WebUI 网页能选模型、能对话
3 调优（缩上下文/调温度） 回答更快、更稳定
4 API 打通 Python 脚本输出回答
5 加料（知识库/联网/换大模型） 新功能生效
6 长期使用（定时任务/团队共享） 稳定运行不崩溃

核心心法：永远先跑通「最小的那个版本」，再往上加东西。 很多人失败不是因为难，而是因为一口气想把所有功能装齐——结果每个环节都半吊子，出了问题不知道怪谁。一次只改一个变量。

9. 延伸实战：让它「自动干活」

跑通人工对话后，可以再加一步「自动化」。举个最简单的例子：每天早上自动生成一份昨天的工作日报草稿。

写一个 daily_report.py，配合系统的定时任务，每天 9 点自动执行：

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

logs = "昨天完成：修复登录页 bug、评审新需求文档、与设计团队对齐视觉稿"

resp = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[
        {"role": "system", "content": "你是日报生成器，把零散记录整理成条理清晰的日报"},
        {"role": "user", "content": f"请整理成日报：\n{logs}"},
    ],
    temperature=0.3,  # 事实整理类任务，低温度更稳定
)
print(resp.choices[0].message.content)
  • Windows：用系统自带的「任务计划程序」，创建基本任务，设置每天 9:00 运行 python daily_report.py；
  • macOS / Linux：用 crontab -e，添加一行 0 9 * * * python /路径/daily_report.py。

原理其实就一句话：本地 API + 定时任务 = 你的专属自动化助手。数据全程不出本机，放心让它「替你干活」而不必担心隐私外泄。

10. 常见问题速查（贴在电脑边）

问题 快速解法
开机后 Open WebUI 打不开 docker start open-webui，并确认 Ollama 服务在运行
模型越聊越慢 上下文被撑大，开新会话或调低 num_ctx
想换模型但硬盘不够 ollama rm 旧模型 释放空间，再 ollama pull 新模型
断网后还能用吗 能——本地部署全流程离线可用，这正是它的优势
手机连不上局域网页面 确认同一 Wi-Fi、防火墙放行 3000 端口、地址用电脑的局域网 IP
回答总是不对劲 先降 temperature，再考虑换家族/升规模（见第 5 篇）

ollama run qwen2.5:7b

最后补充三条「长期使用习惯」，让你的助手能稳定服役很久：
