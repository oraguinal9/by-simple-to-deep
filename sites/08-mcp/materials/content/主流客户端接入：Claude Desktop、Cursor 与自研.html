主流客户端接入：Claude Desktop、Cursor 与自研

Server 写好了，得有人来「连」它。连 Server 的那个角色就是 Host（宿主应用）。这一章讲几个最常见的 Host 怎么接入 MCP Server，以及如果你想自己做一个 Host，核心逻辑是什么。

一、Claude Desktop（桌面端 Host）

Claude Desktop 是官方最早支持 MCP 的 Host。接入方式就是在它的配置文件里声明要连哪些 Server。

配置位置（示意）

  • macOS：~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows：%APPDATA%\Claude\claude_desktop_config.json

配置示例（STDIO 本地 Server）

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/你/Desktop"]
    },
    "demo": {
      "command": "python",
      "args": ["/绝对路径/server.py"]
    }
  }
}

重启 Claude Desktop 后，它会在后台启动这些 Server 子进程，并把它们的能力提供给模型。你在对话里说「读一下我桌面上的 xxx」，模型就会去调 filesystem Server。

它的行为特点

  • 启动时拉起所有配置的 Server；
  • 自动做能力发现（tools/list 等）；
  • 危险操作弹确认框（人在回路，见第九章）；
  • 配置是「声明式」的——你只说「连谁」，具体协议它内部搞定。

二、Cursor（IDE 里的 Host）

Cursor 这类 AI 编程 IDE，把 MCP 当「给编程 Agent 接工具」的渠道。开发者可以接：

  • 文件系统 / Git Server（让 Agent 读写代码）；
  • 数据库 Server（让 Agent 查 schema）；
  • 自定义内部工具 Server（让 Agent 调公司接口）。

配置思路

Cursor 的设置里有一个 MCP 配置区，填法和 Claude Desktop 类似：指定 command + args（STDIO）或指定远程 URL（HTTP+SSE）。配好后，Agent 在「自动写代码 / 跑命令」时就能用上这些能力。

和桌面聊天 Host 的区别

  • 编程 IDE 的 Host 更强调「让 Agent 自主完成多步任务」（读代码→改代码→跑测试→看结果）；
  • 因此它对「多 Server 组合」「长链路工具调用」的依赖更强；
  • 权限模型也更激进（允许 Agent 跑命令），所以安全设置要更谨慎。

三、自研 Host：核心逻辑是什么

如果你想做一个自己的 AI 应用，并接入 MCP，核心就这五步：

第 1 步：选一个 MCP Client 库

你的应用里需要一个「会讲 MCP 协议」的 Client 组件。各语言都有 SDK（Python、TypeScript 等）。它负责和 Server 建立连接、收发 JSON-RPC。

第 2 步：启动 / 连接 Server

  • STDIO：用 subprocess 把 Server 脚本拉成子进程，把它的 stdin/stdout 接给 Client；
  • HTTP+SSE：Client 用 POST 发请求、用 SSE 收推送。

第 3 步：能力发现

连上后，Client 调 tools/list、resources/list、prompts/list，拿到 Server 会什么，存起来给模型用。

第 4 步：把能力喂给模型

把发现到的工具清单，按你所用模型的格式（OpenAI 的 / Anthropic 的 / 通用的），塞进每次请求。模型才知道有这些工具可用。

第 5 步：转发调用、回灌结果

模型返回「我要调 X 工具、参数是 Y」，你的程序： 1. 通过 Client 把调用发给对应 Server； 2. 拿到结果； 3. 把结果拼回对话，让模型继续生成。

这就是第二章讲的「模型出意图 → 程序执行 → 结果回灌」在你自建 Host 里的落地。

伪代码骨架

client = MCPClient()              # 第1步：Client 库
await client.connect_stdio("python", "server.py")   # 第2步：连 Server
tools = await client.list_tools()                   # 第3步：发现能力
reply = model.chat(user_msg, tools=tools)            # 第4步：带能力问模型
if reply.wants_tool_call:
    result = await client.call_tool(reply.name, reply.args)  # 第5步：转发
    reply = model.chat(append_result(result))        # 回灌后继续

四、接入时的常见坑

坑 现象 解决
Server 启动失败 Host 连不上 看 Server 的 stderr 日志（不是 stdout）
STDIO 下 Server 往 stdout 打日志 协议流被污染，Client 报错 日志改 stderr / 文件
工具太多模型选不准 瞎调、漏调 精简暴露、写好 description
远程 Server 没鉴权 谁都能调 加 token / HTTPS
忘了回灌结果 模型答非所问 确保结果进了下一轮对话

五、三种 Host 怎么选

  • 只想体验：用 Claude Desktop，改个 JSON 配置就行；
  • 做编程助手：用 Cursor 类 IDE，让 Agent 接代码/数据库 Server；
  • 做自己的产品：用 MCP Client SDK 自研 Host，按上面五步走。

MCP 的价值在这里体现得最清楚：同一个 Server，三个不同的 Host 都能直接用，不用为每家重写对接。

六、本章小结

  • Host 是「连 Server 的那个应用」，主流有 Claude Desktop（配置式）、Cursor（Agent 式）、自研（SDK 式）；
  • 接入通用流程：选 Client 库 → 连 Server → 能力发现 → 喂给模型 → 转发调用并回灌；
  • STDIO 用子进程 + stdin/stdout；HTTP+SSE 用 POST + SSE；
  • 常见坑：Server 日志污染 stdout、工具过多、远程无鉴权、忘回灌结果；
  • 核心价值：一个 Server 被多 Host 复用，零重复对接。

下一章我们重点讲安全与权限——这是 MCP 落地时最容易翻车、也最重要的一环。
