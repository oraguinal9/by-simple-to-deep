工具调用基础：模型如何「动手」

在讲 MCP 的架构之前，我们必须先搞清楚一件事：模型本身是怎么「调用工具」的？ 因为 MCP 只是在「模型决定调工具」之后，负责把这件事标准化地执行下去。理解了这个「决定」是怎么来的，后面才不迷糊。

一、模型不会「直接执行」任何东西

一个最关键的认知：大模型本质上是个「文本补全器」。你给它一段文字，它预测下一个最可能的文字。它不能直接读文件、不能直接发请求、不能直接算数。

那为什么看起来它能「调工具」？因为整个流程是人和代码配合的结果：

  1. 你给模型一段对话 + 一份「工具清单」；
  2. 模型输出一段特殊格式的文字，表示「我想调这个工具，参数是这些」；
  3. 你的程序解析这段输出，真的去执行那个工具；
  4. 程序把执行结果塞回对话里，再让模型继续；
  5. 模型看到结果，生成最终回答。

模型从头到尾只干了「输出一段表示意图的文字」这一件事。真正「动手」的是你的程序。

二、一次工具调用的完整往返

用一个「查天气」的例子，把每一步摊开：

第 1 步：你提供工具清单

系统：你有一个工具 get_weather(city)，可查询城市天气。
用户：北京今天天气怎么样？

第 2 步：模型返回「调用意图」

模型不回答天气，而是返回一个结构化请求（不同厂商格式不同，这里用通用形式）：

{
  "action": "get_weather",
  "parameters": {"city": "北京"}
}

注意：这不是「模型去查了天气」，而是「模型说：请帮我查北京天气」。

第 3 步：你的程序执行

你的代码看到这个请求，真的去调天气 API，拿到：

{"city": "北京", "temp": 26, "condition": "晴"}

第 4 步：结果回灌给模型

程序把结果拼回对话：

工具返回：{"city":"北京","temp":26,"condition":"晴"}

第 5 步：模型作答

模型基于这个结果，生成自然语言：

北京今天晴，气温 26°C，适合出门。

整个过程里，模型两次输出文字（一次意图、一次回答），程序做了一次真实执行。这就是「模型用工具」的全部真相。

三、为什么模型「知道」该调哪个工具

模型不是天生知道 get_weather 的存在。它靠的是你在 prompt / 工具清单里清楚地描述了每个工具：

  • 工具名字（get_weather）
  • 工具干嘛的（查询城市天气）
  • 需要什么参数（city: 城市名）
  • 参数怎么填（description）

模型在海量训练数据里见过无数「函数调用」的模式，所以它能根据「用户问天气」+「有个叫 get_weather 的工具」，推理出「应该调它」。工具描述写得越清楚，模型选得越准。

经验法则：给模型的工具 description，要写得像「给一个聪明但没见过这个系统的新人看的说明」。

四、参数怎么保证「填对」

模型生成的参数，本质上是「自由文本预测」，可能出错（比如 city 填了数字）。所以成熟的系统都会：

  1. 用 JSON Schema 约束：告诉模型参数必须是什么类型、哪些必填；
  2. 校验：程序拿到模型输出后，先验证参数合法再执行；
  3. 容错：参数不对就回灌错误，让模型重试。

这也是为什么工具定义里总有一大坨 properties / required —— 那是给模型「照着填」的模板。

五、模型「调工具」和「回答」是交替的

复杂任务往往不是「调一次就完」。比如「对比北京和上海今天的温度」：

  1. 模型调 get_weather(北京)；
  2. 程序执行，回灌结果；
  3. 模型调 get_weather(上海)；
  4. 程序执行，回灌结果；
  5. 模型拿到两个结果，生成对比回答。

这种「思考 → 调用 → 看结果 → 再思考」的循环，是 Agent（智能体）的核心运转方式。MCP 要服务的，正是这种多轮、多工具的场景。

六、常见误区澄清

误区 真相
模型自己联网查了资料 是程序替它查，再把结果喂回去
模型「运行」了代码 是程序运行，模型只生成了代码/调用意图
工具是模型的一部分 工具在模型外部，由客户端/Server 提供
调工具一定会成功 可能参数错、可能执行失败，需要校验和重试

七、本章小结

  • 大模型只是文本补全器，不能自己执行任何外部操作；
  • 「模型调工具」= 模型输出「调用意图」→ 程序执行 → 结果回灌 → 模型作答；
  • 模型靠你提供的清晰工具描述来选工具和填参数；
  • 参数要用 JSON Schema 约束 + 程序校验 + 重试来保证正确；
  • 真实任务常是「思考 → 调用 → 看结果」的多轮循环，这正是 MCP 要支撑的场景；
  • 牢记：模型「动手」是假象，真正动手的是你的代码。
