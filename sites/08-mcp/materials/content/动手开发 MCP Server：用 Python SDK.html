动手开发 MCP Server：用 Python SDK

前面都是概念，这一章我们写代码。我会用 MCP 官方 Python SDK（mcp 包），从零写一个最小的「计算器 + 问候」MCP Server，跑在 STDIO 模式下，让你亲眼看到它是怎么被 Host 连上的。

说明：本章代码是为了讲清原理的最小示例，真实项目请用 SDK 的最新 API。运行时需 pip install mcp。

一、先想清楚这个 Server 提供什么

我们做一个教学 Server，暴露两个 Tool：

  1. add(a, b) —— 两数相加；
  2. greet(name) —— 向某人问好。

就这么简单，但足以覆盖「定义工具 → 被调用 → 返回结果」的全链路。

二、最小 Server 代码

下面是使用 mcp Python SDK 的写法（基于 FastMCP 高层接口，最易读）：

# server.py
from mcp.server.fastmcp import FastMCP

# 创建一个 MCP Server 实例（名字随意）
mcp = FastMCP("demo-server")

@mcp.tool()
def add(a: int, b: int) -> int:
    """把两个整数相加，返回它们的和。"""
    return a + b

@mcp.tool()
def greet(name: str) -> str:
    """向给定名字的人问好，返回一句问候语。"""
    return f"你好，{name}！欢迎使用 MCP。"

# 以 STDIO 方式启动（默认从 stdin 读、往 stdout 写）
if __name__ == "__main__":
    mcp.run()

就这么多。你不需要手写 JSON-RPC、不用管消息怎么编码——SDK 帮你把 @mcp.tool() 装饰的函数，自动变成 MCP 协议里的 Tool：函数名 → tool 的 name，docstring → description，类型注解 → input_schema。

三、这背后发生了什么

当 Host 连上这个 Server 并问 tools/list 时，SDK 会根据你的装饰器自动生成类似：

{
  "tools": [
    {
      "name": "add",
      "description": "把两个整数相加，返回它们的和。",
      "input_schema": {
        "type": "object",
        "properties": {
          "a": {"type": "integer"},
          "b": {"type": "integer"}
        },
        "required": ["a", "b"]
      }
    },
    {
      "name": "greet",
      "description": "向给定名字的人问好，返回一句问候语。",
      "input_schema": {
        "type": "object",
        "properties": {"name": {"type": "string"}},
        "required": ["name"]
      }
    }
  ]
}

模型看到这份清单，就知道「哦，有 add 和 greet 可以用」。

当模型决定调 add(3, 5)，SDK 会： 1. 收到 JSON-RPC 调用请求； 2. 匹配到 add 函数，用参数 a=3, b=5 调用； 3. 把返回值 8 包成 JSON-RPC 响应发回去。

你只写了业务逻辑（return a + b），协议细节全交给 SDK。

四、怎么让 Host 连上它（STDIO 配置示例）

以 Claude Desktop 为例，在它的配置文件里加一段（示意）：

{
  "mcpServers": {
    "demo": {
      "command": "python",
      "args": ["/绝对路径/server.py"]
    }
  }
}

Host 启动时，会执行 python /绝对路径/server.py，把这个脚本当作子进程拉起来，然后经 stdin/stdout 跟它说 MCP 协议。这就把前面第五章讲的 STDIO 模式落地了。

五、加一个 Resource 试试

Resource 也很容易。我们加一个「服务器启动时间」的资源：

@mcp.resource("meta://uptime")
def uptime() -> str:
    """返回 Server 的就绪提示。"""
    return "demo-server 已就绪，可调用 add / greet。"

Host 或用户可以通过 meta://uptime 这个 URI 把这段内容注入上下文。注意 Resource 是「被读取的」，不像 Tool 那样由模型主动调。

六、加一个 Prompt 模板

@mcp.prompt()
def summarize(text: str) -> str:
    """生成一段要求模型总结文本的提示词。"""
    return f"请用三句话总结以下内容，并列出两个要点：\n\n{text}"

用户选中这个 Prompt、填入 text，Host 就拿到一段现成的总结指令发给模型。

七、开发时的关键注意事项

  1. STDIO 下别往 stdout 打日志：会破坏协议流。要打日志请用 logging 到文件或 stderr；
  2. docstring 要认真写：它就是模型看到的 description，写清楚「干嘛、何时用、参数含义」；
  3. 类型注解别偷懒：SDK 靠它生成 input_schema，错了模型就填错参数；
  4. 危险操作加闸门：写文件、删数据、发消息前，加权限判断或要求确认（见第九章）；
  5. 先本地 STDIO 跑通，再考虑远程：别一上来就折腾 HTTP+SSE。

八、从「能跑」到「能上线」

教学 Server 跑通后，真实项目通常是： - 把业务逻辑换成真实的（调数据库、调 API）； - 补充错误处理（参数非法、外部超时）； - 加权限与审计日志； - 如需多人用，再封装成 HTTP+SSE 远程 Server。

九、本章小结

  • 用 mcp Python SDK 的 FastMCP，一个 @mcp.tool() 就能把函数变成 MCP Tool；
  • docstring → description，类型注解 → input_schema，SDK 自动生成协议声明；
  • Host 通过 STDIO 把 Server 当子进程拉起，经 stdin/stdout 通信；
  • Resource（@mcp.resource(uri)）提供可读取数据，Prompt（@mcp.prompt()）提供模板；
  • 开发纪律：STDIO 日志走 stderr、写好 description、危险操作加闸门、先 STDIO 后远程。
