MCP 是什么：让 AI 模型连接真实世界的「USB 接口」

你有没有想过：为什么 ChatGPT、Claude 这些大模型，明明「什么都知道」，却没法帮你查一下今天的天气、读一下你电脑里的文件、或者在你公司的数据库里跑一条 SQL？

不是因为它们不够聪明，而是因为它们被关在一个「只有文字的笼子里」。它们能生成文字，却碰不到外面的世界。你问「我桌面上那个 CSV 里有多少行」，它只能说「我看不到你的文件」。

MCP（Model Context Protocol，模型上下文协议） 就是为了解决这个问题而生的。它是一套开放标准，用来规范「AI 模型」和「外部工具 / 数据 / 系统」之间怎么对话。官方喜欢打一个比方：MCP 就像 AI 世界的 USB-C 接口——以前每个设备都得配专用的线，乱七八糟；有了统一的 USB-C，只要插上就能用。MCP 想做的，就是给「模型接工具」这件事一个统一的标准。

一句话理解：MCP 是一套「让模型安全、标准化地调用外部能力」的协议，它定义了模型、客户端、服务端三方怎么通信。

一、没有 MCP 之前，世界是什么样

让我们先看「模型接工具」的原始状态，你就知道 MCP 为什么出现了。

1. 最早的「函数调用」是各玩各的

2023 年前后，OpenAI 推出了 Function Calling（函数调用），后来 Google、Anthropic 也都做了自己的版本。思路是：你给模型一份「函数清单」（名字、参数、说明），模型在回答时，如果觉得该调某个函数，就返回一个结构化的调用请求。

问题来了：

  • 每个模型厂商的格式不一样。OpenAI 的 tool 定义长这样，Anthropic 的 tool_use 长那样。你给 GPT 写的调用代码，搬到 Claude 上基本要重写。
  • 每个应用都得自己造轮子。你想让你的 App 既能查日历、又能读数据库、又能发 Slack，就得为每一个工具写一套对接代码，再为每个模型写一套适配。
  • 工具多了就乱。几百个工具直接塞给模型，模型根本选不准，prompt 也爆。

这就好比：每台设备都有自己的充电口（苹果的 Lightning、老安卓的 Micro-USB、新的 USB-C），你出门得带一堆线。

2. MCP 的回答：统一标准

Anthropic 在 2024 年底开源了 MCP。它的核心主张很简单：

不要把「模型」和「工具」焊死在一起。应该用一套通用的协议，让任何模型都能连上任何符合标准的服务端。

这样一来： - 工具开发者只写一次 MCP Server（比如「文件系统 Server」「GitHub Server」），谁都能用； - 应用开发者只对接一次 MCP 协议，就能接入所有现成的 Server； - 模型厂商只要支持 MCP，就能立刻拥有成千上万种能力。

二、MCP 到底管了什么

MCP 不是「一个具体的工具」，而是一套通信规则。它规定了三件事：

管什么 说明
消息格式 客户端和服务端之间传的 JSON-RPC 2.0 消息长什么样
能力原语 服务端能向模型提供哪几类能力（工具、资源、提示词）
传输方式 消息通过什么通道传（本地标准输入输出 / 远程 HTTP＋SSE）

注意一个常见误解：MCP 不负责「让模型变聪明」，也不负责「执行工具里的逻辑」。它只负责「把模型的请求 reliably 送到正确的地方，并把结果 reliably 送回来」。真正的工具逻辑（比如「查 GitHub」要调 GitHub API），写在 MCP Server 里。

三、一个最小例子，感受一下

假设我们想让模型能「读本地文件」。用 MCP 的思路，大概是这样：

  1. 你启动一个 文件系统 MCP Server（它知道自己能列目录、读文件、写文件）；
  2. 你的 AI 客户端（比如 Claude Desktop）连上这个 Server，问它：「你都会什么？」
  3. Server 回答：「我会 read_file(path)、list_dir(path)……」
  4. 你问模型：「帮我读一下 notes.txt 的第一行」；
  5. 模型判断要调 read_file，返回一个调用请求；
  6. 客户端把这个请求发给文件系统 Server，Server 真的去读文件，把内容返回；
  7. 模型拿到内容，组织成自然语言回答你。

你看到的只是「我问了一句，它答了一句」；背后发生的是一次标准化的协议往返。

四、MCP 和「普通 API」有什么区别

有人会问：我直接写个 HTTP 接口让模型调，不也一样吗？

区别在于标准化和组合：

  • 普通 API：你得自己定义「模型怎么知道这个 API 存在」「参数怎么传」「返回怎么解析」「出错怎么处理」。每个 API 一套。
  • MCP Server：以上全部由协议统一规定。模型用一套统一的「发现能力 → 调用 → 拿结果」流程，就能用上成百上千个 Server，而且这些 Server 可以同时接、组合用。

换句话说，MCP 把「写一个工具」和「让模型用这个工具」两件事彻底解耦了。

五、本章小结

  • 大模型本身碰不到真实世界，MCP 是给它接上外部能力的统一标准（类比 USB-C）；
  • 没有 MCP 时，每个模型、每个应用都得自己造轮子对接工具，混乱且重复；
  • MCP 管的是「通信规则 + 能力原语 + 传输方式」，不管模型聪明与否，也不管工具具体逻辑；
  • 一次 MCP 交互 = 客户端发现能力 → 模型决定调用 → 服务端执行 → 结果回传 → 模型作答；
  • MCP 的价值在于解耦：工具写一次、应用接一次、模型通吃所有。
