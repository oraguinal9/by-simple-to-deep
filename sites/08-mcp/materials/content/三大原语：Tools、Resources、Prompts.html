三大原语：Tools、Resources、Prompts

MCP 把 Server 能向模型提供的能力，分成了三类原语（primitive）。理解这三类的区别，是写好、用好 MCP 的关键。它们分别是：Tools（工具）、Resources（资源）、Prompts（提示词模板）。

一、为什么分三类，而不是「全是工具」

如果所有能力都叫「工具」，模型会分不清：哪些是自己「该主动去调」的，哪些只是「可以拿来看的参考资料」，哪些又是「人类预先写好的标准流程」。

MCP 用三类原语表达这三种不同的语义：

原语 谁触发 模型能不能主动调 典型用途
Tools 模型（自主决定） ✅ 能 执行动作：读文件、调 API、跑命令
Resources 应用/用户（注入上下文） ❌ 不能 提供数据：文件内容、数据库记录
Prompts 用户（主动选） ⚠️ 用户触发，模型套用 复用的工作流模板

一句话：Tools 是「动手」，Resources 是「喂料」，Prompts 是「套路」。

二、Tools（工具）：模型主动调用的动作

Tool 是三类里最常用的。它代表一个有副作用的动作——会真的去执行点什么。

特征

  • 模型自主决定是否调用（根据对话需要）；
  • 有清晰的 name + description + input_schema；
  • 返回结果给模型，模型再组织回答；
  • 通常有副作用（读/写/发/算）。

例子

{
  "name": "query_database",
  "description": "对销售数据库执行一条只读 SQL，返回结果表",
  "input_schema": {
    "type": "object",
    "properties": {
      "sql": {"type": "string", "description": "只读 SELECT 语句"}
    },
    "required": ["sql"]
  }
}

模型看到用户问「上季度销售额最高的产品」，就会主动调 query_database。

设计要点

  • description 要写清「做什么、何时用、参数含义」；
  • 参数用 JSON Schema 约束，减少模型填错；
  • 危险动作（写、删、发）要在 Server 内加权限闸门（见第九章）。

三、Resources（资源）：喂给模型的上下文

Resource 代表一段可被读取的数据，比如一个文件、一条数据库记录、一个网页。它和 Tool 最大的区别是：Resource 是「被拿来看的」，不是「被调来做事的」。

特征

  • 模型一般不主动「调用」Resource；
  • 由 Host / 用户决定「把哪些 Resource 注入到上下文」；
  • 无副作用，纯读取；
  • 常带 URI 标识，如 file:///notes.txt、db://sales/2025。

例子

资源 URI:  file:///project/README.md
内容:      （README 的全文）

当用户问「这个项目是干嘛的」，Host 可以把这个 Resource 的文本内容塞进对话，让模型基于它回答。

和 Tool 的边界

  • 想让模型读取某份资料 → Resource；
  • 想让模型执行某个动作（即使动作是「读取」）→ Tool。

有些 Server 两者都提供：既暴露 read_file 这个 Tool（模型主动读），也暴露 file:// 这个 Resource（Host 预先加载）。具体怎么分，看你的产品交互设计。

四、Prompts（提示词模板）：可复用的「套路」

Prompt 是一段预先写好的提示词模板，用户（或应用）可以主动选它来「套用」。它解决的是「常见任务有标准流程」的需求。

特征

  • 由用户/应用触发，不是模型自己蹦出来的；
  • 本质是「带占位符的提示词」；
  • 帮助用户快速启动一类任务。

例子

一个「代码评审」Prompt 模板：

{
  "name": "code_review",
  "description": "对一段代码做结构化评审",
  "arguments": [
    {"name": "code", "description": "待评审的代码", "required": true}
  ]
}

用户选中它、填入代码，Host 就生成一段「请按以下维度评审这段代码：正确性、可读性、性能……」的提示词发给模型。

价值

  • 把团队沉淀的最佳实践，固化成可复用的模板；
  • 降低用户「不知道怎么问」的门槛；
  • 和 Tool 不同，Prompt 不执行动作，只组织语言。

五、三类怎么配合使用

一个「智能编程助手」Host 可能同时用全三类：

  • Tools：run_tests（跑测试）、edit_file（改文件）——模型主动调；
  • Resources：file://src/main.py（把源码作为上下文注入）——Host 预先加载；
  • Prompts：code_review（评审套路）、write_tests（补测试套路）——用户主动选。

三者在一次对话里各司其职，模型负责「动手」那部分，人和应用负责「喂料」和「选套路」。

六、常见误区

误区 正解
什么都做成 Tool 纯数据用 Resource，固定流程用 Prompt
Resource 也能被模型调 Resource 由 Host/用户注入，模型不主动调
Prompt 会自己执行 Prompt 只生成提示词，不做事
三类越多越好 多了模型反而选不准，按需暴露

七、本章小结

  • MCP 三类原语：Tools（动手，模型主动调）/ Resources（喂料，Host 注入）/ Prompts（套路，用户选）；
  • Tool 有副作用、模型自主调；Resource 纯读取、做上下文；Prompt 是模板、复用流程；
  • 三者配合：Tool 干活、Resource 供料、Prompt 定式；
  • 设计原则：按语义选对原语，别全堆成 Tool；按需暴露，避免模型选择过载。
