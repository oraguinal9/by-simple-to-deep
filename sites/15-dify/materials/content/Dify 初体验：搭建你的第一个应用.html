Dify 初体验：搭建你的第一个应用

上一章你理解了「AI 应用开发平台」是什么。这一章我们动真格的：把 Dify 跑起来，5 分钟搭出你的第一个聊天应用。

Dify 是什么

Dify 是一个开源的 LLM 应用开发平台，它的官方定位是「让开发者（甚至非开发者）用可视化的方式快速构建 AI 应用」。它把「模型接入、提示词、知识库、工作流、Agent、发布」全部产品化。

几个关键特性： - 开源：代码在 GitHub 上，可以自己部署（私有化、数据可控）； - 可视化：拖拽配置，不用写前端后端； - 全功能：聊天助手、工作流、Agent、知识库、工具、发布全都有； - 模型中立：支持 OpenAI、Claude、国产模型（通义、智谱、DeepSeek）、本地模型（Ollama）等。

两种使用方式

方式一：官方云服务（最快）

去 Dify 官网注册账号，直接在线用。适合体验和学习，免费额度有限。

方式二：本地部署（Docker，推荐学习）

Dify 提供 Docker Compose 一键部署，几分钟就能在本地跑起来：

git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
docker compose up -d

启动后浏览器访问 http://localhost，按引导创建管理员账号即可。

本地部署的好处：数据在自己电脑、模型可以接本地 Ollama、随便折腾不怕花钱。

接入你的第一个模型

Dify 本身不提供模型，需要你接入。这一步在「设置 → 模型供应商」里完成：

  • API Key 方式：填入 OpenAI / DeepSeek / 通义等厂商的 API Key，即可使用云端模型；
  • 本地模型方式：如果你的电脑装了 Ollama（L10 讲过），选「Ollama」供应商，填本地模型名，Dify 就能调用它——免费、离线、隐私。

对学习来说，推荐接一个便宜的云端模型（比如 DeepSeek）或本地 Ollama 模型，两条路都体验一遍。

创建第一个应用：聊天助手

模型接好后，开始建应用：

1. 首页点「创建空白应用」
2. 选「聊天助手」类型
3. 起个名字，比如「我的第一个助手」
4. 进入编排界面

Dify 的应用类型主要有：

类型 用途
聊天助手 多轮对话，最常用
文本生成 单次输入输出，适合总结、写作
工作流 可视化流程编排（下一章讲）
Agent 能调用工具的智能体

编排界面：写你的第一个提示词

进入编排界面后，核心是系统提示词（System Prompt）。它定义了这个助手「是谁、怎么说话」。

你是一个乐于助人的中文助手。回答要简洁、准确、友好。

右侧有模型选择器：模型、温度、max tokens 等参数都可以调。

「预览」对话框在右侧，直接输入问题试跑：

用户：你好，你是谁？
助手：你好！我是一个乐于助人的中文助手，有什么可以帮你？

这就是你的第一个 AI 应用——虽然简单，但整条链路（模型接入 → 应用创建 → 提示词 → 试跑）已经打通。

调试与迭代：平台的核心优势

现在体验平台最大的价值——快迭代：

  1. 把系统提示词改成「你是一个暴躁的客服」；
  2. 再问一次同样的问题；
  3. 看回答风格立刻变化。

改提示词 → 立即试 → 看效果，这个循环在平台里只要几秒钟。这就是为什么说平台能把「懂提示词的人」的生产力放大 10 倍——你可以疯狂试验不同写法，直到找到最好的。

几个实用小技巧

  • 多版本管理：Dify 支持保存多个「提示词版本」，改坏了能回滚；
  • 变量：可以加变量（如用户姓名），在提示词里用 {{name}} 引用，让回答个性化；
  • 停止条件：设置「停止词」，防止模型啰嗦地一直说；
  • 对话开场白：设置欢迎语，用户一进来就有引导。

常见问题

Q：模型接好了但试跑报错？ A：多半是 API Key 无效、余额不足，或网络问题。检查「设置 → 模型供应商」里的状态。

Q：Docker 启动失败？ A：先看 docker compose logs，常见是端口被占或内存不足。Dify 官方要求至少 4GB 内存。

Q：本地 Ollama 模型调用慢？ A：小模型（如 qwen2.5:3b）很快，大模型（7B+）在无 GPU 的机器上会慢，属正常。

Q：免费额度用完了？ A：云服务有免费额度限制。学习推荐本地部署 + Ollama，彻底不花钱。

编排界面的完整导览

第一次打开编排界面，别被一堆按钮吓到，其实就几块区域：

区域 作用
左侧（提示词） 写系统提示词、配置变量
中间（预览对话框） 试跑应用、看回答
右侧（模型与功能） 选模型、调参数、开功能（对话开场白等）
顶部（发布/保存） 保存草稿、发布版本

建议：花 10 分钟把每个区域都点一遍，搞清楚每个开关是干嘛的——磨刀不误砍柴工。

应用类型怎么选（进阶认知）

第 2 章的「聊天助手」只是开始。选错应用类型会事倍功半，给一个选择指南：

  • 聊天助手：多轮对话场景，模型自由发挥为主；
  • 文本生成：单次输入→输出（总结、翻译、写作），没有多轮记忆负担，更省 token；
  • 工作流：流程固定、需要可控性的场景（客服分类、审核流水线）；
  • Agent：需要「临场决定调用什么工具」的场景（查询助手、研究助手）。

判断口诀：要对话 → 聊天助手；要一次转换 → 文本生成；要固定流程 → 工作流；要自由干活 → Agent。后面几章会逐个深入。

小练习

  1. 部署 Dify（云服务或 Docker 二选一），接入一个模型。
  2. 创建一个「聊天助手」，写一个 3 句话的系统提示词，试跑 3 个不同问题。
  3. 把系统提示词改成完全不同的风格，对比回答差异，感受「提示词决定行为」。
  4. 进阶：给应用加一个「用户姓名」变量，让回答带上名字。
  5. 进阶：分别创建一个「聊天助手」和「文本生成」，对比同一输入下两者的交互差异。
