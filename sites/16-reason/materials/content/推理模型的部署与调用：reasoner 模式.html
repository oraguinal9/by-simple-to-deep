推理模型的部署与调用：reasoner 模式

会看、会选还不够，这一章讲怎么真正用上推理模型：API 怎么调、本地怎么部署、思考过程怎么处理、和普通模型怎么切换。结合 L10（本地部署）和 L15（Dify）的知识，一次讲透。

用推理模型的三种方式

方式一：云端 API（最省事）

各大厂商都提供了「推理模型」的 API：

  • DeepSeek：deepseek-reasoner（R1 系列）；
  • OpenAI：o1 / o3 / gpt-5 系列（reasoning effort 可调）；
  • 国内厂商：通义 QwQ、Kimi K2、智谱 GLM 等都有对应模型。

特点：开箱即用、无需硬件、按 token 计费（推理模型通常比普通模型贵）。

调用示例（DeepSeek reasoner）：

from openai import OpenAI

client = OpenAI(
    api_key="your-key",
    base_url="https://api.deepseek.com"
)

resp = client.chat.completions.create(
    model="deepseek-reasoner",
    messages=[{"role": "user", "content": "17×23+45 等于多少？"}]
)
print(resp.choices[0].message.content)  # 最终答案
print(resp.choices[0].message.reasoning_content)  # 思考过程（reasoner 特有）

注意：reasoner 类模型一般不支持 temperature 等采样参数（思考过程需要确定性采样）——传了会报错。

方式二：本地部署（Ollama / vLLM）

想免费、离线、隐私，用 L10 的方法部署开源推理模型：

# Ollama 一行拉取运行 R1 蒸馏小模型
ollama run deepseek-r1:7b

推荐模型（本地可跑）： - deepseek-r1:1.5b / 7b / 8b：蒸馏小模型，普通电脑能跑； - qwen3:8b 等带思考模式的模型。

特点：免费但吃硬件，7B 级推理模型无 GPU 会明显慢（思考过程长）。

方式三：接入平台（Dify 等）

L15 讲过 Dify——直接在里面接入推理模型供应商（DeepSeek reasoner / Ollama 本地模型），应用即可按节点选择「推理模型」。适合把推理能力放进工作流/Agent（比如让 Agent 的复杂决策节点用推理模型）。

思考过程：要不要展示给用户

推理模型的输出有两部分：思考过程 + 最终答案。怎么处理？

场景 建议
数学/代码解题工具 展示思考过程（可信、可检查）
客服/问答 不展示（用户要答案不是要草稿）
教育场景 展示（教解题思路）
Agent 内部调用 不展示给终端用户，仅日志记录

工程要点：reasoner API 的思考过程通常单独字段返回（如 reasoning_content），最终答案在 content——展示时两者要分离，别把思考过程当答案发出去。

推理模型 vs 普通模型：怎么切换

一个成熟的系统往往两种都要，按任务路由（参考第 1 章的场景表）：

简单任务（闲聊/翻译/常识） → 普通模型（快、便宜）
复杂任务（数学/代码/规划） → 推理模型（慢、准）

实现方式： - 代码里：判断任务复杂度，动态选择 model； - Dify 里：工作流条件分支，按分类路由到不同模型节点（L15 讲过）； - 成本上：推理模型只处理「值得」的问题，大部分流量走普通模型——这是控制成本的关键架构。

推理模型的工程陷阱

坑 1：把温度传给 reasoner 模型 reasoner 不支持采样参数，传了直接 400 报错。用 SDK 时注意模型类型分支处理。

坑 2：max_tokens 设太短 推理模型要输出思考过程 + 答案，默认 token 上限不够时会被截断——答案还没出来就断了。reasoner 通常要设较大的 max_tokens（几千）。

坑 3：把思考过程误当答案 reasoner 的 content 是最终答案，思考过程在单独字段。解析时取错字段会把「草稿」发给用户。

坑 4：超时设置太短 推理模型慢（可能 20~60 秒），前端/网关超时设太短会导致「明明在思考却报超时」。合理设超时 + 用流式输出提升体验。

坑 5：本地小模型「推理不动」 1.5B 的蒸馏模型能力有限，复杂题可能「假思考」后还是错。本地体验建议至少 7B 级别。

一个完整接入示例：智能解题助手

串联本章知识，做一个「智能解题助手」的 API 接入：

def solve(question):
    """简单题走普通模型，难题走推理模型"""
    # 1. 先简单判断复杂度（关键词/长度）
    if is_simple(question):
        model = "deepseek-chat"          # 普通模型
    else:
        model = "deepseek-reasoner"      # 推理模型
    # 2. 调用
    resp = call_llm(model, question)
    # 3. 返回（推理模型拆开思考与答案）
    if model.endswith("reasoner"):
        return {"answer": resp.content, "thinking": resp.reasoning_content}
    return {"answer": resp.content}

这个「简单/复杂分流」就是生产系统的标准姿势。
