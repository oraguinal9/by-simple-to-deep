实战路线：用推理模型解决复杂问题

最后一章，把这一阶段（以及前面 15 阶）的知识串起来，完整做一个「用推理模型解决复杂问题」的实战项目。我们用「智能数学解题助手」作为贯穿案例——一个推理模型最能发挥价值的场景。

需求定义

场景：做一个面向学生的数学解题助手：拍照/输入题目，AI 给出分步解答，学生能看懂思路。

需求拆解： 1. 各种难度题目都能解（从一元方程到竞赛题）； 2. 给出「清晰的分步推理」，不只是答案； 3. 简单题要快、难题要准（成本可控）； 4. 答错代价高（教错了会误导学生）——准确率优先。

架构设计：三级分流

根据第 7、8 章的取舍原则，设计「按难度分级」的架构：

题目输入
  ↓ 难度判断（关键词/长度/简单启发式，或小模型分类）
  ├─ 简单题 → 普通模型（快、便宜）
  ├─ 中等题 → 推理模型（标准 effort）
  └─ 压轴题 → 推理模型（高 effort + 自洽性多数投票）

设计理由： - 简单题用普通模型：秒回，成本几乎为零，正确率也够； - 难题用推理模型：准确率优先，学生「错不起」； - 压轴题再加自洽性：3 次采样取多数，把准确率再抬一截（用 3 倍成本换，值得）。

实现步骤

第一步：搭模型调用层

封装一个统一接口（第 6 章的代码基础上扩展）：

def solve(question, difficulty):
    if difficulty == "easy":
        model = "deepseek-chat"           # 普通模型
        return call(model, question)
    elif difficulty == "medium":
        model = "deepseek-reasoner"       # 推理模型
        r = call(model, question)
        return {"answer": r.content, "thinking": r.reasoning_content}
    else:  # hard
        # 自洽性：3 次采样取多数答案
        answers = [call("deepseek-reasoner", question).content for _ in range(3)]
        return majority_vote(answers)

第二步：难度判断

简单启发式 + 小模型分类结合：

def judge_difficulty(q):
    # 关键词：出现「竞赛、证明、综合」→ hard
    for kw in ["竞赛", "证明", "综合"]:
        if kw in q: return "hard"
    # 长度/算子数量粗判
    if len(q) < 40 and q.count("+") + q.count("×") <= 2: return "easy"
    return "medium"

进阶：用一个小分类模型判断（准确率高），或收集用户反馈动态调整。

第三步：思考过程的呈现

  • medium/hard 题：把 thinking 做成可折叠的「思维过程」展示（学生可以看思路）；
  • easy 题：只给答案 + 简单步骤，不展示长篇思考。

展示设计：答案用分步格式（第 1 步/第 2 步…），每步配解释——这本身就是「输出思维链」，让学生学到思路。

第四步：评测与迭代

用第 9 章的方法建评测集：

1. 收集 50 道典型题（简单/中等/难各 15~20 道）
2. 每题人工核验标准答案
3. 跑评测：准确率 + 推理质量人工抽样
4. 发现问题 → 迭代
   · 某类题总错 → 是不是难度判断分错级了？
   · 推理过程晦涩 → 提示词加「步骤要清晰、每步解释原因」
   · 难题还是错 → 提高 effort / 检查是否该上更强的模型

第五步：成本控制

  • 简单题走普通模型：80% 流量成本极低；
  • 中等题推理模型：性价比主力；
  • 压轴题自洽性：贵但量少（大部分用户不刷压轴题）。

按这个设计，整体成本比「全上推理模型」省 60% 以上（第 8 章的账）。

扩展：推理 + 工具 + 知识库

推理模型不是孤岛，可以继续升级：

1. 推理 + 计算工具：数学题让推理模型规划步骤，代码节点/计算器保证计算精确——「思维链 + 工具双保险」（第 3 章讲过）。

2. 推理 + 检索：题目涉及课本概念时，先检索教材知识库（RAG）再推理——「资料 + 思路」都给到模型。

3. 推理 + Agent：复杂应用题需要查单位换算、找公式时，让 Agent 调用工具获取信息再推理（L9 的能力组合）。

4. 推理 + 多模态：拍照解题（图片 OCR 转文字 → 推理模型）——这是这类产品的真实形态。
