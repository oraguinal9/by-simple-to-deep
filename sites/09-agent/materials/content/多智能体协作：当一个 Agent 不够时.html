多智能体协作：当一个 Agent 不够时

单个 Agent 再强也有天花板：让它既当研究员又当程序员还当审稿人，结果常常「样样通、样样松」。现实里的聪明做法是让多个 Agent 各司其职，像团队一样协作——这就是多智能体（Multi-Agent）系统。

为什么要多个 Agent

想想一个真实团队为什么分工：

  1. 角色专注：研究员专心搜资料，不会写代码；程序员专心写代码，不被资料淹没。
  2. 上下文隔离：每个 Agent 的上下文窗口只装自己领域的内容，不会被其他领域的噪声挤爆。
  3. 质量把关：写完的东西有人审，错误在内部就被拦下。
  4. 并行加速：互不依赖的任务同时跑，比单 Agent 串行快得多。

一个经典例子：研究→写作→审查 流水线

用「写一篇 AI Agent 市场分析报告」来演示多智能体协作：

          ┌─────────┐      ┌─────────┐      ┌─────────┐      ┌─────────┐
用户 ───> │ 研究员   │ ──> │ 写作者   │ ──> │ 审查员   │ ──> │ 输出    │
          │Researcher│     │Writer    │     │Reviewer  │     │(报告)   │
          └─────────┘      └─────────┘      └─────────┘      └─────────┘
           查资料/摘要       组织成文          挑错/提修改      定稿
  • 研究员（Researcher）：用搜索工具收集 2026 年 AI Agent 市场数据、竞品信息，输出「资料包」。
  • 写作者（Writer）：接收资料包，组织成结构清晰的报告初稿。
  • 审查员（Reviewer）：检查事实错误、逻辑漏洞、格式问题，返回修改意见。
  • 写作者（再循环）：根据意见修改，直到审查通过。

每一棒之间传递的是结构化消息（资料包、草稿、意见），就像团队里的交接文档。

协作的两种组织方式

1. 流水线（Pipeline）：单向接力

上游输出 = 下游输入，顺序执行。适合流程固定的任务（上面的报告流水线就是典型）。优点：结构简单、容易追踪。

2. 黑板模式（Blackboard）/ 广播：多向讨论

多个 Agent 围绕一份共享的「黑板」（公共状态），谁有补充就往上写，互相辩论、迭代方案。适合开放性问题：

【黑板：产品方案 v3】
- 研究员：竞品 A 主打低价，竞品 B 主打生态。
- 产品经理：建议主打「本地私有化部署」差异化。
- 工程师：本地部署在中小客户硬件上跑得动，可行。
- 安全顾问：注意：本地部署后更新渠道要自建。
- 产品经理：好，v4 更新定价策略。

这种模式更像「头脑风暴会议」，能力上限高，但实现复杂、token 消耗大。

多 Agent 之间怎么「说话」

Agent 间的通信方式主要有三种：

方式 说明 适用
直接传参 上游把结果作为下游的输入（函数调用） 流水线
消息队列 通过队列/总线收发消息，可异步解耦 大规模系统
共享状态 读写同一个状态对象（黑板） 协作讨论型

2025 年起，业界还出现了 A2A（Agent-to-Agent）协议，目标是让不同厂商的 Agent 能互操作——就像 HTTP 让不同的网站互联。这是多智能体走向标准化的关键一步。

多智能体的代价（别盲目上）

多 Agent 不是越多越好：

  • 成本暴涨：每个 Agent 都在调大模型，token 花费成倍增加。
  • 错误传播：上游 Agent 的幻觉会顺着流水线放大，审查环节几乎必备。
  • 协调开销：Agent 之间沟通本身就有延迟和歧义。
  • 调试困难：问题出在哪个环节？比单 Agent 难定位得多。

工程建议：先从单 Agent + 好提示词开始，确实忙不过来再拆。拆的时候先从「两个角色」（执行 + 审查）起步，验证有效再逐步加。

主流多智能体框架

  • LangGraph：把 Agent 建成有向图，节点是 Agent/工具，边是流转逻辑——目前工程界事实标准。
  • CrewAI：以「团队（Crew）+ 角色（Agent）+ 任务（Task）」为核心，上手快。
  • AutoGen（微软）：强调多 Agent 对话式协作。
  • OpenClaw / OpenManus：个人助手型，偏「单主控 + 多工具」。

本章小结

  • 多 Agent 的价值：角色专注、上下文隔离、质量把关、并行加速。
  • 经典模式：流水线（单向接力）与黑板（共享讨论）。
  • 通信方式：直接传参 / 消息队列 / 共享状态；A2A 协议推动标准化。
  • 代价：成本、错误传播、协调开销、调试难——先单后多，从「执行+审查」起步。
  • 主流框架：LangGraph、CrewAI、AutoGen 等。
