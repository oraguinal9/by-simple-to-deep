实战路线：从零搭一个能用的 Agent

九章理论讲完了。这一章把它们串成一条可执行的实战路线——照着走，你就能从零搭出一个「能干活」的 Agent。我们不堆概念，只给步骤、取舍和工具选型。

先明确一个原则：从最小可行 Agent 开始

别一上来就上多智能体、接十个工具。业界反复验证的路径是：先做出一个能用 10 分钟搞定的最小闭环，再逐步加东西。 一个最小 Agent 只要三样东西：

  1. 一个大模型 API（DeepSeek、Qwen、GPT、Claude 都行）。
  2. 一个工具（比如天气查询）。
  3. 一个 ReAct 循环（上一章那段 while 循环的完整版）。

跑通它，你就理解了 Agent 的全部精髓。

实战路线图（7 步）

第 1 步：定场景，选「能动手」的任务

不要选「写诗」这种纯生成任务（聊天机器人就够），要选需要调用工具的任务，比如：

  • 日程助手：查日程、创建提醒。
  • 文件整理助手：扫描目录、移动文件（注意权限）。
  • 知识库客服：查文档回答问题（配合第 8 章 RAG）。
  • 订票/比价助手：查价格、给方案（先不自动下单，安全第一）。

判断标准：这个任务不用工具就做不了，Agent 才有存在意义。

第 2 步：选框架（或裸写）

方案 适合谁 说明
裸写（OpenAI/国产 API + requests） 想彻底搞懂原理 自己实现 ReAct 循环，二三百行代码
LangChain 快速原型 工具注册、对话历史、RAG 组件齐全
LangGraph 生产级复杂流程 图结构编排、状态管理、人机确认节点
Dify / Coze 不想写代码 拖拽搭 Agent，适合产品验证

我的建议：想学原理就裸写一遍 ReAct（强烈推荐，一次就通透）；想快点出活用 LangChain 起步，复杂后迁 LangGraph。

第 3 步：写系统提示（第 4 章的知识）

把角色、工具守则、禁止编造、危险先确认、输出格式，一条条写清楚。这是零成本、高回报的一步，别偷懒。

第 4 步：注册工具 + 实现调用

# 以 LangChain 风格为例（示意）
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """查询指定城市的实时天气。"""
    # 这里调用真实天气 API，或先返回模拟数据
    return weather_api(city)

tools = [get_weather]
agent = create_agent(model, tools, system_prompt)   # 框架会帮你跑 ReAct 循环

注意：先每个工具单独测通（参数校验、超时、异常返回），再挂进 Agent。工具没测好就上 Agent，问题会被模型「加工」得面目全非，极难排查。

第 5 步：接记忆与 RAG（按需）

  • 需要记住用户偏好？→ 加长期记忆（向量库，见第 5 章）。
  • 需要回答私有知识？→ 加 RAG（第 8 章）：文档切块 → 向量化 → 检索工具。
  • 别一次全加：先跑通，再加。

第 6 步：上安全闸门（第 9 章，必须做）

最小配置三件套：

  1. 危险工具（删除/发送/花钱）默认人工确认。
  2. 工具参数白名单校验（防越界路径、非法参数）。
  3. 全量日志（Thought/Action/结果全记录）。

第 7 步：测试与迭代

用一组「测试用例」反复跑，看它怎么翻车：

  • 信息不足时，它会不会编？
  • 工具调用失败，它会不会重试？
  • 用户意图含糊，它会不会追问？
  • 遇到注入攻击文本，它会不会被带偏？

每发现一个问题，先改系统提示（最便宜），不行再改工具/流程。评估（Evals）是 Agent 开发的日常，不是上线前的一次性动作。

主流开源框架一句话定位

  • LangChain：老牌全能框架，组件多、上手快。
  • LangGraph：图编排，状态与人机确认友好，生产首选。
  • AutoGPT：经典自主 Agent，适合研究「自主性」上限。
  • OpenClaw / OpenManus：个人助手型 Agent，开箱即用，2026 年现象级项目。
  • Dify / n8n / Coze：低代码平台，拖拽搭 Agent，验证想法最快。
  • CrewAI：多智能体团队模式，角色分工直观。

最后的鼓励

Agent 开发最大的门槛不是技术，而是「想清楚任务边界 + 耐心迭代」。你的第一个 Agent 会很笨——很正常。跑通最小闭环，然后让它一点点变聪明，这条路每一小步都有反馈，也正是最迷人的地方。

去动手吧。🛠️
