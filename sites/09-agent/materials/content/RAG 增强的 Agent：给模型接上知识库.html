RAG 增强的 Agent：给模型接上知识库

大模型的知识停留在「训练时那一刻」，之后发生的事它一概不知；而且它还会一本正经地编造细节（幻觉）。怎么办？把知识库接给它——这就是 RAG（Retrieval-Augmented Generation，检索增强生成）。在 L4 我们已经系统学过 RAG，这一章重点看它和 Agent 怎么结合。

先快速复习 RAG 三步

  1. 离线准备：把文档切成小块，转成向量，存进向量数据库。
  2. 检索（Retrieval）：用户提问时，把问题转成向量，在库里找出最相关的几段。
  3. 生成（Generation）：把检索到的段落和问题一起发给大模型，让它基于这些材料回答。
用户问 ──> 问题转向量 ──> 向量库检索 Top-K ──> 拼进上下文 ──> 大模型 ──> 有据可依的回答

RAG 和 Agent 的三种结合方式

方式一：检索是 Agent 的「工具」之一（最常用）

把「知识库检索」本身注册成工具，Agent 按需调用：

{
  "name": "search_knowledge_base",
  "description": "在公司的知识库中检索相关资料，回答产品、政策、流程类问题时优先使用",
  "parameters": {
    "query": { "type": "string", "description": "检索关键词或问题" }
  }
}

Agent 的 ReAct 循环会自己决定「这个问题要不要先查知识库」：

Thought: 用户问年假政策，这是公司政策问题，应该查知识库而不是凭记忆。
Action: search_knowledge_base[年假 计算规则]
Observation: 返回 3 段相关资料……
Thought: 有了依据，可以回答了。
Final Answer: 按公司制度，年假按入职年限折算……

关键区别：RAG 的「检索 → 生成」是固定流水线；而在 Agent 里，检索是一个可选的、由模型自主决定的动作——它可能先查知识库，再查网页，再决定怎么答，全流程自己编排。

方式二：工具返回的内容再喂给「读文档 Agent」

当知识库很大时，一个 Agent 装不下所有材料。常见做法：检索 Agent 负责找材料、做摘要，把浓缩后的「资料包」传给下游写作者（多智能体 + RAG 结合，见上一章的例子）。

方式三：Agent 先问问题，再检索（Query Rewriting）

用户问得含糊时，Agent 先自己「改写」成几个清晰的检索问题，再逐个查：

用户：帮我看看今年咱们的收益情况怎么样？
Agent 改写检索问题：
  ① 公司 2026 年上半年营收与利润
  ② 与去年同期对比
  ③ 主要业务线的表现
→ 分别检索 → 汇总成回答

一个知识库型 Agent 的完整流程

以「企业客服 Agent」为例：

用户: 我上个月的项目报销还没到账，怎么回事？
        │
        ▼
┌────────────────────────────────────────────────────┐
│ 1. 意图识别：涉及「报销流程」→ 属于知识库可答问题     │
│ 2. 检索：查报销流程文档、到账周期、常见问题           │
│ 3. 若信息不足：调用 get_order(工单号) 查真实状态      │
│ 4. 综合回答 + 给出下一步（如补材料入口）              │
│ 5. 超出权限/无法解决 → 转人工（发给客服 Agent）       │
└────────────────────────────────────────────────────┘

注意第 3 步：知识库查不到时，Agent 会「升级」去查真实业务系统——RAG 给的是「常识/制度」，工具给的是「实时状态」，两者配合才完整。

RAG 增强 Agent 的工程要点

  1. 优先检索：系统提示里写「凡是公司内部制度、产品参数类问题，先查知识库再回答」。
  2. 检索要有「触发词」：给知识库工具写清楚的 description，模型才知道什么时候该用它。
  3. 标注可信度：检索结果带上来源和日期，Agent 回答时可以说「根据公司 2026 版制度」。
  4. 检索不到就承认：规定「知识库没有相关内容时，明确告知，不要编造」。
  5. 新鲜度管理：知识库要定期更新；过期文档的日期要标出来，避免 Agent 用旧政策答新问题。

RAG vs 微调：什么时候用哪个

很多初学者纠结 RAG 和微调（L5 学的）怎么选，一句话：

RAG 微调
本质 外接知识，运行时检索注入 改模型参数，把知识「背进」模型
更新 换文档就行，秒级更新 重新训练，成本高周期长
幻觉 有据可依，显著降低 仍可能编造
适合 事实类、常变化的私有知识 风格、格式、专业能力（如按公司格式写报告）

现实中最常见组合：RAG 管「知识」，微调管「技能」。 Agent 主要靠 RAG 获取事实，微调通常不是第一步。

本章小结

  • RAG = 检索 + 生成，让模型「开卷考试」，是解决幻觉和知识过时的核心手段。
  • 三种结合方式：检索当工具（最常用）、检索 Agent 给下游喂资料、Agent 改写问题再检索。
  • 知识库 Agent 的典型流程：意图识别 → 检索 → 必要时调业务工具 → 综合回答 → 转人工。
  • 工程要点：优先检索、触发词清楚、标注来源、查不到就承认、注意新鲜度。
  • RAG 管知识、微调管技能，Agent 先用 RAG 解决「知道」，再考虑微调解决「会做」。
