第七章 什么是 Agent：会自己用工具的 AI

前面六章，我们讲完了一条主线：RAG——让模型"有知识"。模型能查资料、答得准。

但"有知识"还不够。现实里很多任务，光靠"回答"解决不了：

  • "帮我查下今天北京的天气，再订一件和气温匹配的薄外套"——这得查天气、再下单，不是一句话能答完的；
  • "把上个月销售数据拉出来，算同比，做成图表发我邮箱"——要连数据库、计算、生成文件、发邮件一连串动作。

这种"要动手做事"的任务，主角就变成了 Agent（智能体）。本章我们先建立 Agent 的整体概念，后面两章再拆它的核心机制。

一、从 Chat 到 Agent：被动回答 vs 主动行动

普通对话模型像顾问：你问，它答，答完就停。它不碰任何外部系统，不产生任何真实世界的动作。

Agent 像助理/秘书：你给一个目标，它自己想步骤、调工具、看结果、再想下一步，直到把事办成。区别在于——

普通 Chat Agent
角色 顾问（只说） 助理（说+做）
是否调用外部工具 否 是（搜索/API/代码/DB…）
是否多步 单轮 多轮循环
能否影响现实 不能 能（发邮件、下单、改数据）

一句话：Chat 是"动嘴"，Agent 是"动嘴+动手"。

二、什么是 Agent：四个能力的闭环

一个 Agent 通常包含四个能力，形成一个循环：

   感知（拿到任务/环境信息）
        ↓
   思考（该用哪个工具、下一步做什么）
        ↓
   行动（调用工具，产生结果）
        ↓
   观察（读取工具返回的结果）
        ↓
      （回到思考，直到任务完成）

打比方：你让助理"订明天去上海的高铁"。助理会： 1. 思考：先查车次 → 需要"购票网站/API"这个工具； 2. 行动：调用工具查明天车次； 3. 观察：拿到一串车次和时间； 4. 思考：挑一班 → 再调用"下单"工具； 5. 行动+观察：下单成功，拿到订单号； 6. 回报你"已订 G1234，订单号 xxx"。

整个过程模型自己"想一步、做一步、看一步"，而不是你把所有步骤都写死。

三、工具（Tool）：Agent 的"手和脚"

Agent 之所以能"做事"，是因为它有一组工具。工具就是模型可以调用的一个具体能力，本质是一个函数：输入参数，输出结果。常见工具：

  • 搜索：联网搜最新信息（弥补模型知识截止）；
  • 计算：跑一段代码做精确运算（模型心算易错，让它调计算器/Python 更稳）；
  • 查数据库 / 知识库：本质是上一章的 RAG，可以作为 Agent 的一个工具；
  • 调用 API：查天气、查股价、发短信、下单；
  • 操作文件/系统：读文档、写表格、发邮件。

关键认知：模型自己不会"上网"也不会"算账"，它只是决定"现在该调哪个工具、传什么参数"，真正的动作由工具完成。 模型是"大脑"，工具是"手脚"。

一个常见且强大的组合：Agent 把 RAG 当作其中一个工具。当 Agent 遇到"需要查私有知识"时，就调用 RAG 工具去检索，再把结果用于后续决策。RAG 和 Agent 不是二选一，而是经常搭档。

四、Agent 为什么有用：三类它擅长的任务

  1. 需要实时/私有信息：模型训练数据有截止，但"今天天气""你们的库存"它不知道，必须靠工具现查。
  2. 需要多步拆解：任务天然是一连串动作（查→算→生成→发送），单轮回答搞不定。
  3. 需要操作现实系统：发邮件、改数据库、触发工作流——这些必须调用工具。

反过来，纯知识问答、创意写作，用普通 Chat 或 RAG 就够了，不一定需要 Agent。别为了用 Agent 而用 Agent——能简单解决的，就别上复杂系统。

五、Agent 的"自主"带来的新风险

Agent 能动手，也就有了"闯祸"的可能。这是它和普通 Chat 最大的不同，也最需要警惕：

  • 误操作：让 Agent 发邮件，它可能发错人、发错内容；
  • 无限循环：思考-行动卡在某个步骤反复横跳，耗资源不结束；
  • 被诱导：外部网页/资料里的一句话，可能诱使 Agent 执行危险操作（类似 RAG 里的提示注入，但后果更严重，因为它真能"动手"）。

所以实际系统里，Agent 通常要配： - 权限边界（能调哪些工具、能不能真发送）； - 人类确认（高风险动作先问人）； - 步数/预算上限（防止死循环烧钱）。

六、一个最小心智模型

把 Agent 记成这句话就够了：

Agent = 大模型（大脑） + 一批工具（手脚） + 一个"思考→行动→观察"的循环（做事的方法）。

它拿到目标后，自己决定调哪些工具、按什么顺序，直到把事办成。RAG 是让它"有知识"的利器，也常作为它的一个工具。

七、本章小结

  • 普通 Chat 是"顾问"（只答），Agent 是"助理"（答+做）。
  • Agent = 感知→思考→行动→观察 的闭环循环，直到任务完成。
  • 工具（Tool） 是 Agent 的手脚：搜索、计算、查库、调 API、操作文件。模型只决定"调哪个、传什么参"，动作由工具执行。
  • Agent 擅长：实时/私有信息、多步任务、操作现实系统；简单问答未必需要它。
  • RAG 常作为 Agent 的一个工具，二者搭档而非对立。
  • Agent 能"动手"也带来误操作/循环/被诱导风险，需配权限、确认、预算上限。
