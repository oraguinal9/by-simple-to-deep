第三章 把文字变成向量：Embedding 入门

上一章我们把资料切成了小块。现在问题来了：用户问一句话，模型怎么判断"哪块资料和这句话意思最相关"？

如果靠"有没有共同的关键词"，会遇到尴尬：用户问"猫主子掉毛咋办"，资料里写的是"宠物脱毛的护理方法"——字面完全不同，意思却一样。纯关键词匹配会认为"不相关"，直接漏掉正确答案。

RAG 要的是按意思找，而不是按字面找。这就要请出本章的主角：Embedding（嵌入 / 向量化）。

一、什么是 Embedding：给文字发一张"语义坐标卡"

Embedding 做的事，可以一句话概括：

把一段文字，变成一串有顺序的数字（向量），让"意思相近的文字，数字也相近"。

比如：

  • "猫主子掉毛" → [0.21, -0.83, 0.55, ...]（假设 8 个数字）
  • "宠物脱毛护理" → [0.19, -0.80, 0.52, ...]

你会发现，这两句话的向量长得几乎一样——因为它们的意思一样。而"今天股市大涨"会变成一串完全不同的数字。

这串数字，就是文字的"语义坐标"。Embedding 模型（比如 OpenAI 的 text-embedding、阿里的 bge、智谱的 embedding 等）就是干这个映射的"翻译官"。

二、一个生活类比：把"意思"画到地图上

想象一张巨大的"语义地图"：

  • 地图上每个点代表一个意思；
  • "猫"和"狗"离得近（都是宠物），"猫"和"火箭"离得远；
  • "高兴"和"开心"几乎重叠，"高兴"和"悲伤"在地图两端。

Embedding 就是把文字"定位"到这张地图的某个坐标上。所谓"向量"，其实就是这个坐标的一串数字写法（比如三维坐标 (x, y, z) 就是长度为 3 的向量）。

现实里的 Embedding 维度通常是 768、1024 甚至 3072 维——人类画不出这么高维的地图，但计算机算得飞起。你只要记住：维度越高，能表达的语义细节越丰富（代价是存储和计算更贵）。

三���为什么"相近"这么重要

回到 RAG 的检索：

  1. 把知识库里每一块资料都提前 Embedding 成向量，存进向量数据库；
  2. 用户提问时，把问题也 Embedding 成向量；
  3. 在向量数据库里，找和"问题向量"距离最近的那几个资料向量——也就是"意思最像"的几块。

注意，第 3 步比的不是"有没有共同字"，而是"坐标近不近"。所以"猫主子掉毛"能正确命中"宠物脱毛护理"，因为它们在语义地图上挨着。

这就是 RAG 能做到"按意思检索"的根本原因。

四、距离怎么算：先有个概念，下章细讲

两个向量"近不近"，数学上用一个叫余弦相似度（cosine similarity） 的量来衡量：

  • 值越接近 1：意思越像；
  • 值接近 0：八竿子打不着；
  • 值接近 -1：意思相反（比如"好"和"坏"）。

本章你只要建立直觉：Embedding 把文字变成坐标，相似度衡量坐标近不近。下一章我们会亲手算一遍余弦相似度，并讲向量数据库怎么高效找"最近的邻居"。

五、几个常见误区

误区 1：Embedding 是"把文字编码成密文"。 不是。它不是为了保密，是为了让计算机能用"距离"来衡量语义关系。同一句话的 Embedding 是确定的（同一模型下），不是随机加密。

误区 2：Embedding 能"读懂"文字。 Embedding 模型只是学到了"哪些文字经常出现在相似语境"，从而把相似文字映射到相近坐标。它并不真正"理解"，但足够让检索变聪明。

误区 3：不同模型的 Embedding 能混用。 不能。用模型 A 生成的向量，必须和模型 A 生成的"问题向量"比。换模型就得全部重新 Embedding（重嵌）。所以选好一个 embedding 模型后，知识库和查询要始终用同一个。

六、 practical 建议（新手向）

  • 选模型：中文场景优先考虑在中文语料上训练过的模型（如 bge-large-zh、m3e、智谱/通义系列 embedding），效果优于直接拿英文模型硬套中文。
  • 切块和 Embedding 要配套：先切块（第二章），再对每块做 Embedding；查询时也整句 Embedding，保持粒度一致。
  • 维度不是越大越好：768 维对绝大多数业务足够，盲目上 3072 维只会让存储和检索变慢。

七、本章小结

  • RAG 要"按意思找资料"，纯关键词匹配会被同义改写坑掉。
  • Embedding = 把文字变成一串数字（向量），意思相近 → 向量相近。
  • 可以想象成"语义地图"：语义相近的文字，在地图上坐标挨得近；维度越高表达越细。
  • 检索时把"问题"和"资料"都变向量，找距离最近的资料块。
  • 衡量"近不近"用余弦相似度（接近 1 像、接近 0 无关），下章细算。
  • 注意：Embedding 不是加密、不是真理解；不同模型的向量不能混比。
