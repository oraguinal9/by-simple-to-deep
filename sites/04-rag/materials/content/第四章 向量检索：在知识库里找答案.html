第四章 向量检索：在知识库里找答案

上一章我们把文字变成了向量（语义坐标），并提到"找离问题最近的几块资料"。本章就把这步拆开讲透：距离到底怎么算、数据库怎么高效找、找出几个才合适。

一、余弦相似度：两个向量的"方向"有多像

我们说过用余弦相似度（cosine similarity） 衡量两个向量近不近。它的直觉很形象：

把两个向量看成从原点出发的箭头。夹角越小（越指向同一方向），它们越相似；夹角 90° 完全不相关；反向则相反。

公式长这样（不用背，理解即可）：

cosine(A, B) = (A·B) / (|A| × |B|)
  • A·B 是点积：对应位置数字相乘再求和；
  • |A|、|B| 是向量的长度（模）：各数字平方求和再开方；
  • 结果范围 [-1, 1]，越接近 1 越像。

举个 2 维的小例子

设： - A = (3, 4)，B = (6, 8)（B 其实就是 A 放大 2 倍，方向完全一致） - 点积 A·B = 3×6 + 4×8 = 18 + 32 = 50 - |A| = √(3²+4²) = 5，|B| = √(6²+8²) = 10 - cosine = 50 / (5×10) = 50/50 = 1.0 ← 完全相似 ✅

再设 C = (3, -4)（和 A 关于 x 轴对称，方向相反）： - 点积 A·C = 3×3 + 4×(−4) = 9 − 16 = −7 - |C| = 5 - cosine = −7 / (5×5) = −0.28 ← 意思相反 ❌

看，余弦相似度不看"向量长短"（放大多少倍无所谓），只看方向——这恰好符合我们的需求：我们关心"意思像不像"，不关心"这句话写得多长"。

二、从"算相似度"到"检索"

RAG 的检索步骤现在是清晰的：

  1. 知识库每块资料早已 Embedding 成向量，存好；
  2. 用户问题也 Embedding 成向量 Q；
  3. 拿 Q 和每一块资料的向量算余弦相似度；
  4. 按相似度从高到低排序，取最前面的 k 个（这就是 top-k）；
  5. 这 k 块就是"和问题最相关的资料"，送去拼提示词。

流程上就一句话：算一遍相似度 → 排序 → 取前 k。

三、top-k：取几个才合适

k 是 RAG 里最该调的参数之一：

k 太小 k 太大
可能漏掉关键资料（没召回） 塞进无关资料，模型被噪声干扰
上下文不足，答得单薄 占满窗口，真正相关的被稀释

常见起步值 k = 3~5。判断标准很朴素：观察模型回答时，你给的那几块里，是不是"该有的都在、不该有的没来"。

一个小技巧叫 召回率（recall）思维：你可以拿一批真实问题，人工标出"标准答案应该引用哪几块"，再看系统 top-k 里有没有覆盖到——覆盖率就是召回率。调 k 直到覆盖得让人满意。

四、为什么需要"向量数据库"，而不是直接遍历

你可能会想：不就是"拿问题向量和每块算一遍余弦"吗？for 循环遍历不就行了？

能，但慢。问题在规模：

  • 当资料有 10 万、100 万块时，每次提问都要算 100 万次余弦，延迟高、成本高。
  • 而且 Embedding 通常是 768 维，高维空间里"精确找最近"本身就很贵。

向量数据库（Vector DB） 就是为这事而生的：它用专门的索引结构（常见如 HNSW、IVF）提前把向量组织好，让"找最近的 k 个"从"暴力扫全库"变成"几步跳跃定位"，速度快几十到上百倍。

你不用懂 HNSW 内部怎么跳。只要记住：向量数据库 = 给高维向量建了"快速找邻居"的索引，让 top-k 检索在百万级数据上也能毫秒返回。

常见选择：Milvus、Qdrant、Chroma（轻量本地）、pgvector（直接塞进 PostgreSQL）、以及各云厂商的向量检索服务。

五、精确 vs 近似：一个重要的取舍

向量检索有个关键概念：

  • 精确最近邻（Exact / brute force）：真的和每块都比一遍，结果最准，但慢。
  • 近似最近邻（ANN, Approximate Nearest Neighbor）：用索引"近似"找，极快，但偶尔可能漏掉真正最近的那个（召回率 < 100%）。

实际系统几乎都用 ANN——因为"快且够准"远比"慢且完美"实用。代价是：检索这一步本身可能引入一点点遗漏，所以第六章我们会讲怎么用"重排序"来补救。

六、把检索接回 RAG 主线

到现在，RAG 的前半段已经完整：

提问 → Embedding(问题) → 向量库 top-k 检索 → 拿到最相关的 k 块资料
                                                       ↓
                                          下一章：拼成提示词 → 生成

检索这一步的输出，是一组"带相似度分数的资料块"。分数既是"该用哪些块"的依据，也可以变成可信度参考（比如分数都极低时，说明知识库里可能根本没有答案，这时该老实告诉用户"查不到"，而不是硬编）。

七、本章小结

  • 余弦相似度 = 点积 / (两向量长度之积)，只看"方向"不看"长短"，范围 [-1,1]，越接近 1 越像。
  • 检索流程：问题 Embedding → 和每块算相似度 → 排序 → 取 top-k（常见 k=3~5）。
  • k 太小漏资料、太大塞噪声，按实际召回效果调。
  • 大规模下靠向量数据库的索引（HNSW/IVF）做近似最近邻（ANN） 检索，快且够准。
  • 检索输出"带分数的资料块"，分数可用于判断"知识库里到底有没有答案"。
