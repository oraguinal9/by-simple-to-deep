第十章 动手实践与进阶路线

前面九章，我们把 RAG 与 Agent 的来龙去脉讲透了。最后一章，做两件事：①给你能看懂的最小代码骨架，把抽象流程落到代码层面；②给出全系列进阶路线，告诉你学完本阶后，下一站去哪。

说明：下面代码是教学示意，重点在"结构对不对"，不绑定具体库版本。真要跑，请按你选用的 embedding/向量库/模型 SDK 的当前文档替换细节。

一、最小 RAG：五步骨架

一个能跑的 RAG，核心就五步。下面用伪代码把骨架画出来：

# ---- 第 1 步：准备资料（切块）----
docs = load_pdf("公司手册.pdf")
chunks = chunk_text(docs, size=500, overlap=50)   # 第二章

# ---- 第 2 步：每块变向量，存入向量库 ----
embedder = EmbeddingModel("bge-zh")               # 第三章
vectors = [embedder.encode(c.text) for c in chunks]
vector_db.add(vectors, chunks)                    # 第四章

# ---- 第 3 步：用户提问时，检索 top-k ----
question = "出差打车能报销吗？"
q_vec = embedder.encode(question)
top_chunks = vector_db.search(q_vec, top_k=3)      # 向量检索 + 排序

# ---- 第 4 步：拼装提示词 ----
prompt = f"""
你是严谨的报销助手。只根据【资料】回答，没有就明说"查不到"，禁止编造。
【资料】
{format_with_refs(top_chunks)}    # 每块带 [编号] 和出处  第五章
【问题】{question}
"""

# ---- 第 5 步：生成回答 ----
answer = llm.generate(prompt)
print(answer)

这就是 RAG 的全部骨架。真实工程只是在这五步上做厚：切块更智能、检索加 rerank/混合（第六章）、提示词更严谨（第五章）、评估常态化（第六章）。

二、最小 Agent：ReAct 循环骨架

Agent 的核心是一个"思考-行动-观察"的循环。示意如下：

tools = {
    "get_weather": get_weather_fn,     # 函数说明见第八章
    "search_products": search_products_fn,
}

history = []                           # 短期记忆（第九章）
user_goal = "北京今天适合穿啥？"

for step in range(MAX_STEPS):          # 防死循环：步数上限
    # 把目标 + 历史 + 工具清单 交给模型
    resp = llm.react(goal=user_goal, history=history, tools=tools)
    if resp.has_final_answer:          # 模型判断事办完了
        print(resp.answer); break

    # 模型给出一个 Action（Function Calling）
    action = resp.action               # 如 get_weather(city="北京")
    if action.name not in tools:       # 防幻觉函数名
        history.append("错误：函数不存在"); continue
    obs = tools[action.name](**action.args)   # 程序真正执行
    history.append(Thought=resp.thought, Action=action, Observation=obs)

# 循环结束后，history 里完整记录了"它怎么一步步办成的"

看懂这两段，你就掌握了 RAG 与 Agent 的工程骨架。剩下的都是在这上面"加厚"（更聪明的检索、更稳的工具、更好的规划）。

三、RAG × Agent 联合调试清单

遇到回答不好，按顺序查（融合前两章）：

  1. 资料里有没有答案？（没有就去补库）
  2. 检索召回了吗？ 打印 top-k，看正确答案块在不在、排第几（加 rerank/混合检索）。
  3. 切块合理吗？ 答案被切散？调大小/重叠。
  4. Embedding 适合中文吗？ 换中文优调模型。
  5. 提示词约束了吗？ "只依据资料、没有就说查不到"。
  6. Agent 卡死/循环？ 加步数上限、校验函数名、失败回填。
  7. 工具清单写清了吗？ 每个工具的 description/参数要准确。

五、给动手派的三条建议

  1. 先搭最小可用，再优化。别一上来就上 rerank、混合检索、多 Agent。先把"五步 RAG"和"ReAct 循环"跑通，再按第六章清单逐个加料。
  2. 检索侧优先于生成侧。80% 的问题在检索，先修"找得准"，再纠结"答得美"。
  3. 务必保留日志。把每次的 top-k、Thought/Action/Observation 存下来，这是你调试和向别人解释"它为什么这么干"的唯一依据。

六、本章小结

  • 最小 RAG = 切块 → Embedding → 向量检索 top-k → 拼提示词 → 生成（五步骨架）。
  • 最小 Agent = "思考→行动→观察"的 ReAct 循环 + 工具清单 + 步数上限/函数名校验。
  • 调试按"检索侧优先"的清单逐层排查。
  • 全系列 L1→L8 由简入深：本阶 L4 是"让模型有知识、会做事"的关键一跃。
  • 学习心法：先最小可用、检索优先、留好日志。
