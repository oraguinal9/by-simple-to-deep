第二章 文档切块：怎么把一本书喂给模型

上一章我们说，RAG 的核心是"先查资料，再回答"。但有个前提没解决：你那一大堆资料，模型怎么"翻"？

你不能把整个公司的知识库（几百万字）一次性甩给模型——它装不下，也翻不动。真实做法是：先把资料切成一块一块的小片段，建好索引；等用户提问时，只精准找出最相关的那几块。

这个"切"的动作，行话叫 chunking（切块 / 分块）。本章就讲清楚：为什么要切、怎么切、切多大最合适。

一、为什么必须切块，不能整篇喂

想象你有一本 300 页的员工手册 PDF。两种用法：

  • 不切块：每次提问，都把整本手册贴进提示词。结果：提示词爆仓、检索粒度太粗（只能判断"整本手册"相不相关，无法定位到第 47 页那句关键规定）、而且大部分内容其实和问题无关，反而干扰模型。
  • 切块：把手册切成 500 个段落片段，每个片段单独建索引。提问时只捞出和问题最像的那 3 段。又快又准。

切块的本质，是把"按文档检索"变成"按片段检索"，让检索的颗粒度足够细。

二、切块策略：怎么切才合理

切块不是随便拿刀砍，常见有几种策略，从简单到聪明：

1. 按结构切（最推荐起步）

照着文档原有的层级切：一个 Markdown 标题（#、##）下的一段算一块，或者一个段落（paragraph）算一块。 - 优点：每个块天然语义完整，不会把一句话拦腰斩断。 - 适合：结构清晰的文档（手册、Wiki、Markdown、带标题的 PDF）。

2. 固定长度切（最省事）

不管内容，每隔固定字数（比如 500 字 / 200 个 token）切一刀。 - 优点：实现简单、长度均匀。 - 缺点：容易把一句话、一个表格、一段代码从中间切开，破坏语义。 - 补救：加重叠（overlap）。

3. 语义切（最聪明）

用模型判断"这段话讲的主题变没变"，在主题切换的地方切。比如一段讲"退款流程"、下一段讲"物流时效"，就在交界处切。 - 优点：每块语义高度内聚。 - 缺点：需要额外模型调用，成本高一点。

新手建议：先用"按结构切 + 适度固定长度兜底"，等真正遇到检索质量问题时，再上语义切。

三、重叠（overlap）：别把一句话拦腰斩断

固定长度切最容易出的问题：恰好在一段话中间切开了，前半句在一个块、后半句在另一个块。检索时如果只命中其中一半，模型读到的就是半句残废信息。

解决办法：重叠切分。 比如块长 500 字、重叠 50 字，那么第 2 块的开头 50 字，和第 1 块的结尾 50 字是重复的。这样即便切点落在句子中间，关键信息也会完整出现在某个块里。

打个比方：像两个人接力传话，交接处故意多说一句"刚才那句是……"，确保不断片。

四、切块大小：切多大最合适

这是 RAG 里最常被问的问题，没有标准答案，但有经验区间和权衡：

块太大 块太小
一块里混进太多无关内容，检索不精准 一句话被拆散，语义不完整
单块占满上下文，能检索的块数变少 检索准了，但模型拿到的上下文支离破碎
噪声多，模型被带偏 容易丢失前后的来龙去脉

常见起步值：每块 300–800 字（约 200–500 token），重叠 10%–20%。

更聪明的做法是匹配你的检索器和生成器：如果你发现"检索总差一点点就命中"，就调小块；如果"模型答得支离破碎"，就调大块或加大重叠。

五、别忘了给每块"贴标签"（元数据）

切块时，最好顺手记录每块来自哪里，比如：

{
  "content": "猫咪掉毛严重时……",
  "metadata": {
    "source": "喂养手册.pdf",
    "page": 47,
    "chapter": "第三章 日常护理",
    "type": "doc"
  }
}

这些元数据（metadata） 有三个用处： 1. 回答时能告诉用户"这段来自《喂养手册》第 47 页"，可溯源； 2. 检索时可以按来源过滤（比如只搜"手册"，不搜"聊天记录"）； 3. 排查问题时能快速定位是哪块资料出了问题。

六、一个完整例子

假设你有《公司报销制度.docx》，切成 80 块，每块带"章节 + 页码"元数据。用户问"出差打车能报销吗？"：

  1. 检索器在 80 块里找出最相关的 3 块（分别是"交通报销标准""出差规定""票据要求"）；
  2. 这 3 块连同问题拼成提示词；
  3. 模型基于这 3 块作答，并标注"依据《报销制度》'交通报销标准'章节"。

如果当初没切块、直接整篇塞，模型很可能在几万字里"迷路"，答非所问。

七、本章小结

  • 切块（chunking）是把大文档拆成小片段，让检索从"整篇"精确到"片段"。
  • 三种策略：按结构切（推荐起步）、固定长度切（要加重叠）、语义切（最聪明但贵）。
  • 重叠（overlap） 防止句子被拦腰斩断，是固定长度切的标配。
  • 块大小经验值 300–800 字，重叠 10%–20%，按检索/生成效果反调。
  • 每块记得带元数据（来源、页码），方便溯源与过滤。

八、小练习

  1. 找一篇你手头的长文档（说明书、论文、内部 Wiki），试着手工把它按"标题/段落"切成 10 块左右，体会一下"切在哪最自然"。
  2. 下面哪种情况该调大块、哪种该调小块？
  3. A. 检索经常"差一点命中"正确答案；
  4. B. 模型拿到的资料支离破碎、答得没头没尾。
  5. 为什么重叠切分能减少"半句残废信息"的问题？用自己的话讲一遍。
