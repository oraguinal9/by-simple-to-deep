第一章 什么是 RAG：让大模型"开卷考试"

你有没有遇到过这种情况：问一个 AI 助手"我们公司去年的退款政策是什么"，它却一本正经地编了一段听起来很合理、但其实根本不存在的规定？

这不是模型"坏"，而是因为它的脑子里根本没有你公司的资料。大模型在训练时学的是互联网上的公开文本，它知道"一般来说退款政策长什么样"，但不知道"你们家具体怎么定"。这种"一本正经胡说八道"的现象，行话叫幻觉（hallucination）。

RAG 就是为了解决这个问题而生的。本章我们用一个生活里的比喻，把 RAG 的来龙去脉讲清楚。

一、闭卷考试 vs 开卷考试

把大模型想象成一个学霸。

  • 闭卷考试：考试时什么资料都不让带，全凭平时记忆答题。大模型"原生"就是这样——你问它问题，它只靠训练时记住的东西来回答。遇到它没记过、或记错的细节，就只能"猜"，猜错了就是幻觉。
  • 开卷考试：考试时允许带参考资料，遇到不确定的，先翻书、找到相关段落、再结合题目作答。答得又准又有出处。

RAG 就是给大模型"开卷"的能力。

RAG 是 Retrieval-Augmented Generation 的缩写，翻译过来叫"检索增强生成"。拆开看就是三个字各自的意思：

  • Retrieval（检索）：回答问题前，先从外部知识库里"翻"出相关的资料。
  • Augmented（增强）：把翻到的资料，塞进给模型的提示词里，作为上下文。
  • Generation（生成）：模型结合"问题 + 资料"，生成有根据的回答。

一句话总结：先查资料，再回答。就这么简单。

二、为什么不直接把资料全塞给模型？

你可能会想：那为什么不干脆把公司的全部文档都贴进提示词，让模型一次看完？

两个现实问题：

  1. 装不下。模型的"上下文窗口"是有限的（哪怕现在能装几万字，也不可能为每个问题都塞进几百万字的公司资料库）。
  2. 塞太多会乱。给模型一大坨无关内容，它反而容易答偏，或者把不相关的信息混进来。

RAG 的聪明之处在于按需取用：每次只检索出和当前问题最相关的几段，精准投喂。既省空间，又提准确率。

三、RAG 的完整流程长什么样

把整个过程串起来，其实就四步：

用户提问
   ↓
① 检索：去知识库里找和"问题"最相关的几段资料
   ↓
② 拼装：把"问题 + 找到的资料"拼成一个提示词
   ↓
③ 生成：模型读提示词，基于资料作答
   ↓
④ 回答：把答案返回给用户（最好带上出处）

举个具体例子。你问："我们家猫主子最近掉毛厉害，能不能吃鸡肉？"

如果知识库里存着你家猫的健康档案和喂养手册，RAG 会：

  1. 检索出"猫咪饮食禁忌"和"蛋白质需求"这两段；
  2. 拼成提示词："根据以下资料回答……【资料1：……】【资料2：……】问题：猫能吃鸡肉吗？"；
  3. 模型基于资料给出"可以，鸡肉是优质蛋白，但要注意……"；
  4. 顺手告诉你"以上来自《喂养手册》第 3 章"。

是不是比凭空编靠谱多了？

四、RAG 能解决什么、不能解决什么

RAG 擅长： - 回答"你们家/你们公司特有的"问题（政策、文档、手册、私域知识）； - 需要最新信息的问题（知识库可以随时更新，不用重新训练模型）； - 需要有出处、可追责的回答（医疗、法律、企业合规场景）。

RAG 不擅长 / 要注意： - 资料库里压根没有的答案，它还是答不上来（或退回幻觉）； - 检索这一步如果"找错了资料"，后面生成得再漂亮也是建立在错误基础上——所以检索质量决定了 RAG 的上限； - 它让模型"知道事实"，但不会让模型突然"学会新技能"（那是微调干的事，后面章节会讲）。

五、一个常见的误解

"上了 RAG，模型就永远不会胡说了。"

错。 RAG 大幅降低了幻觉，但不能 100% 消除。原因有三：检索可能漏掉关键资料；模型可能忽略你给的资料而坚持自己的偏见；提示词没写好时，模型会"自作主张"。所以实际系统里，RAG 通常要配合"检索质量优化 + 回答评估"一起用（本书第六章会专门讲）。

六、本章小结

  • 大模型原生是"闭卷"的，只凭训练记忆答题，容易在陌生/私有知识上产生幻觉。
  • RAG = 检索 + 增强 + 生成，核心是"先查资料，再回答"，相当于给模型开卷。
  • RAG 不是把所有资料硬塞给模型，而是每次只检索最相关的几段，精准投喂。
  • RAG 降低幻觉、支持私域/最新/可溯源知识，但检索质量决定上限，且不能彻底消灭幻觉。
