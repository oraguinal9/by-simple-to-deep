模型管理：下载、换装与显存优化

玩到这一步，你的电脑里可能已经有七八个模型、十几个 LoRA 了：放在哪？怎么分类？为什么有时候换了个模型就全乱套？显存到底怎么省？这一篇把「工具房」整理明白，让你的创作环境长期健康运行。

三个主题：模型文件放哪与分类 → 显存优化 → 怎么挑模型（少走弯路）。

一、模型文件放哪：ComfyUI 的「仓库地图」

先记住一个大前提：ComfyUI 并不关心模型文件名是否华丽，它只认「放在哪个目录」。 你把模型放错文件夹，界面上就是找不到、加载报错。下面是 ComfyUI 安装目录里的标准结构：

ComfyUI/
├── models/                 ← 所有模型都在这下面
│   ├── checkpoints/        ← 大模型（引擎），如 SDXL 本体、各类画风模型
│   ├── loras/              ← LoRA 小模型（换风格/角色）
│   ├── vae/                ← VAE 解码器（单独版）
│   ├── controlnet/         ← ControlNet 模型（Canny/Depth/OpenPose 等）
│   ├── upscale_models/     ← 放大模型（ESRGAN 等）
│   ├── clip/               ← 文本编码器相关文件
│   ├── unet/               ← 新版模型的 UNet 部分（SD 3 系列常用）
│   └── motion_modules/     ← AnimateDiff 运动模块
├── output/                 ← 生成的图片默认存这里
├── custom_nodes/           ← 插件节点目录
└── workflows/              ← 工作流文件（建议也存这）

记住一个「放哪」口诀：checkpoint 进 checkpoints，LoRA 进 loras，ControlNet 进 controlnet，放大模型进 upscale_models。 文件名可以用中文也可以用英文，但路径里不要有空格和中文（目录名、盘符路径都要注意），这是 ComfyUI 各种诡异报错的头号来源。

1.1 模型的「换装」逻辑

你已经知道 checkpoint 是三合一套装（模型+CLIP+VAE）。如果你想单独替换其中一部分，该怎么办？比如某个模型自带的 VAE 解码偏灰，你想换一个官方高清 VAE：

  1. 下载 VAE 文件（.safetensors）放进 models/vae/；
  2. 在工作流里加一个 Load VAE 节点；
  3. 把这个节点的 vae 输出，连给 VAE Decode，替代 checkpoint 自带的 VAE。

这就像给汽车换轮胎——不换发动机，只换轮胎。同理，LoRA 是贴纸（不改发动机），ControlNet 是方向盘（外挂控制），放大模型是洗车工（后期处理）。理解了「零件可单独更换」，你就理解了模型管理的精髓。

二、显存不够？七招「省显存攻略」

显存不足（报错里常见 CUDA out of memory）是本地玩 AI 的第一大痛苦。好消息是：省显存的手段很多，效果立竿见影。 从入门到进阶排个序：

第 1 招：用低显存启动参数

启动时给 ComfyUI 加参数，让它主动降低显存占用。最常用的两个：

# 低显存模式：显存不够用时自动把部分数据转移到内存
python main.py --lowvram

# 如果情况更糟，还有一步更省的
python main.py --novram

# 两者叠加也没问题
python main.py --lowvram --novram

代价：速度变慢（因为要来回搬数据）。先用 --lowvram，除非还报错再用 --novram。

第 2 招：用半精度（fp16/bf16）

模型计算默认可能用较高精度，半精度能省一半显存。许多整合包默认已是半精度，你可以在启动参数里显式指定：

python main.py --fp16

苹果电脑（Mac）用 --force-fp16。原理不深究，记住：半精度是省显存性价比最高的一档。

第 3 招：换小模型

SDXL 太吃显存？换 SD 1.5（第 2 篇讲过）。视频模型跑不动？换 AnimateDiff 的低帧数小分辨率。在「同等工作量下选最小模型」是长期策略。

第 4 招：调小分辨率与帧数

把 1024×1024 降到 768×768，把视频 16 帧降到 8 帧，显存占用直接下降。别小看这招——省显存的本质就是「一次算少一点」。

第 5 招：用量化模型

量化是把模型权重「压得更紧凑」的技术，比如把 fp16 压成 int8。量化版模型（文件名常带 fp8、int8、GGUF 等字样）显存占用更小，速度也快，代价是画质略降。进阶玩家常用，新手可先记个名。

第 6 招：别同时开太多东西

浏览器标签页、游戏、剪辑软件都会占显存。跑图前先关掉占显存的程序，是最简单的「免费优化」。

第 7 招：升级硬件 / 租云算力

穷则思变。本地实在跑不动，就租云端算力（按小时计费的显卡租用平台，如 AutoDL），几十块钱能跑很久。先解决问题，再攒钱升级显卡。

方案 难度 省显存效果 速度代价
关后台程序 无 小 无
调小分辨率/帧数 无 中 几乎无
--lowvram / --novram 低 中 中
半精度 fp16 低 大 很小
量化模型 中 大 更快
换小模型 低 大 看情况
云租算力 低 —— ——

三、模型冲突与清理：让工具房整洁

模型越攒越多，会出现两类问题：模型冲突和垃圾堆积。

3.1 模型冲突（最常见翻车现场）

你照着教程抄了一个工作流，加载时报错「模型不存在」或画出来的东西很奇怪，多半是：

  • 版本不匹配：工作流是 SDXL 的，你加载了 SD 1.5 模型（或反过来）——画风和画质全乱。挑 LoRA、ControlNet 时尤其要看适配版本；
  • 同名文件覆盖：两个不同来源的模型被存成同一个文件名，后下的覆盖了先下的——建议下载时给文件加来源或日期前缀；
  • 插件版本不对：工作流用了某个插件节点，你没装或版本旧——用 ComfyUI Manager 统一管理插件更新。

检查口诀：先看模型版本（1.5 / SDXL），再看节点是否齐全，最后看路径是否有中文。 三步走完，80% 的问题能解决。

3.2 清理与备份

  • 定期清理：models 目录按文件大小排序，删掉你确定不再用的模型；output 目录定期归档清理，否则会越堆越多；
  • 重要工作流和模型要备份：工作流 .json 文件很小，建议同步到网盘；模型文件大，至少把「常用套装」记个清单（哪些模型+哪些 LoRA 搭配出什么效果）；
  • 标注习惯：养成「工作流保存时命名清楚、注明用到的模型」的习惯，半年后你会感谢自己。

四、怎么挑模型：少走弯路的四个要点

模型不是越新越好，也不是越热门越好。给你一套「挑模型方法论」：

4.1 看预览图，别只看评分

模型的预览图是「官方示范」，不是「它一定给你这效果」。 挑模型时：

  • 看预览图风格是否合你口味（写实/动漫/国风…）；
  • 看预览图旁边标注的参数（多少步、什么采样器、CFG 多少）——照抄这些参数出图最接近预览效果；
  • 看下载量和评论，人多说明坑少。

4.2 看标签与适配版本

模型页会标注：

  • 适配基座：Base Model: SD 1.5 / SDXL / SD 3.5——这是最重要的一个字段，不匹配就白下；
  • 标签：Character（角色）、Style（风格）、Concept（概念）、Clothing（服装）——决定 LoRA 用途。

4.3 看许可协议（License）

开源模型都有许可协议，大概分两类：

  • 宽松许可（如 SD 1.5、SDXL 官方许可）：允许商用，改动自由；
  • 严格许可：只许个人使用、不许商用、不许修改，或者必须署名。

一句话提醒：个人自娱自乐怎么都行，但要商用（接单、卖图、做产品）前，务必看清许可。 侵权风险是最不值得踩的坑。

4.4 从「复现预览图」开始

拿到新模型，第一步不是自由发挥，而是复现它的预览图：用预览图标注的参数+提示词，跑一张尽量接近的图。跑得越接近，说明环境没问题，然后再开始你自己的创作。这是避免「模型挺好、我用着不行」的最短路径。

五、模型管理实战清单

给你的「工具房」做一个健康检查，照着做一遍：

□ 1. 打开 ComfyUI/models 目录，确认模型都放在正确子目录
□ 2. 路径检查：ComfyUI 安装路径无中文、无空格
□ 3. 显存检查：启动参数是否已加 --lowvram（如需要）
□ 4. 版本检查：主力模型是 SDXL 还是 1.5，LoRA/ControlNet 是否匹配
□ 5. 清理检查：删掉不用的模型，归档 output 旧图
□ 6. 备份检查：重要工作流已命名保存并备份
□ 7. 许可检查：准备商用的模型，确认许可允许

六、模型文件的「格式学问」

下载模型时会看到各种文件名后缀，先认清楚，避免下错文件：

后缀 是什么 说明
.ckpt 老格式 兼容最广，但体积大、加载慢，可能含不安全的旧组件
.safetensors 新安全格式 推荐首选，体积小、加载快、无安全风险
fp16 / bf16 精度标识 半精度，显存占用减半，画质几乎无损
fp8 / int8 / GGUF 量化标识 进一步压缩，更省显存，画质略有下降
pruned 裁剪版 去掉了无用组件，文件更小，直接用即可

下载口诀：优先 .safetensors，显存紧选带 fp16/fp8 的版本。 看到「模型文件有几个 G 下不动」，先看看有没有更小的量化版。

另外提醒下载大文件的技巧：浏览器直接下载大模型容易中断，推荐用支持断点续传的工具（如 IDM、迅雷，或命令行里的 wget、aria2），网络断了可以接着下，不用从头再来。这是攒模型之路最实用的「防崩溃」技能。

6.1 模型备份与迁移

换新电脑或担心重装系统，怎么保住多年积累？

  • 工作流（体积小）：打包上传网盘，随时可复原；
  • 常用模型：体积大，挑「主力套装」备份即可（比如 2 个大模型 + 5 个常驻 LoRA + 3 个 ControlNet）；
  • 模型清单：建一个文本文件，记录每个模型的来源链接、用途、搭配——这比备份文件本身更值钱；
  • 迁移时，目录结构保持原样（checkpoints/loras/controlnet…）拷过去，最不容易出错。

6.2 去重与清理

模型越攒越多，用系统搜索按大小排序，往往能发现「同款不同名」的重复文件。清理原则：

□ 同名或哈希一致的重复文件：保留最新版
□ 试过但不用了的：移入一个「弃用区」文件夹，先别急着删
□ 用工作流反查：哪些模型正在被引用，其余都可考虑归档

别怕删错：模型可以重新下载，但工作流丢了就真没了。清理时「先保工作流、再动模型」。

6.3 分享与合规的边界

从别人那下载模型没问题，但注意：

  • 模型页的许可协议决定你能不能商用、能不能修改再分发；
  • 商用前先确认许可，个人练习则基本无限制；
  • 你未来要是上传自己的模型或作品，也记得标注所用模型的许可，尊重原作者。

七、给每个模型建一张「身份证」

模型越攒越多，最容易忘的是「这个模型当时配什么参数好用」。建议给主力模型维护一份简单的记录，用表格或文本都行：

模型：Realistic_Vision（写实）
  ├─ 版本：SD 1.5
  ├─ 来源：Civitai 页面链接
  ├─ 常用参数：steps 25 / cfg 7 / euler_a + karras
  ├─ 搭配 LoRA：皮肤质感增强
  └─ 备注：适合人像，风景一般

模型：DreamShaper（梦幻）
  ├─ 版本：SDXL
  ├─ 来源：……（同上格式）
  └─ 备注：低 CFG（5 左右）效果更柔

这份「身份证」可以放在 ComfyUI 目录外的一个文本文件里，或干脆写在模型文件夹旁边。你记下的每个参数，都是下一次创作少踩的一个坑。 很多老玩家回头再看，最庆幸的就是当年坚持记录。

八、本篇小结

  • 目录即仓库：checkpoint 进 checkpoints、LoRA 进 loras、ControlNet 进 controlnet、放大模型进 upscale_models，放错目录=加载不到；
  • 模型的三合一套装可以分件更换：VAE 可单换、LoRA 可叠加、ControlNet 可外挂；
  • 省显存七招：关后台 → 调小分辨率 → --lowvram → 半精度 → 量化 → 换小模型 → 云算力，从易到难依次尝试；
  • 模型冲突多因版本不匹配、同名覆盖、插件缺失，排查按「版本→节点→路径」三步走；
  • 挑模型四要点：看预览图、看适配版本、看许可协议、先复现预览图。

工具房收拾利索了。接下来我们要做的，是让 ComfyUI 从「手动点一下出一张图」进化成「自己跑一百张」——批量生成与自动化。这也是它区别于 WebUI 的最强项。
