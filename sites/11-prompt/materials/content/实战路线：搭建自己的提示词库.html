实战路线：搭建自己的提示词库

学完九章，你已经拥有什么

恭喜你走到第十讲。先把前面九章的知识点串一遍，你会发现它们不是零散的技巧，而是一条完整的「提示词生产线」：

  • 提示词是什么：与大模型的对话协议——提示词是你和模型之间的「协议」，模糊的输入得到模糊的输出。
  • 提示词基本功：清晰、具体、有边界——四要素（角色、任务、背景、输出格式）+ 双向约束（做什么、不做什么）。
  • 角色设定：让模型扮演专家——加一个具体身份，输出立刻「贴人设」。
  • few-shot 示例：用例子教会模型——描述不清的标准，给例子比讲规则管用。
  • 思维链：让模型先想再说——多步骤任务，让它把推理过程写出来再给结论。
  • 结构化输出：让模型按格式说话——用 JSON / 表格 / 固定模板，让输出可被程序消费。
  • 上下文与长文本：摘要、切片与分步处理——长文档先切块、再汇总、先检索再作答。
  • 提示词优化与评测：迭代升级——用固定测试集，「写 → 测 → 改」一轮轮打磨。
  • 提示词的安全与防注入——防注入四板斧，别让数据冒充指令。

这些知识你学过了，但「学过」和「用起来」之间还差一步——把知识变成一套属于自己的、可复用的工具。这一章就是这最后一步：手把手带你搭建自己的提示词库（Prompt Library）。

为什么要建提示词库：你的「AI 外挂」

先想一个问题：你日常用 AI 时，有多少时间是花在「重新描述同一个需求」上的？写日报、写总结、翻译资料、想文案……这些需求你几乎每天都在重复，但你每次都从头组织语言，输出质量还忽高忽低。

提示词库解决的就是这个浪费。它就像你的「AI 外挂」：把你验证过的、好用的提示词，按场景分门别类存好，下次直接用，改改参数就能跑。

建提示词库有四个实打实的好处：

  1. 省时间：不用每次从零开始写，从库里取出来改两处就发。
  2. 稳定：库里的都是你实测过、跑过多轮的「成熟品」，输出质量有保底。
  3. 可复用：同一个模板，换个产品、换个场景就能复用。
  4. 积累：你的「经验值」不散落在对话框里，而是沉淀成资产，越攒越厚。

搭建提示词库：五步走

下面是一套经过验证的五步流程，从零开始把库建起来。

第一步：分类——给「高频场景」建抽屉

先别急着写提示词，先盘点你用 AI 最多的场景。打开你的历史对话记录，数一数你都在问什么。大多数人会落在这么几类：

分类 典型需求
写作 写文案、写朋友圈、写文章、起标题
总结 会议纪要、文章总结、读书笔记
翻译 中英互译、术语翻译、润色
办公 写邮件、做表格、写周报
代码 写代码、找 bug、解释代码
学习 解释概念、出题、对比观点

建议：一开始只建 3~5 个分类就够了。 分类太少会混，分类太多记不住。建库初期，宁少勿多，用一阵子再往里加分类。

第二步：写草稿——每个分类先攒 1~3 条

每个分类下面，把你「最近用 AI 做过、且做成了」的需求，写成一条提示词草稿。写草稿时只做一件事：把四要素填齐。 用我们在 提示词基本功 里学的框架：

角色：你是一位【身份】
任务：请【具体动词 + 对象】
背景：【产品/资料/场景】
输出格式：【长度】【结构】【语气】【不要什么】

比如「总结」分类下的草稿：

角色：你是一位擅长抓重点的文字编辑。
任务：把下面的会议记录总结成会议纪要。
背景：会议主题是门店促销方案讨论，有 40 分钟的录音转写文字。
输出格式：分「决定 / 待办 / 风险」三块；每块用列表；总长不超过 300 字；不要加评价性语言。

第三步：实测——每条草稿至少跑 3 次

写出来的草稿只是「草案」，必须实测。实测的动作是：

  • 拿你真实的输入去跑（不是编一个理想输入）；
  • 同一输入跑 3 次，看输出稳定不稳定；
  • 用 提示词优化与评测 里教的「四指标」打分：正确率、一致性、守规矩率、满意度。

只把「过了实测」的草稿放进库里。 没过的，继续回炉，别急着存。这条纪律能保证你的库「存进去的都是能用的」。

第四步：迭代——用「改一处」的节奏打磨

实测发现问题后，按前面学的迭代方法改：一次只改一处，改了再测，测过再存。 具体套路：

  1. 记下这轮的问题（比如「输出太长」）；
  2. 只改一个地方（比如加「不要超过 300 字」）；
  3. 用同一批输入重测；
  4. 满意后，更新入库，并在「改进历史」里记一句话。

第五步：沉淀——给每条提示词配上「使用说明书」

库里的每条提示词，别只存正文，附上三行「说明书」：

  • 什么时候用：一句话说清适用场景；
  • 怎么改：哪些参数需要每次调整（比如产品名、字数）；
  • 踩过的坑：这条提示词曾经出过什么问题、怎么解决的。

这样哪怕半年后你忘了当初为什么这么写，翻一下说明书就能重新上手。

从「改自己的常用问题」开始：零门槛入门法

最后给你一个心理上的台阶：你不需要等「准备齐全」再开始建库，也不用追求库有多「完整」。

最省力的起步方式，是「逆向收集法」：接下来两周，你正常用 AI，遇到以下两种情况，就把对话存进库里：

  • 情况一：某次输出你特别满意——回去把这次提问的提示词抄下来，存进去；
  • 情况二：某次输出让你改了又改——把最终「改成什么样才满意」的提示词抄下来，存进去。

两周下来，你自然会攒出 10 到 20 条「用过的、好用的」提示词。这时候再回头做分类整理，库就水到渠成地建起来了。不要为了建库而建库，要让库长在你的真实使用里。

最后：提示词工程的心法

临别之际，送你三句话，作为整个系列的心法：

  1. 提示词没有「标准答案」，只有「更适合你的答案」。 别人的模板可以抄，但最终要以你自己的实测为准。
  2. 模型在变，提示词也要跟着变。 换一个模型、模型升级一次，你库里的提示词都可能需要重新测试。定期用测试集「体检」你的库。
  3. 工具会迭代，但方法不会。 今天你学到的「说清楚、给例子、先想再说、按格式、防注入、迭代改」这些方法论，无论未来模型多强，都依然成立。

常见疑问：关于提示词库的三个担心

建库这件事，动手之前很多人心里还有三个疑虑，一并在这里打消。

疑问一：「我记性不好，建了库也会忘用」

解决这个问题不用靠记性，靠「入口」。把提示词库放在你每天都会打开的地方——比如你的笔记软件首页、聊天软件的置顶文件、甚至桌面上的一个快捷方式。再加一条铁律：每次要用 AI 前，先打开库看一眼，而不是直接打开对话框。 强迫自己「先查库再提问」两周，习惯就养成了。库的存在不是给你「记住」，而是替你「记住」。

疑问二：「我的需求太杂，没有固定套路」

「杂」恰恰是建库的理由，而不是不建库的借口。你可以按「频率」而不是「场景」来分类：把「每周至少用一次」的需求做成模板，把「偶尔一次」的需求只存草稿不精修。库里「精修模板 + 草稿笔记」两档并存，杂需求也有地方放。另外，很多看起来不同的需求，骨架其实是同一个——「总结类」模板改个参数就能用在小作文、会议、研报上，一鱼多吃正是库的价值。

疑问三：「模型升级那么快，库会不会很快就过期」

会「部分过期」，但不会「全部报废」。模型升级后，旧的提示词可能措辞不再最优，但它的方法论部分（四要素、few-shot、思维链）依然有效。应对方法很简单：模型大版本升级时，用库里每条提示词的测试集重新跑一遍，不行的就按「一次改一处」的节奏修一版。这个动作每次升级只花半小时，却能保证你的库永远跟得上。库要维护，就像花园要打理，但维护的成本远低于重建的成本。

本章小结

  • 学完九章，你拥有了一条完整的「提示词生产线」，本章把它沉淀为「提示词库」。
  • 建库五步：分类建抽屉 → 写草稿（四要素填齐）→ 实测（至少跑 3 次）→ 迭代（一次改一处）→ 沉淀（配使用说明书）。
  • 库里每条提示词都配「什么时候用 / 怎么改 / 踩过的坑」三行说明书。
  • 起步不用求完美：用「逆向收集法」，两周攒下 10~20 条真实用过的提示词，再回头分类。
  • 心法三句：没有标准答案只有适合你的答案；模型变提示词也要跟着变；工具会迭代但方法不会。

至此，L11 提示词工程的十讲就全部结束了。从「把一句话问清楚」到「建一座自己的提示词库」，你完成的不只是十节课，而是一整套和大模型协作的方法。现在，去打开你的对话框，写下第一条属于你的提示词吧。
