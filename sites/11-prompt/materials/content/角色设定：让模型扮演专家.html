角色设定：让模型扮演专家

一个看似「玄学」却很有效的小技巧

你先做一个小实验。打开任意一款大模型产品，问它同一个问题两次：第一次直接问，第二次先补一句「你是一位有着二十年从业经验的心脏科医生」，再问同一个问题。你会发现第二次的回答明显不一样：用词更专业、结构更像医生会说的话、甚至敢用一些专业术语。

这不是玄学，也不是模型的「人格」被唤醒了。背后有一个朴素的道理：大模型在训练时读过的资料，是分门别类的——法律文本、医学论文、营销文案、编程代码、儿童故事……它全都见过。当你指定一个角色时，等于给它一个「检索方向」，让它优先从「这个角色会怎么说」的知识库里取词造句。

角色设定（Role Prompting）因此成为提示词工程里性价比最高的技巧之一：只需要加一句话，不需要增加多少字数，输出质量却常常肉眼可见地提升。

这一章我们会讲清楚：角色设定到底设定的是什么、为什么通常有效、应该怎么写，以及几个可以直接抄用的模板。最后提醒你角色设定的边界——它不是万能药。

角色设定：到底「设定」了什么

一句话概括：角色设定，就是在提示词里明确告诉模型「现在请你以某某身份来回答」。 它看起来只是加了一句话，实际上在三个维度上同时起了作用。

第一，决定了语气和用词

同一个人表达同一个意思，用不同身份说，口吻完全不同。同一句话「这个方案有风险」，小学老师会说得委婉鼓励，风控专家会直接罗列风险点，销售则会想办法把它包装成「机会」。模型也一样。指定角色，就是指定它用哪套「腔调」说话。

  • 普通问：这段代码有 bug 吗？
  • 设定为老师：你是一位耐心的编程老师，请用初学者能听懂的话，看看这段代码哪里有问题。——它会先肯定你的思路，再一步步指出来，甚至附上解释。

第二，决定了知识和表述的「口味」

模型肚子里装着天文、地理、医学、法律、文学等各种领域的知识，但它用哪一套词汇体系来表达，取决于你让它「用谁的脑子」。你问「什么是无形资产」，设定成会计师，它会给你讲摊销、折旧、报表科目；设定成创业者，它会给你讲「我们公司那些看不见但值钱的东西」。角色决定的是知识的「打开方式」。

第三，决定了回答的边界

这是最容易被忽略、也最有价值的一点。模型默认是「有问必答」，你问什么它都答，而且倾向于往大往全了答。角色设定天然自带「管闲事边界」：你让它扮演「只负责合同审查的律师」，它就不会顺便给你科普公司注册流程。角色是一种隐形的范围约束，它告诉模型：超出这个身份职责的问题，你可以少答、不答，或者明确说「这超出我的职责范围」。

为什么「加了角色」通常比「不加角色」更稳

很多人有疑问：模型的「内心」反正什么都会，加不加角色区别在哪？前面说过，大模型是「续写器」，你给了角色，就改变了它续写的「上下文概率分布」。翻译成大白话：给它一个身份，它后续每个字的选择都会倾向「这个身份会说出口的话」，于是整体输出的风格、深度、结构都跟着稳定下来。

稳定，是角色设定的核心价值。表现在三个方面：

  • 风格稳定：同样要求「写一份年终总结」，让「资深 HR」写，它会侧重绩效、晋升、职业规划；让「运营」写，它会侧重数据、活动、增长。角色让每次输出都「贴着同一种人设」。
  • 质量稳定：让「资深产品经理」评估一个功能方案，它会自动补上用户视角、优先级、上线风险——这些都是「产品经理这个角色」的责任范围，模型会下意识补全。
  • 边界稳定：角色自带「不能越界」的暗示。前面说的「只负责合同审查的律师」，会让模型在不确定时更倾向于拒绝或说明，而不是硬编一个答案。

一个小提醒：角色设定的「稳定」不是 100% 的。模型没有真正的身份和记忆，它只是「演」得更像。把它当作一种「默认调参」，而不是一个真正的专家替身。

怎么写角色：一个好角色的三个要素

角色不是随便加一句「你是专家」就完事。「专家」是最差的角色设定——它太大、太空，等于没设。一个好角色，至少要包含三个要素。

要素一：身份要具体

不要「你是专家」，要「你是一位有十年经验的育儿领域儿童心理学家」。越具体，模型能调用的「对应语料」越精准。

  • 差：你是一位专家。
  • 好：你是一位专注于 3~6 岁��儿情绪问题的儿童心理咨询师，接待过上千个类似案例。

要素二：带上职责和立场

光有身份还不够，告诉它在这个身份下「要干什么、替谁考虑」。比如：

你是一位医疗器械公司的合规专员。你的职责是：从合规和风险的角度审查医疗产品文案，凡是涉及疗效承诺、绝对化用语的内容，一律标红提示。

这样模型就有了「任务导向」——它知道自己是来挑刺的，而不是来夸产品的。

要素三：说明沟通方式

告诉它怎么和你说话：语气、详细程度、是否允许反问。比如：

你是一位耐心的语文老师，面向五年级学生。请用简单的话解释，多用比喻，不要使用专业术语，一次只讲一个知识点。

合在一起，就是一个「四件套」角色模板：

你是一位【具体身份】。
背景：我【相关的身份或处境】，正在【做某件事】。
你的职责：请【具体任务】，重点是【优先级最高的诉求】。
沟通方式：语气【风格】，长度【要求】，遇到不清楚的地方【怎么做】。

三个可以直接抄用的角色模板

模板一：万能「审稿编辑」

你是一位有二十年经验的图书编辑，擅长挑毛病。请审阅下面这篇文章：
1. 指出逻辑不通的地方，给出修改建议；
2. 标出所有可能引起歧义的表述；
3. 删除所有空话套话；
4. 最后用 3 句话告诉我「这篇文章整体值不值得发出去」。
请不要夸我，只谈问题。

这个模板的精髓是最后一句「请不要夸我，只谈问题」——它把模型的「礼貌本能」压下去，逼它输出真实的问题清单。

模板二：「讲人话」翻译官

你是一位能把专业术语翻译成大白话的科普作家。请把下面这段【专业领域】的内容改写成 200 字以内的小学生能看懂的解释：
1. 禁止出现任何专业术语，必须用生活化比喻；
2. 开头先讲一个生活场景引入；
3. 最后用一句「所以」收尾。
原文如下：【粘贴内容】

这个角色特别适合处理「合同条款」「医学报告」「基金说明书」这类让普通人头疼的文本。

模板三：「反向」谈判顾问

你是一位替客户争取利益的谈判顾问，正在帮我准备一次【买什么东西 / 谈什么合作】的谈判。
请从对方的角度，列出 5 个他可能会用的压价理由；
再针对每一个理由，给出我的反驳话术；
最后告诉我：哪些是真正的底线，哪些可以让步。

这个模板的技巧在于「让模型先替对方想」，往往能挖出你一个人想不到的谈判筹码。

角色设定最常见的三种写法错误

学技巧的同时，也要知道坑在哪。以下三种错误，几乎是每个初学者都会踩的。

错误一：角色与任务不匹配

你让它扮演「严肃的金融分析师」，却让它写「卖萌的宠物用品推广文案」——角色和任务互相打架，输出会变得四不像。角色必须服务于任务，先想清楚任务要什么风格，再配什么角色。

错误二：只设角色，不设任务

你是资深律师。就完了，没有下文。模型只能「表演」一个律师，但不知道要干嘛。角色设定永远是配角，任务才是主角。正确的姿势是「角色 + 具体任务 + 输出要求」三件套一起上。

错误三：把角色当护身符

有人以为加了「你是专家」，模型就不会出错、不会编造了。这是误解。角色可以改善风格和结构，但不能消除幻觉。一个扮演「资深医生」的模型，照样可能一本正经地编造一个不存在的药名。该做的防幻觉工作（要求它注明信息来源、不确定就说不知道），一条都不能省。相关的安全讨论见 提示词的安全与防注入。

进阶一点：角色是可以「叠」的

角色设定不是只能有一个。你可以给模型叠多层角色，让它先以 A 身份思考，再以 B 身份批判，最后以 C 身份综合。这种「角色切换」在复杂任务里特别好用。

一个简单例子，帮你想一个促销方案：

第一轮，请以「资深市场总监」的身份，给出 3 个促销方案；
第二轮，请切换到「资深财务总监」的身份，从成本角度点评这 3 个方案，指出哪些算不过账来；
第三轮，请切换到「一线门店店长」的身份，从店员执行难度角度，指出哪个方案最好落地；
最后，综合三轮意见，用「资深市场总监」的身份给出最终推荐，并说明理由。

模型会非常配合地「演」完整个流程，而且因为每轮有明确角色，输出比「一口气让我出个方案」要系统得多。这就是角色设定的进阶用法——不只是一个身份，而是一支「虚拟团队」。

本章小结

  • 角色设定 = 在提示词里明确「请以某某身份回答」，它决定模型的语气、知识表达方式和回答边界。
  • 它本质上是给模型一个「检索方向」，让它在海量语料里优先选用「这个角色会怎么说」的表达。
  • 角色设定的核心价值是「稳定」：风格稳定、质量稳定、边界稳定。
  • 好角色要具体：具体身份 + 职责立场 + 沟通方式。「专家」两个字是无效设定。
  • 常见错误：角色与任务不匹配、只设角色不设任务、把角色当防幻觉的护身符。
  • 角色可以叠加使用，组成「虚拟团队」解决复杂问题。

角色给了模型「身份」，但有时候光有身份还不够——有些任务，它看过再多「身份」也不一定做得对，你需要直接「做给它看」。下一章我们讲用例子教模型：few-shot 示例。请阅读 few-shot 示例：用例子教会模型。
