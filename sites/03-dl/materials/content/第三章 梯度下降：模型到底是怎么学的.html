第三章 梯度下降：模型到底是怎么"学"的

本章目标：搞懂深度学习最核心的算法——梯度下降（Gradient Descent）。看完这章，你会明白"训练模型"这四个字在计算机里到底发生了什么。

3.1 蒙眼下山：一个足够好的类比

想象你被蒙上眼睛，扔在一座山上，任务是走到山谷最低处。你看不见地形，只能感受脚下。

你会怎么做？

  1. 用脚试探周围，感受哪个方向是往下坡最陡的
  2. 朝那个方向迈一步
  3. 重复 1、2，直到脚下变平（四面八方都不再下降）

这就是梯度下降的全部思想。对应关系：

下山 深度学习
你所在的位置 当前的参数 w、b
海拔高度 损失 Loss
山谷最低点 损失最小的那组参数
最陡下坡方向 负梯度
每步迈多大 学习率 learning rate
走一步 一次参数更新

3.2 梯度是什么？就是"坡度"

先看最简单的情况：只有一个参数 w。

损失 L 随 w 变化，画出来是一条曲线（通常像个碗）：

Loss
 │      ╲                    ╱
 │        ╲                ╱
 │          ╲            ╱
 │            ╲___    ╱
 │                ╲__╱   ← 最低点，我们要找的
 └──────────────────────────→ w

在某个位置 w 上，梯度就是这条曲线在该点的斜率，数学上写作 dL/dw（L 对 w 的导数）。

梯度告诉你两件事：

  • 符号：梯度为正 → 往右走损失会变大 → 应该往左走；梯度为负 → 应该往右走
  • 大小：梯度绝对值越大，坡越陡，说明离最低点可能还远

所以更新规则自然就是——往梯度的反方向走：

w_new = w_old − 学习率 × 梯度

写成公式：

w ← w − η · (∂L/∂w)

η（读作 eta）就是学习率。这条公式，就是深度学习的"心脏"。

3.3 动手算一遍

用最简单的例子：模型 ŷ = w · x（先不管 b），数据只有一条：x=2, y=6（所以正确答案显然是 w=3）。

损失用 MSE：

L = (y − ŷ)² = (6 − 2w)²

求导（用链式法则，见第六章，这里先接受结果）：

dL/dw = 2 · (6 − 2w) · (−2) = −4(6 − 2w)

设学习率 η = 0.1，从 w = 0 开始：

轮次 当前 w 预测 ŷ=2w 损失 (6−ŷ)² 梯度 −4(6−2w) 新 w = w − 0.1×梯度
1 0.00 0.00 36.00 −24.0 2.40
2 2.40 4.80 1.44 −4.8 2.88
3 2.88 5.76 0.058 −0.96 2.976
4 2.976 5.952 0.0023 −0.192 2.9952
5 2.9952 5.9904 0.0001 −0.038 2.99904

看，w 自动收敛到 3 了。 没有人告诉它答案是 3，它是靠"哪边下坡就往哪走"一步步蹭过去的。

w = 0.0
lr = 0.1
x, y = 2, 6

for step in range(1, 6):
    y_hat = w * x
    loss = (y - y_hat) ** 2
    grad = -2 * (y - y_hat) * x        # dL/dw
    w = w - lr * grad
    print(f"第{step}轮  loss={loss:8.4f}  w={w:.5f}")

这段 10 行代码，就是所有深度学习训练的内核。 GPT 的训练循环和它结构完全一样，只是参数从 1 个变成 1750 亿个。

3.4 学习率：最重要的超参数

学习率 η 决定每步迈多大。它太重要了，调错了模型根本学不动。

学习率 现象 类比
太小（如 0.0001） 收敛极慢，训练几天没进展 一步挪一厘米下山
合适 稳步下降，快速收敛 正常步幅
太大（如 1.0） 在谷底两侧来回横跳 一步跨过整个山谷
极大（如 10） 损失变成 NaN，训练崩溃 一步跳到隔壁山头，越跳越高

💡 强烈建议：去本站首页玩一下「梯度下降下山台」演示，把学习率拖到 1.2 看看小球是怎么疯掉的。看一次比读十遍文字管用。

实践中常用的做法：

  • 从 0.001（Adam 优化器的经典默认值）或 0.01 开始试
  • 用学习率调度（scheduler）：训练前期大步走，后期小步精调
  • Warmup：训练最开始的几百步，学习率从 0 慢慢升上去，防止一开始就炸（大模型训练必备）

3.5 三种"下山"方式：批量的选择

上面的例子只有 1 条数据。真实数据有几百万条，每次更新参数时要用多少条数据算梯度？

方式 每次用多少数据 优点 缺点
批量梯度下降 BGD 全部数据 方向最准，路径平滑 慢到不能用，显存装不下
随机梯度下降 SGD 1 条 快，能跳出小坑 噪声大，路径抖
小批量 Mini-batch ⭐ 一批（如 32/64/256 条） 兼顾速度与稳定 需要调 batch size

实践中 99% 用 Mini-batch，但大家口头上仍习惯统称它为 "SGD"。

几个必须知道的术语：

  • batch size：一批多少条数据，常见 32 / 64 / 128 / 256
  • step / iteration：处理完一批、更新一次参数，叫一步
  • epoch：全部训练数据完整过一遍，叫一轮

举例：10000 条数据，batch size = 100 → 一个 epoch = 100 步。训练 20 个 epoch = 2000 步参数更新。

3.6 局部最优？其实没那么可怕

初学者常担心："万一走进一个小坑，不是全局最低点怎么办？"

Loss
 │  ╲          ╱╲
 │    ╲__╱      ╲       ← 小坑（局部最优）
 │   局部最优      ╲___╱  ← 全局最优
 └─────────────────────→ w

这个担心在低维空间是合理的，但在深度学习里基本不是问题，原因很有意思：

参数有几亿个维度。要成为"局部最低点"，必须在所有几亿个方向上都是往上走。这个概率低到可以忽略——随便哪个方向能往下，就还能继续走。

真正常见的麻烦是鞍点（saddle point）：一部分方向往上、一部分往下的平坦区域，梯度接近 0，模型看起来"卡住了"。解决办法是加动量（Momentum）——让小球带着惯性冲过平地。

3.7 优化器：给梯度下降开挂

朴素的 w ← w − η·grad 有明显缺点：所有参数用同一个学习率，遇到平地走不动。于是有了各种改进版，统称优化器（Optimizer）：

优化器 核心思想 一句话
SGD 原始版 简单可靠，收敛慢
SGD + Momentum 加惯性，累积历史方向 像滚下山的球，能冲过小坑和平地
AdaGrad 更新频繁的参数用小学习率 适合稀疏特征
RMSProp AdaGrad 的改进，只看近期梯度 适合非平稳目标
Adam ⭐ 动量 + 自适应学习率 默认首选，绝大多数场景直接用它
AdamW Adam + 正确的权重衰减 大模型训练标配 
import torch

# 你会在几乎所有训练代码里看到这一行
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

你不需要背它们的公式，只需记住：先用 AdamW / Adam，学习率 1e-3 到 1e-4，跑不动了再折腾别的。

3.8 完整的训练循环长什么样

把前三章的内容拼起来，就是一个真实的训练循环。任何深度学习代码都逃不出这五步：

for epoch in range(num_epochs):
    for x_batch, y_batch in dataloader:        # 取一批数据

        y_pred = model(x_batch)                # ① 前向：算预测（第1、5章）
        loss   = loss_fn(y_pred, y_batch)      # ② 算损失（第2章）

        optimizer.zero_grad()                  # ③ 清空上一轮的梯度
        loss.backward()                        # ④ 反向：自动求所有梯度（第6章）
        optimizer.step()                       # ⑤ 按梯度更新参数（本章）

对照记忆：

  1. 前向传播 → 算出预测值
  2. 计算损失 → 用尺子量错得多离谱
  3. 清空梯度 → PyTorch 的梯度是累加的，必须先清零（新手最常忘）
  4. 反向传播 → 自动算出每个参数该往哪调
  5. 更新参数 → 真正地"学习"发生在这一步

3.9 本章小结

  • 训练 = 蒙眼下山：不断朝损失下降最快的方向调参数
  • 梯度 = 坡度，指明损失上升最快的方向，所以要往它的反方向走
  • 核心公式：w ← w − η · ∂L/∂w
  • 学习率太小学得慢，太大会震荡甚至炸掉
  • 实践中用 Mini-batch，batch size 常取 32~256
  • 高维空间里局部最优不可怕，鞍点才是常见麻烦，靠动量解决
  • 优化器首选 AdamW
  • 训练循环永远是那五步：前向 → 损失 → 清梯度 → 反向 → 更新
