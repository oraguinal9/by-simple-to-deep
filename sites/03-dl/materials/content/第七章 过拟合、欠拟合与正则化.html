第七章 过拟合、欠拟合与正则化

本章目标：理解为什么"训练集上 99 分、真实场景 60 分"，以及工程上治疗它的六种常规武器。这是理论到落地之间最关键的一章。

7.1 一个死记硬背的学生

两个学生备考：

  • 小 A：把 500 道真题的答案一字不差背下来。模拟考（原题）100 分，正式考试（新题）50 分。

  • 小 B：只看了 3 道题就说"我懂了"。模拟考 55 分，正式考试 52 分。

  • 小 A 的问题叫 过拟合（Overfitting）：把训练数据背下来了，包括其中的噪声，但没学到规律。

  • 小 B 的问题叫 欠拟合（Underfitting）：能力不足或学得不够，连训练数据都没学好。

我们要的是小 C：理解了解题方法，模拟 85、正式 82。这叫泛化（Generalization）能力好。

机器学习的终极目标不是在训练数据上表现好，而是在没见过的数据上表现好。

7.2 怎么判断：看两条曲线

必须把数据切成三份：

数据集 占比 用途 能否用来调参
训练集 train ~70~80% 更新模型参数 —
验证集 val ~10~15% 调超参数、判断何时停 可以
测试集 test ~10~15% 最终评估 绝对不能，只用一次

⚠️ 测试集一旦被你反复用来"看看效果如何然后再调调"，它就变成了第二个验证集，评估结果会虚高。这是实践中最常见的作弊（往往是无意的）。

训练时把训练损失和验证损失画在同一张图上，一眼看出状态：

 Loss
  │
  │╲                              ← 验证损失（val）
  │ ╲___                    ___╱  ← 后期回升 = 过拟合开始
  │     ╲______________╱
  │╲                              ← 训练损失（train）
  │ ╲______________________       ← 一直在降
  └──────────────┬─────────────→ epoch
                 ↑ 最佳停止点

判断表：

训练损失 验证损失 诊断 对策
高 高 欠拟合 加大模型、训练更久、换特征
低 高（且在上升） 过拟合 见 7.4 节六种武器
低 低 👍 正常 可以收工
高 低 数据划分有问题 检查代码/数据泄漏

7.3 过拟合是怎么发生的

三个主要原因：

  1. 模型太复杂：参数量远超数据能支撑的信息量。用 100 万参数拟合 200 条数据，它完全有能力把每条都背下来。
  2. 数据太少或不够多样：只见过白猫，就以为"白色 = 猫"。
  3. 训练太久：前期学规律，后期开始抠噪声细节。

一个直观的例子：用多项式拟合 10 个带噪声的点

  • 1 次多项式（直线）：欠拟合，抓不住趋势
  • 3 次多项式：刚好，抓住了整体形状
  • 9 次多项式：穿过每一个点，训练误差 0，但曲线剧烈扭动，预测新点时错得离谱

7.4 六种常规武器

武器一：更多数据（最有效，也最贵）

数据量翻倍，通常比任何算法技巧都管用。搞不到新数据时用数据增强（Data Augmentation）：

  • 图像：随机裁剪、翻转、旋转、调色、加噪、Cutout、MixUp
  • 文本：同义词替换、回译（中→英→中）、随机删词
  • 语音：变速、变调、加背景噪声

原理：让模型见到同一个物体的各种变体，逼它学"本质特征"而不是死记像素。

from torchvision import transforms
train_tf = transforms.Compose([
    transforms.RandomResizedCrop(224),
    transforms.RandomHorizontalFlip(),
    transforms.ColorJitter(0.2, 0.2, 0.2),
    transforms.ToTensor(),
])

武器二：L2 正则化（权重衰减）

在损失函数里加一项"参数大小的惩罚"：

新损失 = 原损失 + λ · Σ w²

为什么有用：过拟合的模型往往有一些特别大的权重（为了精确穿过某个噪声点，必须剧烈扭动）。惩罚大权重 = 强迫曲线平滑。

λ 是强度，常取 1e-4 ~ 1e-2。在 PyTorch 里就是优化器的 weight_decay 参数：

optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)

L1 正则（λ·Σ|w|）则会把很多权重压成恰好 0，产生稀疏模型，可用于特征选择。

武器三：Dropout（随机失活）⭐

训练时随机让一部分神经元临时"罢工"（输出置 0），比例通常 0.1~0.5。

nn.Sequential(
    nn.Linear(784, 256), nn.ReLU(), nn.Dropout(0.5),
    nn.Linear(256, 10),
)

为什么有用（两种解释都对）：

  1. 防止依赖：某个神经元随时可能消失，网络不敢把宝押在单个特征上，必须学会冗余表达。
  2. 隐式集成：每次随机屏蔽相当于训练一个略微不同的子网络，最终等效于成千上万个网络投票。

⚠️ Dropout 只在训练时开启，推理时必须关闭。PyTorch 里靠 model.train() / model.eval() 切换。忘记调用 model.eval() 是新手最常见的 bug 之一，会导致推理结果每次都不一样。

武器四：早停（Early Stopping）

监控验证损失，连续 N 个 epoch 不再改善就停止训练，并回滚到最好的那个 checkpoint。

best, patience, wait = 1e9, 5, 0
for epoch in range(200):
    train_one_epoch()
    val_loss = evaluate()
    if val_loss < best:
        best, wait = val_loss, 0
        torch.save(model.state_dict(), "best.pt")     # 保存最优
    else:
        wait += 1
        if wait >= patience:
            print(f"验证损失 {patience} 轮没改善，提前停止")
            break
model.load_state_dict(torch.load("best.pt"))          # 回滚到最优

简单、免费、几乎总是该用。

武器五：批归一化（BatchNorm / LayerNorm）

把每层的输入归一化到均值 0、方差 1，再用两个可学习参数缩放平移。

好处：训练更稳、可以用更大的学习率、有轻微正则效果。

  • BatchNorm：在 batch 维度上归一化，CNN 里的标配
  • LayerNorm：在特征维度上归一化，Transformer / 大模型的标配（因为序列长度可变，batch 统计不可靠）

武器六：简化模型

减少层数或宽度。数据量小的时候，小模型往往打得过大模型。

经验法则：先用小模型跑通基线，再逐步加大，直到验证损失不再改善。

7.5 完整的实战流程

1. 切分数据 train / val / test
2. 先训一个小模型，跑通全流程，拿到基线分数
3. 逐步加大模型，直到出现明显过拟合（训练损失远低于验证损失）
   —— 能过拟合说明模型容量够了，这是好事
4. 开始上正则化：数据增强 → Dropout → weight decay → 早停
5. 调学习率、batch size 等超参（只看验证集）
6. 全部定型后，在测试集上评估一次，得到最终报告数字

🔑 步骤 3 反直觉但很关键：新手总想一步到位，老手会先故意把模型做到过拟合，证明"容量足够、代码没 bug、数据能学"，然后再往回收。先过拟合，再正则化——这是业界通行的调参哲学。

7.6 大模型时代的新现象

传统机器学习教科书说"模型越大越容易过拟合"，但大模型时代出现了一些例外：

  • 双下降（Double Descent）：模型继续变大，验证误差先升后再次下降，突破了经典的 U 型曲线。
  • 过参数化的祝福：参数量远超数据量的超大模型，反而泛化得更好。
  • 大模型的主要风险不是过拟合，而是数据污染——测试题混进了训练集（data contamination），导致跑分虚高。

不过对于 99% 的实际项目（数据几千到几十万条），经典的过拟合规律依然完全适用，本章的六种武器都要会用。

7.7 本章小结

  • 过拟合 = 训练好、验证差 = 背答案；欠拟合 = 都差 = 没学会
  • 必须切 train / val / test 三份，测试集只用一次
  • 通过两条损失曲线诊断状态：验证损失开始回升 = 过拟合起点
  • 六种武器：更多数据/增强 → Dropout → L2 权重衰减 → 早停 → 归一化 → 简化模型
  • Dropout 只在训练时开，推理前务必 model.eval()
  • 调参哲学：先把模型做到能过拟合，再加正则往回收
