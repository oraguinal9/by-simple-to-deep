第四章 数据集与指令格式：怎么准备训练数据

微调的效果，七分靠数据。很多人微调翻车，不是模型不行，而是给的数据"喂错了姿势"。本章讲清楚：到底给模型吃什么。

SFT 数据长什么样？

监督微调（SFT）喂的是"指令—回答"配对。最经典的三段式：

  • 指令（instruction）：要模型做什么。
  • 输入（input）：可选的补充材料（没有就留空）。
  • 输出（output）：标准回答，模型要学着模仿它。

举个客服例子：

{
  "instruction": "根据退货政策回答用户问题",
  "input": "用户问：我昨天买的衣服，今天能退吗？",
  "output": "您好，商品签收后 7 天内可无理由退货。您昨天购买、今天仍在期限内，可以申请退货，运费由买家承担。"
}

模型学的是：看到这样的指令+输入，就产出这样的输出。

常见数据格式

不同训练框架吃不同格式，但本质都是上面那三段：

  • Alpaca 格式（JSON 列表）：最通用，上面就是。
  • ShareGPT 格式：多轮对话，用 messages 数组，role 分 system/user/assistant。
  • 纯对话格式：直接写成一段 用户：…\n助手：… 的文本。

格式不重要，语义一致才重要：每一条都要有清晰的"该学什么输出"。

数据从哪来？

  1. 自己写：最准但最慢。适合任务很专、样本少（几百条也能起步）。
  2. 从现有资料提取：把产品手册、FAQ 拆成问答对。
  3. 用强模型"蒸馏"生成：用 GPT-4 级模型，根据你定的指令模板批量产出"问题—回答"候选，再人工抽检修正。这是今天最常见的扩量手段。
  4. 公开数据集：HuggingFace 上有大量 SFT 数据集（如 English 的 Dolly、中文的 ShareGPT-Chinese、COIG 等），可借鉴风格。

质量 > 数量

一条高质量数据，胜过一百条脏数据。坏数据的典型症状：

  • 回答错误（事实错、逻辑错）——模型会认真学错。
  • 格式不一（有的带 JSON、有的纯文本）——模型学到混乱。
  • 重复刷屏（同一条复制几百遍）——模型过拟合到这句，其他都不会。
  • 和任务无关（混进闲聊）——稀释学习目标。

经验值参考：很多实用场景 几百到几千条精心打磨的数据 就能看到明显效果；盲目堆到几万条若质量差，反而更糟。

数据要"像最终用法"

一个常被忽视的要点：你最终怎么用模型，就怎么造数据。

  • 想要固定 JSON 输出？那训练样本的输出就都必须是合法 JSON。
  • 想要某种语气？每条输出的语气都要一致。
  • 想要模型先"思考"再答？那输出里就包含思考过程。

模型是"照葫芦画瓢"的高手——你画的葫芦歪，它画出的瓢也歪。

训练/验证集切分

和评估模型一样，数据要留出一小部分（如 10%）不参与训练，专门用来监控"模型在没见过的数据上表现如何"（防过拟合，见第六章）。这一步训练脚本通常自动帮你切，但你得知道它存在。

本章小结

  • SFT 喂的是「指令—输入—输出」配对，本质是"照着标准回答模仿"。
  • 格式（Alpaca/ShareGPT）不重要，语义一致才重要。
  • 数据质量远大于数量；来源可自写、可蒸馏、可公开集。
  • 训练样本要复刻你真实的使用方式（格式、语气、结构）。

小练习

  1. 你要训练一个"把用户口语转成 SQL 查询"的模型。写一条 instruction/input/output 样例。
  2. 为什么"把同一条好数据复制 100 遍"反而是坏主意？
